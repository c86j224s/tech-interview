# 독립 지식노트 구성

## 범위와 기준일

2026-09-17 기준, 질문·답변 확장은 철회하고 기술 자체의 원리·구현·운영을 중심으로 학습 노트를 구성했다. 기존 질문 1,000개는 변경하지 않았다. 참고 저장소는 `jbee37142/Interview_Question_for_Beginner`, 확인 리비전은 `26c959a31f279295931130833cb6d0a43592e26e`이다. 원문 답변을 복제하지 않고 기술 주제와 누락을 대조했다.

## 구조 변경

- 질문 연결은 선택 사항이다. 독립 노트는 `questionIds: []` 또는 필드 생략으로 작성할 수 있다.
- `prerequisites`는 먼저 이해할 개념, `related`는 연관·심화 개념이다. 대상 누락·자기 연결·선행 개념 순환을 검사한다.
- 자료를 대조한 노트는 `reviewedAt`을 표시한다. 이 날짜는 전체 실험 통과나 최신 안정 버전의 보증이 아니다.
- 9개 학습 경로와 전체 분야 트리를 병행한다. 경로는 권장 시작 순서이고, 트리는 개념별 대표 위치이다.
- 모든 문서에 같은 분류의 관련 개념과 역방향 학습 연결을 제공한다. 질문은 별도 접힌 선택 연습이다.
- 기존 질문 기반 coverage 페이지는 질문과 본문의 연결 검토일 뿐 전체 기술 지식 완성도가 아니다.

## 검증과 수정

루나로 12개 분야의 조사와 독립 검증을 수행하고, 별도 12개 묶음에서 본문 초안과 검증안을 작성했다. 통합자는 36개 최종 본문을 모두 읽고 원본 경로 링크를 배포 URL로 정규화했다. 검증안도 무조건 수용하지 않았으며 다음 문제를 직접 고쳤다.

- 트리 BFS 큐 추적과 DFS 처리 노드를 잘못 공유한 표
- Kafka poll 결과 중 큐 포화 이후 나머지 레코드를 잃는 축약 예제
- Java 상속 관계가 있는 예외의 잘못된 multi-catch와 public 상속 멤버 접근 일반화
- RIO 제출 후에 상태를 등록하여 빠른 완료와 경쟁하는 예제
- 용량 제한 큐의 실제 capacity 검사 누락
- Flow Field의 0비용 간선에서 거리 감소만으로 방향을 고르는 문제
- 메모리 초과 입력을 추가 메모리 검토 없이 계수·기수 정렬로 보내는 선택 모형
- 반응형 구독 예제의 최초 32개 수요와 불필요한 추가 수요 혼합
- 누락된 공간 트리·복셀 그림

선형회귀 첫 갱신, 트리 순회 중간 상태, 복셀 음수 좌표·저장 크기, 경로 비용에 대해 로컬 산술·상태 회귀 테스트를 추가했다. macOS 27.0 arm64의 Python kqueue/socketpair 시험은 EV_CLEAR 통지 후 4바이트를 1바이트씩 읽고 EOF를 확인했다. Windows RIO/IOCP, Linux epoll/io_uring, Kafka/Pulsar 클러스터, Recast/OpenVDB, Java/iOS 전체 실행이나 부하 시험을 했다고 주장하지 않는다.
