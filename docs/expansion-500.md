# 500문항 확장과 랜덤 출제

2026-09-13에 기존 350문항에 150문항을 추가했습니다. 기존 문항의 ID와 제목은 유지하며 새 문항은 기본 원리에서 한 단계 더 들어가는 동작·실패 조건을 다룹니다. AI 에이전트 50문항은 그대로 유지합니다.

## 추가 범위

| --- | ---: | --- |
| DB와 저장 계약 | 29 | 쓰기 편향, 직렬화 재시도, 잠금 읽기·SKIP LOCKED, 버전·UPSERT, NULL·EXISTS·윈도 함수, 인덱스·파티션·VACUUM·CDC·복구 |

각 문항은 구두 답변, 득점·감점 포인트, 심화 질문과 기존·신규 문항 연결을 갖습니다. 5분 표시는 설명의 확장 목표이며 실제 낭독 시간은 아닙니다. 모든 답변의 길이를 맞추기 위해 반복 문장을 넣지 않습니다. 실제 DB·OS·라이브러리 동작은 제품과 버전에 따라 확인하도록 범위를 명시했습니다. 이번 확장은 새 공식 명세를 전수 실행 검증한 자료가 아니며, AI 에이전트의 최신 자료 확인 범위는 별도 [출처 문서](agent-sources.md)를 따릅니다.

## 랜덤 출제의 변경

기존 구현은 고정 seed를 사용하지 않았지만 현재 문항만 제외한 독립 추첨이어서 최근 본 문항이 다시 나올 수 있었습니다. `/practice/`의 기본 문항도 고정되어 시작 경험이 반복됐습니다.

새 동작은 다음과 같습니다.

- Fisher–Yates로 전체 문항 ID를 섞어 남은 덱에서 하나씩 선택합니다.
- 현재 문항과 직접 방문한 문항은 남은 덱에서 제거합니다. 한 주기 안에서는 덱에서 이미 꺼낸 문항을 다시 출제하지 않습니다.
- 남은 항목을 소진하면 현재 문항을 제외한 새 덱을 섞습니다. 주기 경계에서 연속 동일 문항은 나오지 않지만 이전 주기의 다른 문항은 다시 나올 수 있습니다.
- `crypto.getRandomValues`와 rejection sampling으로 범위 난수를 만들고, 사용할 수 없으면 `Math.random`으로 fallback합니다. 운영용 고정 seed는 없습니다.
- 남은 덱은 탭별 `sessionStorage`에 저장합니다. 새로고침·일반 이동·뒤로 가기에서도 저장된 상태를 다시 읽습니다. 새 탭은 별도 세션이지만 브라우저의 탭 복제·복원은 세션 상태를 복사할 수 있습니다.
- 저장소 오류·손상은 메모리 덱으로 fallback합니다. 이 경우 전체 문서 이동을 넘는 중복 방지는 유지되지 않을 수 있지만 현재 문항은 제외합니다.
- 문항 추가 시 새 ID를 남은 덱에 섞고 삭제된 ID는 제거합니다.
- 홈 시작 버튼과 메뉴의 질문 연습은 JavaScript가 있으면 랜덤 문항으로 이동합니다. `/practice/` 직접 주소와 JavaScript 없는 링크는 고정 기본 문항으로 열려 접근성과 공유 동작을 유지합니다.

이것은 매 클릭이 독립적인 균등 추첨인 방식에서 **한 주기 안의 중복을 줄이는 무작위 순열**로 바꾼 것입니다. 주제별 가중치나 강제 카테고리 교대는 적용하지 않아 같은 주제의 서로 다른 문항이 연속해서 나올 수 있습니다.

## 검증

덱의 전체 항목 한 번 방문, 새로고침 후 이어가기, 직접 방문 제외, 주기 전환, 문항 추가·삭제, 저장소 손상·차단, 빈·단일 목록과 난수 범위를 단위 테스트로 확인합니다. 브라우저에서는 랜덤 시작, 연속 이동·새로고침, 저장소 차단 fallback, 종이 전환·뒤로 가기와 전체 문항 링크를 검증합니다.
