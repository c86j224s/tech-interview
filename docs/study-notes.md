# 학습 노트 작성과 연결

면접용 `questions/`와 학습용 `notes/`를 분리합니다. 질답은 짧게 말하며 판단을 드러내는 자료이고, 노트는 원리·전제·예제·슈도코드·비용·오해·직접 실험을 설명하는 자료입니다. 제목만 있는 문서나 답변을 그대로 복사한 문서를 만들지 않습니다.

## 폴더와 주소

- `notes/algorithms/`: 퀵소트·이진 탐색·그래프 탐색
- `notes/data-structures/`: 힙·해시 테이블
- `notes/databases/`: 트랜잭션·인덱스
- `notes/distributed/`: 재시도·멱등성·Outbox
- `notes/concurrency/`: 작업 수명·취소
- `notes/networking/`: TCP
- `notes/security/`: 인증·인가
- `notes/ai/`: 에이전트 실행 구조

노트는 하나의 구체적인 학습 주제에 집중합니다. Redis·Kafka처럼 제품 전체를 한 파일로 요약하지 않고 원자 실행, 저장 복구, 복제 확인 등 독립적으로 공부할 문제로 나눕니다. 전체 1,000문항의 모든 기술을 설명한 상태는 아니며, 직접 관련된 문항에만 연결합니다. 기존 안정 ID는 주제를 좁혀도 유지하되, 더 이상 본문이 설명하지 않는 문항 연결은 제거합니다.

웹 주소는 폴더와 무관한 안정 ID를 사용합니다. 예: `/tech-interview/notes/quicksort/`. `/tech-interview/notes/`에서 주제별 목록을 봅니다. 모든 페이지는 공통 AI 생성·학습 이용 금지 안내를 유지합니다.

## 형식

```yaml
---
id: quicksort
title: 퀵소트의 분할과 최악 시간
topic: 알고리즘
summary: 분할 불변식과 예제, 복잡도와 보완 전략을 설명합니다.
questionIds: [quicksort-worst-case, sorting-stability]
---
```

본문의 첫 h1은 title과 일치해야 합니다. h2별 자동 목차와 앵커를 생성합니다. 알고리즘이면 구간 표현·종료·불변식·작은 실행 예제·복잡도를 설명하고, 기술이면 구성 요소·데이터 흐름·상태·실패 지점·복구·검증 방법을 설명합니다. 슈도코드와 실행 가능한 코드는 구분합니다.

## 문체와 설명의 깊이

상황과 궁금증을 설명한 뒤 필요한 용어를 소개합니다. 추상적인 요약이나 반복 문장으로 분량을 채우지 않습니다. 하나의 작은 예제를 구조·상태 표·슈도코드에서 끝까지 추적하고, 실패 입력의 예상 결과까지 적습니다. 표는 비교나 상태 변화를, 그림은 흐름·구조·책임 경계를 설명할 때 씁니다. 모든 노트에 모든 그림 종류를 억지로 넣지 않습니다.

## 정적 그림

`diagram` 코드 블록의 JSON은 빌드 중 SVG로 변환됩니다. 브라우저의 JavaScript나 외부 서비스·폰트·도표 라이브러리가 없어도 그림이 보입니다. 그림마다 제목·설명과 ‘그림을 글로 읽기’가 함께 생성됩니다. 좁은 화면에서는 그림 안에서만 좌우 스크롤하고 본문은 넘치지 않습니다. 테마 색은 사이트 토큰을 따릅니다.

````markdown
```diagram
{"title":"실행 경계","caption":"화살표는 요청 순서입니다.","rows":[[{"id":"request","label":"요청"}],[{"id":"commit","label":"커밋","detail":["같은 DB 안의 변경"]}]],"edges":[{"from":"request","to":"commit","label":"조건 갱신"}]}
```
````

- `title`, `caption`, `rows`, `edges`는 필수입니다. 제목과 설명에서 그림의 의미와 화살표 종류를 밝힙니다.
- 행은 1~12개, 각 행은 노드 1~3개입니다. 노드의 `id`는 그림 안에서 고유한 영문 식별자이고 `label`은 이름, `detail`은 최대 3개의 짧은 설명입니다.
- `edges`의 `from`, `to`는 실제 노드 ID, `label`은 관계입니다. 존재하지 않는 연결이나 자기 연결은 빌드 오류입니다.
- 선택적인 `kind: "class"`는 이름과 책임·필드·메서드를 구분합니다. 이 간단한 책임도는 UML 전체 문법이 아니며, 관계는 화살표 이름으로 정확하게 설명합니다.
- 긴 간선·역방향·교차가 많으면 여러 작은 그림으로 나눕니다. 생성 후 실제 화면에서 글자와 선이 겹치지 않는지 확인합니다.

## 연결의 단일 원본

노트의 `questionIds`에 직접 연결할 기존 문항 ID를 기록합니다. 승격 심화 문항은 `promotedFrom.id`에 연결된 노트를 기본적으로 이어받습니다. 직접 연결과 상속 연결은 중복 제거합니다. 같은 노트를 관련 없는 카테고리 전체에 자동 연결하지 않습니다.

질문 페이지의 ‘원리부터 공부하고 싶다면’과 노트의 ‘배운 내용으로 답해 보기’는 같은 연결에서 양방향 생성합니다. 노트에 없는 ID를 넣으면 콘텐츠 검증이 실패합니다. 개별 Markdown 답변 본문에 노트 URL을 반복 삽입할 필요는 없습니다.

## 2026-09-14 개편 범위

기존 12개 노트의 안정 주소는 유지하고, 총 21개 노트와 정적 그림 26개로 보강했습니다. Redis는 원자 실행·지속성·복제/승격, Kafka는 키 순서·소비 완료 경계·복제 ACK로 나눴습니다. 그래프 탐색은 BFS·Dijkstra·A*로, 멱등성과 Outbox는 각각 독립 노트로 분리했습니다. TCP·인증·트랜잭션·에이전트 실행 노트도 하나의 구체적인 문제에 집중하도록 범위를 좁혔습니다.

주제에 맞지 않는 연결을 제거한 결과 직접 연결과 승격 상속을 합쳐 134문항에서 노트로 이동할 수 있습니다. 연결 수 확대보다 본문이 실제로 설명하는 내용과의 일치를 우선합니다.

검산은 Python으로 퀵소트 1,093개 작은 배열, lower_bound 5,465개 입력, 힙 삽입·추출 추적, TCP 프레임의 모든 두 조각 분할과 한 바이트 입력을 확인했습니다. BFS·Dijkstra·A*의 본문 예와 음수 입력 거절·재확장 반례도 별도 Python 구현으로 확인했습니다. 이는 슈도코드를 옮긴 예제 검산이며 모든 언어·숫자 범위·운영 환경을 검증한 것은 아닙니다. Redis·Kafka 서버의 실제 장애 주입 실험은 수행하지 않았습니다. 버전 민감한 경계의 공식 문서는 각 노트 끝에 연결했습니다.

## 유지보수와 검증

`npm run validate`와 빌드는 노트 ID·중복·필수 메타데이터·h1·목차·문항 ID와 그림 JSON을 검사합니다. 테스트는 승격 문항의 노트 연결, 역방향 목록, 기존 안정 URL, 목차 앵커와 모바일 코드·표·그림 넘침을 확인합니다. 모든 노트를 JavaScript가 꺼진 375px 화면에서도 열어 그림과 글 설명을 확인하며, 밝은/어두운 테마에서 SVG 글자가 도화지 밖으로 잘리지 않는지 검사합니다. 이것은 렌더링 검사이며, Redis/Kafka 장애 실험을 실행했다는 뜻은 아닙니다.

노트의 참고 링크는 추가 학습 경로이며 외부 문서를 이번 실행에서 전수 검증했다는 뜻은 아닙니다. 언어·플랫폼별 코드는 실행한 환경과 한계를 별도로 기록합니다. 문서가 자라면 기존 안정 ID는 유지하고 필요할 때 세부 노트를 추가합니다.
