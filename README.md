# 말로 풀어보는 CS

CS 지식을 공부하고 복습하며 구두 기술 면접을 연습하는 정적 사이트입니다. 정의를 외우기보다 원리와 조건을 자신의 말로 설명하는 연습에 초점을 맞춥니다.

공개 사이트 주소: https://c86j224s.github.io/tech-interview/

## 제공하는 기능

- 한 화면에서 질문 하나를 보고, 생각한 뒤 답변과 점검 포인트를 펼칩니다.
- 현재 질문을 제외한 무작위 질문으로 이동합니다.
- 전체 목록에서 질문·카테고리·태그를 검색하고 필터링합니다. 목록의 `/` 단축키로 검색창에 초점을 맞출 수 있습니다.
- 각 질문에는 직접 공유할 수 있는 고유 주소가 있습니다. 현재 답변의 전제를 바꾸는 꼬리 질문과 일반 연관 개념을 구분해 연결합니다.
- 모바일 화면과 라이트·다크 모드를 지원합니다. 테마 선택만 현재 브라우저에 저장하며, 저장소 접근이 차단돼도 동작합니다.

Astro로 Markdown을 읽어 빌드 시 HTML을 생성합니다. 서버나 데이터베이스는 필요하지 않습니다. 질문과 답변은 JavaScript 없이도 읽을 수 있으며, 랜덤 이동·목록 필터·테마 전환에는 JavaScript가 필요합니다.

## 로컬 실행

Node.js 22.12 이상과 npm이 필요합니다.

```sh
npm ci
npm run dev
```

http://127.0.0.1:4321/tech-interview/ 에서 확인합니다. Astro가 백그라운드로 실행된 경우 `npx astro dev status`로 상태를 보고 `npx astro dev stop`으로 중지할 수 있습니다.

배포할 정적 빌드와 브라우저 테스트는 다음 순서로 확인합니다. 테스트는 설치된 Google Chrome을 사용합니다.

```sh
npm run build
npm test
npm run preview
```

미리보기 서버도 같은 주소에서 열립니다. `npx astro preview stop`으로 중지합니다. 다른 서버가 4321 포트를 사용 중이라면 먼저 해당 서버를 확인하세요.

## 문항 관리

현재 300문항을 제공합니다. 300문항으로 확장하면서 참고한 저장소와 보강 범위는 [주제 선정 자료](docs/topic-sources.md)에 정리했습니다.

[`questions/`](questions/)에 문항 하나당 Markdown 파일 하나를 저장합니다. 각 문항은 다음 구성입니다.

1. 일반화된 기술 질문
2. 구두 답변 — 보강본은 약 5분을 목표로 핵심 결론·원리·사례·실패 조건·대안을 설명합니다. 단순한 질문을 억지로 늘리지는 않습니다.
3. 득점 포인트 — 불릿으로 작성합니다.
4. 감점 포인트 — 불릿으로 작성합니다.
5. 더 파고들 거리 — 불릿으로 작성합니다.

YAML 프런트매터에 `id`, `title`, `difficulty`, `category`, `tags`, `related`를 기록합니다. 난이도는 기본 개념·사용 계약을 확인하는 `하`와 내부 동작·예외 조건을 확인하는 `중하`로 구분합니다. 목록에서는 난이도·카테고리·태그·검색어를 함께 적용할 수 있습니다. 전체 질문과 ID만 담은 [`question-index.json`](question-index.json)을 먼저 확인해 의미가 겹치는 질문을 피합니다. 추가·삭제·제목 수정 시 인덱스도 함께 갱신합니다.

```sh
npm run validate
```

검증기는 인덱스와 파일의 일치, ID·질문 중복, 메타데이터, 본문 섹션과 불릿, 연관 ID, 꼬리 질문의 대상과 연결 문장을 확인합니다. 빌드 전에도 자동 실행됩니다. 의미상 중복은 자동 판별하지 않으므로 작성자가 기존 문항을 비교해야 합니다. 자세한 기준은 [작성 지침](docs/interview-style.md)을 참고하세요.

## GitHub Pages 배포

소스는 `main`, 빌드 결과는 `gh-pages` 브랜치에서 관리합니다. 저장소 설정의 Pages 배포 원본은 **Deploy from a branch → gh-pages → /(root)** 입니다.

```sh
npm run deploy
```

이 명령은 검증과 정적 빌드 후 `dist/` 내용만 `gh-pages`에 커밋·푸시합니다. 실행하는 계정의 GitHub 쓰기 권한이 필요하며 실제 공개 사이트를 변경합니다. 소스의 커밋·푸시는 별도로 수행합니다. GitHub Pages의 게시가 완료될 때까지 잠시 걸릴 수 있습니다.

다른 저장소로 배포할 때는 `astro.config.mjs`의 `site`와 `base`를 함께 변경하세요. 사이트 URL의 하위 경로를 포함해 링크와 자산 주소가 생성됩니다.

## 콘텐츠 원칙

개인 경력은 주제 선정에만 활용하며 공개 콘텐츠는 독립적으로 이해할 수 있는 일반적인 기술 질답으로 작성합니다. 회사명, 프로젝트명, 내부 구조, 실제 성과 수치, 개인의 담당 역할이나 경력 원문을 포함하지 않습니다. 원본 경력 자료는 저장소와 배포물에 넣지 않습니다.

득점·감점 포인트는 학습용 자기 점검 기준이며 특정 회사의 실제 채점표가 아닙니다. 문항 Markdown은 저장소에서 검토한 신뢰할 수 있는 콘텐츠로 취급하므로, 외부 사용자 입력을 그대로 렌더링하는 용도로 재사용해서는 안 됩니다.

## 깊이 있는 답변과 꼬리 질문

전체 **300문항**을 5분 목표 답변으로 보강하고, 문항마다 맥락 있는 꼬리 질문 3개씩 **900개 연결**을 구성했습니다. 핵심 결론에서 원리·구체 사례·실패 조건·대안으로 확장하며, 목록과 문항 상단에 `5분 답변 목표 · 보강본`으로 표시합니다. 5분은 설명의 깊이와 범위를 위한 목표이지 낭독 실측값은 아닙니다. 모든 내용을 한 번에 외우기보다 질문의 범위에 맞춰 답하고 꼬리 질문으로 이어가는 연습에 사용합니다.

문항별 선택 메타데이터 `followups`에는 이어갈 문항의 `id`와 현재 답변에서 파생되는 질문인 `prompt`를 기록합니다. ‘이어서 설명해 보기’에서 꼬리 질문을 먼저 읽고 답한 뒤 해당 문항으로 넘어갑니다. 단순한 태그 유사도 추천은 `연관 개념`으로 별도 표시합니다. 새 문항을 복제하지 않고 기존 300문항을 연결합니다.
