01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

로그인 검증용 비밀번호는 원문으로 복원할 필요가 없으므로 보통 복호화 가능한 암호화보다 비밀번호 전용 해시를 사용합니다. 유출됐을 때 공격자가 후보를 빠르게 대입하지 못하게 계산과 메모리 비용을 부여하는 것이 중요합니다. 단순히 일반 해시를 한 번 적용하는 것과는 다릅니다.

저는 검증된 Argon2id 같은 비밀번호 해시 구현을 쓰고 사용자별 무작위 salt와 비용 파라미터를 함께 저장하겠습니다. salt는 같은 비밀번호의 결과가 같아지는 것을 막지만 비밀키는 아니므로 숨기는 데 의존하지 않겠습니다. 비용은 무조건 최대가 아니라 실제 서버에서 로그인 지연과 동시 인증 부하를 재서 정해야 합니다. 너무 비싸면 정상 트래픽이나 인증 남용에 서버가 먼저 고갈될 수 있습니다.

기존 해시 정책을 바꿀 때는 저장된 알고리즘·파라미터를 식별하고 로그인에 성공한 비밀번호를 새 정책으로 다시 해시하는 점진적 전환을 할 수 있습니다. 추가 비밀값인 pepper를 사용한다면 저장소와 분리된 키 관리 및 교체·분실 시 복구 정책이 필요합니다. 비밀번호 원문과 인증 입력은 로그에 남기지 않겠습니다. 검증은 로그인 성공뿐 아니라 잘못된 입력의 지연, 재해시 전환, 부하 제한을 함께 확인하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 복원과 검증을 구분한다. 전용 해시의 목적을 설명한다.
  • 비용과 가용성을 비교한다. 실제 부하로 파라미터를 정한다.
  • 전환과 비밀 관리를 다룬다. 재해시·키·로그 정책을 포함한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 빠른 해시 한 번이면 안전하다고 말한다. 후보 대입 비용이 낮다.
  • salt를 숨기면 된다고 말한다. salt는 고유성을 위한 값이다.
  • 비용은 무조건 크게 잡는다. 인증 처리 용량을 해칠 수 있다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 해시 정책을 바꾸는데 사용자가 장기간 로그인하지 않으면 어떻게 처리할까요?
  • pepper가 유출되거나 분실됐을 때 복구 선택은 어떻게 달라지나요?
  • 없는 사용자와 잘못된 비밀번호의 응답 차이를 어떻게 줄일까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
