# 격자 맵에서 목적지 칸은 비어 있지만 양옆에 벽이 있습니다. 캐릭터가 대각선으로 그 모서리를 지나가도 되나요?

## 구두 답변

목적지가 비었다는 것만으로 대각 이동을 허용하면 안 됩니다. 허용할 모서리 통과 규칙을 먼저 정해야 합니다. 목적지 셀이 비어 있어도 인접한 두 직교 셀의 벽 사이를 대각선으로 지나가면 실제 캐릭터가 벽을 통과할 수 있습니다. 점 하나의 격자 경로와 크기가 있는 물체의 이동 가능성은 다릅니다.

다음은 모서리 통과 규칙이 필요한 작은 예입니다. S는 출발, G는 목적지, #은 벽입니다.

```text
S #
# G
```

S와 G만 보면 둘 다 빈 칸이지만 둘 사이 모서리는 벽 두 개가 맞닿는 곳입니다. 크기가 있는 캐릭터라면 지나갈 공간이 없을 수 있습니다. 탐색 알고리즘이 아니라 허용할 이동과 충돌 규칙을 먼저 정해야 합니다.

저는 대각 이동 시 양옆 셀을 모두 비워야 하는지, 하나만 비어도 되는지, 대각 이동 자체를 금지할지 명시하겠습니다. 캐릭터 반경이 있으면 장애물을 반경만큼 확장해 중심점 경로를 찾거나 통로의 여유 폭을 검사할 수 있습니다. 서로 크기가 다른 캐릭터가 같은 경로 데이터를 그대로 써도 되는지 확인해야 합니다.

휴리스틱과 JPS 같은 가지치기도 이 이동 규칙을 전제로 하므로 규칙만 바꾸고 탐색 최적화를 그대로 두면 경로를 놓칠 수 있습니다. 테스트는 두 벽이 만나는 모서리, 한 칸 통로, 서로 다른 크기와 경계 좌표를 포함합니다. 화면에서는 지나갈 수 있어 보이는데 서버가 거절하거나 반대가 되지 않도록 클라이언트 표시와 서버 판정의 기준도 맞추겠습니다.

## 득점 포인트

- 점 경로와 물체 크기를 구분한다.
- 모서리 통과 규칙을 명시한다.
- 휴리스틱·가지치기·표시의 전제를 맞춘다.

## 감점 포인트

- 목적 셀이 비면 경로도 항상 유효하다고 말한다.
- 모든 크기의 캐릭터가 같은 통로를 통과한다고 말한다.
- 이동 규칙 변경 뒤 JPS 전제를 재검증하지 않는다.

## 더 파고들 거리

- 장애물 팽창은 작은 통로를 어떻게 바꾸나요?
- 서로 다른 반경의 에이전트를 위한 맵 데이터를 어떻게 공유할까요?
- 부동소수점 위치를 셀로 바꿀 때 경계 오차를 어떻게 다룰까요?
