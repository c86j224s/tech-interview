# 복셀의 물리적 고체 여부와 특정 에이전트의 이동 가능 여부를 하나의 점유 비트로 표현하면 어떤 규칙을 잃게 되나요?

## 구두 답변

고체 여부는 복셀이 물리적으로 차지하는지에 관한 정보이고, 이동 가능 여부는 에이전트의 크기·능력·현재 상태를 포함한 질의 결과입니다. 물, 낮은 장애물, 경사, 문, 사다리는 같은 점유 값으로도 에이전트마다 통과 규칙이 달라질 수 있습니다. 따라서 `occupied=true` 하나를 모든 충돌·경로 규칙의 의미로 사용하면 정보가 섞입니다.

정적 지형의 재질·부피와 동적 객체 점유, 에이전트별 clearance·이동 능력을 분리하겠습니다. 작은 캐릭터가 지나가는 통로도 큰 캐릭터는 못 지나갈 수 있고, 공중 이동은 바닥 점유뿐 아니라 위쪽 공간과 3차원 충돌을 봐야 합니다. 경로 탐색용 walkable 데이터는 원본 복셀에서 파생한 결과이므로 원본 버전과 재생성 책임을 기록합니다.

저장 효율을 위해 비트·팔레트·압축 블록을 사용할 수 있지만, 의미를 압축 형식에 묻지 않겠습니다. 동적 점유가 자주 바뀌는데 큰 정적 압축 블록에 함께 넣으면 작은 변경도 재인코딩 비용을 만들 수 있으므로 정적·동적 계층을 나눌 수 있습니다. 조회 시에는 정적 지형, 동적 점유, 에이전트 조건을 합쳐 최종 충돌·이동 가능 결과를 계산합니다.

테스트는 재질·문 상태·경사·캐릭터 크기·공중 이동·동적 장애물을 바꾸며 충돌과 경로 결과가 같은 의미 규칙을 따르는지 확인합니다. 서버·클라이언트의 지형 버전이 다르면 서버 권위 결과를 우선하고 보정이나 이동 제한을 적용하겠습니다.

## 득점 포인트

- 물리 점유·동적 점유·에이전트 통과 조건을 분리한다.
- 에이전트 크기와 3차원 여유를 이동성에 반영한다.
- 압축 선택을 조회·갱신·파생 버전 비용과 함께 평가한다.

## 감점 포인트

- 고체가 아니면 모든 에이전트가 이동 가능하다고 말한다.
- 정적·동적 상태를 언제나 같은 비트로만 표현한다.
- 압축률만 보고 자료구조를 고른다.

## 더 파고들 거리

- clearance를 미리 계산하면 어떤 반복 조회를 줄일 수 있나요?
- 동적 점유 계층을 별도로 두면 충돌 결과를 어떻게 합치나요?
- 서버·클라이언트 지형 버전 불일치를 어떤 메시지로 처리하나요?
