01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

먼저 일을 나누는 비용보다 메모리를 가져오는 비용이 커졌는지 보겠습니다. NUMA에서는 CPU가 자기 노드의 메모리에 접근하는 것과 다른 노드의 메모리에 접근하는 비용이 다릅니다. 코어 수가 충분해도 작업과 데이터가 멀리 배치되면 스레드를 늘린 이득을 잃을 수 있습니다.

예를 들어 한 초기화 스레드가 큰 배열을 모두 먼저 접근하고, 이후 여러 노드의 작업자가 나눠 처리한다고 하겠습니다. 첫 접근에 따라 메모리를 배치하는 환경에서는 페이지가 초기화 스레드 쪽에 몰릴 수 있습니다. 저는 노드별 메모리 배치와 원격 접근 비율을 보고, 작업자가 자기 구간을 초기화하는 방식과 비교하겠습니다. 스케줄러가 스레드를 자주 옮긴다면 CPU 이동과 캐시 재예열 비용도 확인하겠습니다.

지역성이 실제 병목이면 노드별 작업 큐와 메모리 풀로 소유를 나누거나 작업자를 적절히 고정할 수 있습니다. 하지만 한 노드가 바쁘고 다른 노드가 쉬는데 고정 때문에 일을 못 넘긴다면 처리량이 떨어집니다. 저는 무조건 고정하기보다 지역성을 우선하고 과부하일 때만 다른 노드로 넘기는 방식을 검토하겠습니다. 실제 데이터 크기와 부하 편중을 재현해서 원격 접근 감소가 전체 지연 개선으로 이어지는지 확인하는 것이 중요합니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 작업과 데이터 배치를 함께 본다. 코어 수만이 아니라 원격 접근 비율을 확인한다.
  • 초기화 방식의 영향을 설명한다. 첫 접근 정책과 페이지 배치를 연결한다.
  • 고정의 부작용을 고려한다. 지역성과 부하 균형 사이에서 조건부 선택을 한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • CPU affinity를 고정하면 항상 빨라진다고 말한다. 불균형과 유휴 자원이 생길 수 있다.
  • 메모리는 모든 코어에서 같은 비용이라고 말한다. NUMA의 원격 접근 차이를 놓친다.
  • 작은 벤치마크만으로 결론 낸다. 캐시에 들어가는 데이터는 실제 원격 메모리 비용을 숨길 수 있다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 노드별 풀에서 다른 노드로 객체를 넘길 때 수명과 해제 비용은 어떻게 달라질까요?
  • 메모리를 노드에 나눠 배치하는 방식과 작업별 지역 배치 중 언제 무엇이 유리할까요?
  • CPU 이동과 페이지 이동 중 어느 쪽을 선택할지 어떻게 판단할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
