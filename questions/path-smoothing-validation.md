# 격자나 NavMesh에서 찾은 경로의 코너를 직선으로 줄일 때 캐릭터 반경·경사·동적 장애물을 어떻게 재검증하나요?

## 구두 답변

경유점을 줄이면 경로가 자연스럽고 짧아질 수 있지만, 원래 탐색이 보장한 통과 가능성을 자동으로 보존하지는 않습니다. 중심점 사이를 잇는 선분이 보인다는 raycast와, 반경·높이·경사 제약이 있는 캐릭터가 실제로 통과할 수 있다는 swept-volume 검사는 다릅니다. 격자에서는 선분이 통과하는 셀과 캐릭터 footprint(캐릭터가 실제로 차지하는 바닥 영역)를 검사하고, NavMesh에서는 portal(인접한 이동 영역을 잇는 통로) 내부의 funnel(불필요한 꺾임을 줄이는 경로 다듬기) 결과가 agent corridor(에이전트가 지나갈 수 있는 통로) 안에 있는지 확인하겠습니다. 중심선만 비어 있고 몸체가 벽에 걸리는 실패를 막기 위해 이동체 크기로 재검사합니다.

예를 들어 중심선은 벽 모서리를 피하지만 몸체 반경이 벽에 걸릴 수 있습니다. 높이·계단·낙하·일방 통행·가중 지형 비용도 직선 후보가 보존해야 할 규칙입니다. 동적 문이나 다른 캐릭터가 생기면 사전 계산 경로가 낡으므로 이동 직전 또는 짧은 구간마다 서버 기준으로 재검증하고 막히면 재탐색합니다.

너무 긴 선분을 허용하면 장애물 변화에 대응하는 구간이 커지고, 스무딩으로 가장 짧은 대신 더 비싼 지형을 통과할 수 있습니다. 서버와 클라이언트가 같은 충돌·반경·틱 규칙을 사용하는지 확인하고, 좁은 모서리·층 경계·큰 agent·동적 문·가중 지형을 시험합니다. 성공 기준은 waypoint 수가 아니라 실제 이동 성공률과 규칙 위반 0건입니다.

## 득점 포인트

- 시야 raycast와 크기 있는 캐릭터의 통과 검사를 구분한다.
- 반경·경사·가중 지형·동적 장애물의 재검증을 포함한다.
- 경로 단순화의 비용과 서버 판정 기준을 성공 지표로 바꾼다.

## 감점 포인트

- 직선으로 보이면 어떤 캐릭터도 통과한다고 말한다.
- 최단 경로 스무딩이 지형 비용과 이동 규칙을 항상 보존한다고 말한다.
- 클라이언트 화면만으로 서버 이동 안전성을 확인한다.

## 더 파고들 거리

- 가중 지형에서 직선 스무딩이 최단이지만 더 비싼 경로를 만들 수 있나요?
- swept-volume 검사와 점 raycast는 모서리·속도에서 어떻게 다른가요?
- funnel의 portal 결과와 동적 장애물 갱신을 어떤 재검증 주기로 결합할까요?
