# 서버 구조체를 바이트로 복사해 보내면 다른 CPU와 언어에서도 같은 값으로 읽을 수 있나요?

## 구두 답변

메모리 구조체 표현은 byte order·padding·정렬·타입 크기·ABI에 의존할 수 있습니다. 네트워크 형식은 필드의 크기·순서·부호·endianness와 길이를 명시해야 합니다.

### 동작 원리와 전제

16비트 값의 바이트 순서가 다르면 수치가 달라지고 padding에는 초기화되지 않은 데이터가 포함될 수도 있습니다. 포인터나 언어 객체 헤더를 그대로 전송하지 않습니다. 검증된 직렬화 포맷이나 명시적인 바이트 인코딩을 사용합니다.

### 선택과 실패 처리

길이 필드는 최대값과 실제 수신 바이트를 비교하고 오버플로를 방지합니다. 버전·알 수 없는 필드·문자열 인코딩·부동소수점 특수값도 계약에 포함합니다. packed 옵션이 전체 이식성을 보장하지 않습니다.

### 구체적인 사례와 검증

메시지 길이가 4바이트 unsigned라고 정했다면 네트워크 순서로 읽은 값을 충분히 넓은 타입에서 검증하고 헤더 길이와 더할 때 overflow를 막습니다. 길이 필드가 맞아도 실제 수신 buffer에 그 바이트가 모두 있는지 확인해야 합니다. 문자열은 UTF-8인지와 byte 길이·문자 길이를 구분합니다. enum의 알 수 없는 값은 구버전 호환 정책에 따라 거절·보류·보존할 수 있습니다. struct padding을 그대로 보내면 불필요한 메모리 내용이 노출될 수 있어 명시적인 필드 직렬화가 안전합니다. 여러 언어의 golden bytes를 같은 테스트에 두면 표현의 일치성을 검증하기 쉽습니다.

다른 언어·아키텍처·잘린 payload·큰 길이·음수·최대값을 golden vector로 시험합니다. TCP 수신 경계와 메시지 경계도 따로 설계합니다. 직렬화는 객체 복사가 아니라 명시한 데이터 계약의 변환입니다.

## 득점 포인트

- 핵심 구분: 메모리 구조체 표현은 byte order·padding·정렬·타입 크기·ABI에 의존할 수 있습니다.
- 선택 조건: 길이 필드는 최대값과 실제 수신 바이트를 비교하고 오버플로를 방지합니다.
- 검증 기준: 다른 언어·아키텍처·잘린 payload·큰 길이·음수·최대값을 golden vector로 시험합니다.

## 감점 포인트

- 같은 필드 이름과 struct 크기면 언어·CPU가 달라도 바이트 표현이 같다고 한다.
