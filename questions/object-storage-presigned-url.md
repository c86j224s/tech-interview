# 파일을 presigned URL로 공유하면 로그인 검사 없이도 안전한가요?

## 구두 답변

presigned URL은 정한 조건 아래 접근할 수 있는 bearer 성격의 권한을 URL 소유자에게 주는 방식입니다. 링크를 가진 사람의 현재 로그인 신원을 자동 검사하는 것과 다르므로 공개 범위·수명·대상을 제한해야 합니다.

### 동작 원리와 전제

읽기와 업로드 권한을 나누고 객체 키·메서드·만료·지원되는 크기·헤더 조건을 지정합니다. URL이 로그·브라우저 기록·메시지에 남으면 다른 사람이 사용할 수 있습니다. 짧은 만료가 즉시 철회를 항상 제공하는 것은 아닙니다.

### 선택과 실패 처리

중요한 자료는 앱의 현재 인가를 거쳐 짧은 URL을 발급하고 다운로드 전에 필요한 정책을 확인합니다. 만료가 전송 중 세션을 끊는지 새 요청만 막는지는 제품 계약에 따릅니다. 같은 키 덮어쓰기가 다른 파일 공개로 이어지지 않게 버전도 관리합니다.

### 구체적인 사례와 검증

URL을 가진 사용자가 다른 사람에게 전달하면 별도 로그인 없이도 접근할 수 있는 경우가 많습니다. 이를 막아야 하는 자료라면 직접 proxy를 통해 현재 인가를 확인하거나 다른 전달 방식을 검토합니다. URL 만료 전 이미 시작한 전송을 즉시 끊는 보장은 제품별로 확인해야 합니다. 업로드 URL은 사용자가 임의의 다른 객체 키를 덮지 못하게 하고 완료 뒤 내용 검사·공개 단계를 나눕니다. CDN 캐시가 URL 만료와 다른 수명으로 콘텐츠를 제공하는지도 확인합니다. 서명 URL은 편리한 제한 위임이지만 비밀 링크의 보관·전송·재사용 정책까지 필요합니다.

다른 사용자 공유·만료·재사용·로그 노출·잘못된 키·업로드 크기를 시험합니다. 추측 어려운 링크와 자원 인가를 동일시하지 않습니다. 링크 발급 권한과 실제 객체 저장소의 정책이 일치하는지 확인하겠습니다.

## 득점 포인트

- 핵심 구분: presigned URL은 정한 조건 아래 접근할 수 있는 bearer 성격의 권한을 URL 소유자에게 주는 방식입니다.
- 선택 조건: 중요한 자료는 앱의 현재 인가를 거쳐 짧은 URL을 발급하고 다운로드 전에 필요한 정책을 확인합니다.
- 검증 기준: 다른 사용자 공유·만료·재사용·로그 노출·잘못된 키·업로드 크기를 시험합니다.

## 감점 포인트

- presigned URL은 링크가 공유되어도 발급받은 로그인 사용자만 사용할 수 있다고 한다.
