# 공간 서버 경계를 넘는 캐릭터의 소유권을 중복 처리와 늦은 입력 없이 이전하려면 어떤 전환점을 두어야 하나요?

## 구두 답변

한 캐릭터의 권위 있는 상태를 두 공간 서버가 동시에 수정하면 입력·전투·보상 이벤트가 중복되거나 순서가 뒤섞입니다. 상태를 새 서버에 복사한 것과 새 서버가 유일한 소유자가 된 것은 다르므로, 이전 작업 ID와 단조 증가하는 세대 번호, 명시적인 전환 단계를 둬야 합니다.

예를 들어 새 서버가 현재 상태와 세대 `g+1`을 준비한 뒤, 기존 서버의 신규 입력을 차단하고 이미 처리 중인 입력을 drain합니다. 그 과정에서 마지막 변경(delta)을 새 서버에 전달하고 최종 delta가 적용됐음을 확인한 다음, 전환점을 기록해 새 서버가 `g+1`의 입력을 받도록 권위를 넘길 수 있습니다. 짧은 입력 보류를 허용하면 이 순서가 단순해지고, 무중단이 필요하면 전환 중 입력을 작업 ID와 순서 번호로 버퍼링해 최종 delta 이후 한 소유자만 순서대로 적용합니다.

모든 서버와 이벤트 소비자는 세대 번호를 조건으로 확인해 오래된 소유자의 늦은 쓰기를 거절해야 합니다. 주변 서버의 복제 상태는 관찰용일 뿐 권위 있는 쓰기 권한이 아닙니다. 이전 실패 상태를 내구적으로 기록하고 어느 서버가 재개·복구 책임을 가지는지 정합니다. 결제·보상 같은 외부 이벤트는 안정적인 account ID·character ID와 업무 멱등성 키를 계속 사용하고, 권위 라우터가 그 식별자를 기준으로 현재 owner epoch를 해석해 올바른 서버로 전달하게 하겠습니다.

테스트는 경계 왕복, 이전 중 입력·전투·접속 종료, 양쪽 서버 재시작, 지연된 이전 메시지, 이전 실패 후 재개를 포함합니다. 성능보다 먼저 동시에 유효한 소유자가 하나뿐이고 각 입력이 중복·역순 없이 처리되는지를 검증하겠습니다.

## 득점 포인트

- 상태 복사와 유일한 소유권 확정을 구분한다.
- 전환점·세대·입력 버퍼·늦은 쓰기 차단을 순서로 설명한다.
- 실패 복구와 안정 ID·멱등 키·owner epoch 기반 라우팅을 포함한다.

## 감점 포인트

- 두 서버가 모두 처리한 뒤 나중에 합치면 된다고 말한다.
- 클라이언트 재접속만으로 소유권이 해결된다고 말한다.
- 관찰 복제본에도 권위 있는 쓰기 권한을 준다.
