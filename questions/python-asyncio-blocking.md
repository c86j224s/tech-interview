# asyncio 서버에서 async 함수가 전체 요청을 느리게 만드는 이유는 무엇인가요?

## 구두 답변

async 함수라는 선언만으로 함수 내부가 논블로킹이 되는 것은 아닙니다. 이벤트 루프에서 오래 계산하거나 동기 파일·네트워크 호출을 하면 그동안 다른 코루틴이 실행 기회를 얻지 못할 수 있습니다. 저는 요청 전체 시간이 아니라 이벤트 루프를 돌려주지 않는 구간을 찾겠습니다.

예를 들어 async 엔드포인트에서 동기 HTTP 라이브러리로 외부 서비스를 부르면, 응답이 늦을 때 다른 요청도 함께 지연될 수 있습니다. 해당 호출을 취소 가능한 비동기 클라이언트로 바꾸는 것이 우선입니다. 바꿀 수 없는 블로킹 라이브러리라면 제한된 스레드 풀에 맡기겠습니다. 다만 풀에 보낸 작업을 기다리는 쪽이 취소돼도 실행 중인 동기 호출은 계속될 수 있어 타임아웃과 동시성 상한이 필요합니다.

CPU 계산이 원인이라면 스레드로 옮기는 것이 실제 병렬 성능을 주는지 실행 환경을 확인해야 합니다. CPython의 일반적인 GIL 환경에서는 순수 Python 계산을 스레드에 옮겨도 코어를 충분히 쓰지 못할 수 있습니다. 프로세스 풀이나 별도 작업 서비스로 분리하되 직렬화와 전달 비용을 재겠습니다. 이벤트 루프 지연과 작업 풀 대기를 따로 측정해, 블로킹을 다른 무제한 큐로 옮기는 데서 끝나지 않도록 하겠습니다.

## 득점 포인트

- **문법과 실행 동작을 구분한다.** async 내부의 동기 호출을 찾는다.
- **작업 종류에 따라 대안을 고른다.** 비동기 I/O·스레드·프로세스를 구분한다.
- **격리 후의 한계를 본다.** 취소와 풀 대기 상한을 확인한다.

## 감점 포인트

- **async이면 자동으로 별도 스레드라고 말한다.** 이벤트 루프에서 실행할 수 있다.
- **스레드 풀로 보내면 취소도 즉시 된다고 말한다.** 실행 중 동기 호출은 남을 수 있다.
- **CPU 작업도 무조건 스레드를 늘리면 된다고 말한다.** 런타임과 작업 특성을 확인해야 한다.
