# 갱신 토큰을 회전시키는 서버가 정상 동시 갱신과 탈취 재사용을 어떻게 구분하고 차단하나요?

## 구두 답변

갱신 토큰 회전은 한 번 사용한 토큰을 새 토큰으로 교체하고, 이전 토큰을 다시 사용했는지 기록하는 방식입니다. 이전 토큰이 정상 회전 뒤 다시 들어오면 토큰 계열이 복제됐을 가능성을 탐지할 수 있습니다. 그러나 모바일 앱의 응답 유실이나 여러 탭의 동시 요청도 같은 모양을 만들 수 있으므로 재사용을 무조건 공격으로 단정하면 정상 사용자를 대량 로그아웃시킬 수 있습니다.

서버는 토큰 원문 대신 안전한 해시와 토큰 계열·기기 세션·상태·버전을 저장하고, 현재 유효한 토큰을 조건부로 소비해 새 토큰을 원자적으로 발급해야 합니다. 두 요청이 동시에 같은 토큰을 사용하면 하나만 전환에 성공하게 하고, 다른 요청은 짧은 재시도 유예나 동일 요청 식별 결과를 확인하도록 설계할 수 있습니다. 유예를 무제한으로 두면 회전의 탐지 효과가 사라집니다.

토큰을 회전했지만 응답이 끊긴 경우 클라이언트가 이전 토큰으로 재시도합니다. 서버는 제한된 조건에서 이미 발급한 후속 결과를 재사용할지, 계열을 회수할지 정책을 가져야 합니다. 확실한 비정상 재사용이면 해당 기기 세션 또는 전체 토큰 계열을 폐기하고 재인증을 요구할 수 있으며, 이미 발급한 짧은 접근 토큰의 즉시 무효화는 별도의 검증 저장소나 짧은 수명 정책이 필요합니다.

테스트는 동시 갱신, 응답 유실, 오래된 토큰 재사용, 여러 기기, 저장소 재시작을 포함합니다. 로그에 토큰 원문을 남기지 않고 회전 버전과 실패 이유만 관찰하겠습니다.

## 득점 포인트

- 이전 토큰 재사용을 탐지하는 회전 원리를 설명한다.
- 응답 유실·동시 요청과 공격 재사용을 구분한다.
- 원자적 소비·회수 범위·비밀 보관을 구체화한다.

## 감점 포인트

- 모든 재사용이 공격이라고 단정한다.
- 오래된 토큰을 계속 허용해 탐지 효과를 없앤다.
- 분석을 위해 토큰 원문을 로그에 남긴다.

## 더 파고들 거리

- 여러 탭·기기의 동시 갱신에서 클라이언트와 서버 책임은 어떻게 나뉘나요?
- 토큰 계열 회수가 기존 접근 토큰에 즉시 적용되려면 무엇이 필요한가요?
- 재시도 유예 시간을 어떤 네트워크·클라이언트 근거로 정하나요?
