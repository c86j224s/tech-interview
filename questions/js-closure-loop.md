# 반복문 안에서 만든 콜백이 마지막 값만 출력합니다. var와 let의 클로저 캡처는 왜 다르게 보이나요?

## 구두 답변

클로저는 함수를 만들 때의 변수 값을 사진처럼 복사하는 기능이 아니라, 함수가 참조하는 바깥 렉시컬 환경을 계속 사용할 수 있게 하는 구조입니다. 그래서 반복문 변수의 선언 방식이 결과를 바꿉니다.

```js
const varFns = [];
for (var i = 0; i < 3; i++) varFns.push(() => i);

const letFns = [];
for (let j = 0; j < 3; j++) letFns.push(() => j);

console.log(varFns.map(fn => fn())); // [3, 3, 3]
console.log(letFns.map(fn => fn())); // [0, 1, 2]
```

`var i`는 함수 스코프에 바인딩 하나만 만들고 세 함수가 그 같은 바인딩을 공유합니다. 반복이 끝난 뒤 그 바인딩의 값이 3이므로 나중에 콜백을 호출하면 모두 3을 읽습니다. 반면 `for`의 `let j`는 반복마다 별도의 환경과 바인딩을 제공하므로 각 콜백이 자기 반복의 `j`를 참조합니다. 핵심은 클로저가 현재 값을 복제하는지가 아니라 어떤 바인딩을 공유하는지입니다.

`var`를 꼭 써야 한다면 반복마다 값을 함수 인자로 넘겨 새 매개변수 바인딩을 만드는 방식으로 고정할 수 있습니다. 다만 현대 JavaScript에서는 이 목적에 `let`을 쓰는 것이 단순합니다. 콜백을 즉시 실행하는 코드와 나중에 실행하는 코드를 구분해야 하며, 클로저가 큰 객체나 이벤트 대상까지 계속 참조하면 작업이 끝난 뒤에도 메모리가 유지될 수 있으므로 수명도 함께 관리하겠습니다.

## 득점 포인트

- 클로저가 값을 복사하기보다 바인딩을 참조한다는 점을 설명한다.
- var의 함수 스코프 단일 바인딩과 let의 반복별 바인딩을 대비한다.
- var 대안과 클로저 수명에 따른 메모리 보유를 제시한다.

## 감점 포인트

- var 콜백이 각 반복의 숫자를 자동으로 저장한다고 말한다.
- let이 항상 전역 변수라서 결과가 다르다고 설명한다.
- 클로저가 참조하는 객체의 수명에는 영향을 주지 않는다고 말한다.

## 더 파고들 거리

- forEach의 콜백 매개변수는 반복별 값을 어떻게 전달하나요?
- 클로저로 상태를 숨길 때 모듈이나 class private 필드와 무엇이 다른가요?
