01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

UDP는 애플리케이션이 전달 정책을 직접 정할 수 있지만, 프로토콜만 바꾼다고 지연 문제가 해결되는 것은 아닙니다. 순서와 재전송을 TCP처럼 모두 다시 구현하면 비슷한 대기와 더 큰 구현 비용을 만들 수 있습니다. 먼저 오래된 데이터가 늦게 오는 것과 일부 데이터가 빠지는 것 중 무엇을 허용할지 정하겠습니다.

실시간 위치 정보라면 몇 초 전 위치를 재전송해 받는 것보다 최신 위치를 받는 것이 중요할 수 있습니다. 이런 경우 순서 번호로 오래된 상태를 버리고 최신 상태를 반복 전달하는 방식을 쓸 수 있습니다. 반면 결제나 계정 변경처럼 유실되면 안 되는 메시지는 확인 응답과 중복 방지, 재시도가 필요합니다. 메시지 종류를 구분하지 않고 모두 같은 신뢰성 정책에 넣지 않겠습니다.

UDP를 선택하더라도 혼잡 제어와 전송률 제한, 메시지 크기와 경로 MTU를 다뤄야 합니다. 큰 데이터그램이 조각나면 손실 영향이 커질 수 있고 NAT나 방화벽 환경에서 연결 유지도 필요할 수 있습니다. 저는 실제 손실·재정렬·지연 환경에서 사용자 경험과 대역폭을 비교하겠습니다. 이미 검증된 전송 라이브러리가 요구사항을 만족한다면 직접 프로토콜을 만드는 것보다 우선 검토하겠습니다. 선택 기준은 이름이 아니라 메시지별 최신성·신뢰성과 운영 비용입니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 업무 메시지의 요구를 나눈다. 최신 상태와 반드시 반영할 명령을 구분한다.
  • 직접 책임질 기능을 설명한다. 혼잡·중복·순서·크기를 포함한다.
  • 실제 경로에서 검증한다. 손실·재정렬·NAT와 비용을 확인한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • UDP는 항상 더 빠르고 가볍다고 말한다. 필요한 신뢰성 구현에 따라 달라진다.
  • UDP에는 혼잡 제어가 필요 없다고 말한다. 전송률을 무제한으로 밀면 경로를 악화시킨다.
  • 모든 메시지를 재전송한다. 이미 쓸모없는 상태를 늦게 전달할 수 있다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 스냅샷과 입력 명령을 서로 다른 전달 정책으로 나누면 어떤 장점이 있나요?
  • 경로 MTU를 넘는 메시지를 애플리케이션에서 나눌 때 어떤 상태가 필요할까요?
  • 순서 번호가 순환할 때 최신 패킷 여부를 어떻게 비교할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
