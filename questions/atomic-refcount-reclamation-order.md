# 참조 카운트 증감의 메모리 순서와 객체 데이터를 처음 공개하는 메모리 순서는 왜 따로 설계해야 하나요?

## 구두 답변

새 참조를 얻는 증가는 이미 유효한 소유권을 가진 상태에서 수를 늘리는 경우와 객체 최초 공개가 다릅니다. 감소가 마지막 참조를 없애면 이전 쓰기가 소멸·회수 경로에 보이도록 적절한 순서가 필요합니다.

구현에 따라 증가 relaxed, 감소 release와 마지막 acquire fence 같은 패턴을 쓰지만 증명된 소유·동기화 전제를 따라야 합니다. raw pointer에서 수만 증가시키면 이미 해제된 객체를 부활시킬 수 없습니다. 참조 계수 보호와 객체 필드 동시성은 별도로 설계합니다.
