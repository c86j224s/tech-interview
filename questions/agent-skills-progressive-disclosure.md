# 에이전트에 팀별 작업 지침과 스크립트를 계속 추가하고 있습니다. Agent Skills와 점진적 로딩은 어떤 문제를 해결하나요?

## 구두 답변

자주 반복되는 작업의 지침·참고 자료·스크립트를 작은 패키지로 묶고 필요한 순간에만 자세한 내용을 읽게 할 수 있습니다. Agent Skills는 이런 재사용 가능한 지식과 절차의 형식을 제공하며, 모든 지침을 항상 프롬프트에 넣는 비용을 줄이는 데 도움이 됩니다. 스킬은 학습된 모델 가중치나 실행 권한 자체가 아니라 런타임이 발견하고 읽는 자료입니다.

### 메타데이터에서 필요한 절차로 들어갑니다

확인한 Agent Skills 형식은 필수 SKILL.md에 name·description 프런트매터와 본문 지침을 두고, 선택적으로 scripts·references·assets 등을 포함합니다. 처음에는 이름과 설명으로 관련성을 판단하고, 활성화할 때 본문을 읽으며, 세부 참고 파일과 스크립트는 필요에 따라 접근합니다. 이를 **점진적 공개** 또는 progressive disclosure라고 합니다. 토큰을 아끼려면 설명이 실제 사용 조건을 분명히 드러내야 하며 모든 요청에 해당하는 광범위한 문구는 오탐 호출을 늘릴 수 있습니다.

예를 들어 데이터 정리 스킬은 입력 CSV 검사 절차와 검증된 변환 스크립트, 오류 예제를 제공할 수 있습니다. 실행 가능한 코드를 미리 갖추면 모델이 매번 같은 변환을 새로 작성하는 비용을 줄이지만, 실행 전 입력·경로·부수 효과·의존성을 확인해야 합니다. 스킬의 allowed-tools 같은 메타데이터가 지원되는지는 구현마다 다를 수 있고, 문서가 도구를 허용한다고 host의 보안 정책을 넘어서는 것은 아닙니다.

### 재사용과 공급망 책임

스킬을 공유하면 잘못된 지침도 여러 작업에 반복 적용됩니다. 버전·소유자·테스트·배포 출처를 관리하고, 업데이트 전후에 어떤 행동이 바뀌는지 검토합니다. 다른 프로젝트에서 유효했던 경로나 승인 절차를 현재 프로젝트에 무조건 적용하지 않습니다. 외부 스킬 파일은 읽기만 해도 모델의 행동에 영향을 주므로 코드뿐 아니라 설명과 예시도 검토 대상입니다.

평가에서는 스킬 선택 정확도, 필요한 참고 자료를 찾는 비율, 지침 준수, 결과 정확성·총 토큰·실행 시간을 비교합니다. 과도한 분할로 파일을 계속 찾아다니면 지연이 늘고 중요한 지침을 누락할 수 있으므로 본문과 세부 자료의 경계를 조정합니다. A2A Agent Card의 skill은 원격 에이전트가 광고하는 기능이고 SKILL.md 패키지와 동일한 규약은 아닙니다. 이름이 같아도 discovery와 실행·권한의 실제 계약을 구분하겠습니다.

### 실행 사례로 확인합니다

점진 로딩의 실패도 구체적으로 시험합니다. 설명이 너무 일반적이면 관련 없는 스킬이 켜지고, 핵심 금지 조건을 깊은 참고 파일에만 숨기면 모델이 그 파일을 읽지 않아 놓칠 수 있습니다. 항상 필요한 범위·입력 검증·중단 조건은 본문에 두고 긴 형식 설명과 예제는 참조로 분리하는 편이 안전합니다. 스크립트가 특정 Python·운영체제·네트워크를 요구하면 compatibility나 지침에서 알리고 실행 전 확인합니다. 형식 검사 도구가 통과해도 지침의 정확성과 코드 안전성을 증명하지는 않습니다. 실제 과제와 경계 입력을 실행해 결과가 맞는지, 스킬을 쓰지 않은 기준선보다 재현성과 비용이 좋아졌는지 비교하겠습니다.

## 득점 포인트

- 스킬을 지침·자료·코드 패키지로 설명하고 가중치 학습과 구분한다.
- 메타데이터·본문·참고 자료의 점진적 로딩과 선택 정확도를 연결한다.
- 스킬 버전·코드·설명 검토와 host 권한 경계를 유지한다.

## 감점 포인트

- 스킬 파일을 추가하면 모델이 영구 학습했다고 한다.
- allowed-tools가 모든 host에서 보안 권한을 자동 부여한다고 본다.
- 공유 스킬의 지침과 스크립트를 검토 없이 실행한다.

- 외부 스킬 업데이트의 설명과 스크립트가 바뀌면 무엇을 검토하나요?
- 참고 파일을 너무 잘게 나눠 탐색 비용이 늘면 로딩 경계를 어떻게 조정하나요?
