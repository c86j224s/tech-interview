# 네트워크가 두 지역으로 갈라진 동안에도 서비스를 계속 제공하려 합니다. CAP의 C와 A를 어떤 대가로 선택하나요?

## 구두 답변

CAP에서 네트워크 분할 허용성은 분산 노드 사이의 통신이 끊겨도 시스템이 그 상황을 견디는 성질입니다. 분할이 실제로 발생한 동안에는 각 지역이 서로의 최신 쓰기를 알 수 없으므로, 선형화 가능한 일관성(C)을 유지하면서 양쪽이 모두 성공 응답을 계속 내리기는 어렵습니다. 한쪽이나 과반 쿼럼만 쓰기를 허용하고 다른 쪽은 오류·대기로 돌리면 서로 다른 성공 순서를 만들지 않는 대신 가용성(A)을 일부 포기합니다. 반대로 각 지역이 독립적으로 쓰기를 성공시키면 요청에는 계속 응답할 수 있지만 나중에 충돌을 병합하거나 최종 일관성을 받아들여야 하므로 강한 C를 포기하는 선택이 됩니다.

여기서 C는 ‘모든 복제본이 항상 같은 바이트를 가진다’는 막연한 의미가 아니라, 성공한 연산이 하나의 최신 순서에 맞게 관찰되는 강한 일관성으로 이해해야 합니다. A는 실패하지 않은 노드가 받은 요청마다 해당 연산의 명세에 맞는 응답을 결국 제공한다는 조건입니다. 단순한 오류 응답을 계속 보내는 것으로 충족되는 것이 아니며, 정해진 밀리초 안의 응답을 뜻하는 성능 상한과도 다릅니다. 네트워크 분할 허용성은 선택 항목이라기보다 분산 시스템에서 장애로 발생할 수 있는 상황을 어떻게 처리할지에 가깝습니다. 그래서 ‘CAP는 셋 중 둘을 평소에 고르는 공식’으로 설명하면 부정확합니다.

정상 네트워크에서는 강한 일관성 시스템도 왕복과 쿼럼 확인 비용 때문에 지연을 늘릴 수 있고, 최종 일관성 시스템도 캐시와 복제 상태에 따라 빠를 수 있습니다. 즉 분할이 없는 평상시의 지연은 CAP의 C/A 선택과 별도로 측정해야 합니다. 또한 한 서비스 전체를 CP나 AP로 낙인찍기보다 기능별로 기준을 정합니다. 잔액 차감과 중복 결제 방지는 분할 중 쓰기를 거부하더라도 C를 우선할 수 있고, 좋아요 수나 분석 수집은 임시 충돌을 허용하고 A를 우선할 수 있습니다.

선택 뒤에는 사용자에게 재시도 가능한 오류인지, 읽은 값이 잠정적인지, 충돌을 어떻게 정정하는지까지 계약으로 드러내야 합니다. 쿼럼 구성과 타임아웃, 장애 복구 뒤 병합 규칙을 검증하지 않은 채 ‘가용성을 높였다’고 말하지 않겠습니다.

## 득점 포인트

- 분할 중 강한 일관성과 계속되는 성공 응답을 동시에 보장할 수 없는 실행 선택을 설명한다.
- CAP의 C·A를 지연 시간이나 복제본의 물리적 동일성과 혼동하지 않는다.
- 잔액과 좋아요처럼 기능별로 다른 선택과 사용자 계약을 제시한다.

## 감점 포인트

- CAP를 평상시에도 C·A·P 중 두 개만 고르는 단순한 체크표로 설명한다.
- 복제본이 잠시 다른 값을 보이면 곧바로 CAP 위반이라고 단정한다.
- AP를 선택하면 충돌 병합과 정정 정책이 필요 없다고 말한다.
