# 점수로 정렬한 뒤 동점자의 기존 순서를 유지하려 합니다. 안정 정렬은 어떤 보장인가요?

## 구두 답변

안정 정렬은 비교 기준상 같은 원소들의 입력 상대 순서를 유지합니다. 점수가 같은 두 사용자가 입력에서 A, B 순서였다면 정렬 뒤에도 A가 먼저입니다. 같은 점수가 항상 사용자 ID순이라는 뜻은 아니므로 입력 순서가 바뀌면 결과도 바뀔 수 있습니다.

여러 기준으로 정렬할 때 낮은 우선순위부터 안정 정렬을 적용하면 이전 순서를 보존하며 기준을 쌓을 수 있습니다. 그러나 분산 랭킹처럼 입력 순서가 일정하지 않다면 안정성만 믿기보다 점수와 사용자 ID 같은 명시적인 보조 키를 비교하는 편이 재현하기 쉽습니다.

저는 라이브러리 정렬이 안정적인지와 비교 함수가 일관된 순서를 정의하는지 확인하겠습니다. 비교에서 동등한 원소와 실제 같은 객체도 구분해야 합니다. 안정성을 얻기 위해 추가 메모리를 쓰는 구현도 있어 비용을 비교합니다. 테스트는 동점 원소에 원래 순서 표식을 붙이고, 정렬 후 기준 순서와 상대 순서가 모두 맞는지 확인하겠습니다.

## 득점 포인트

- 동등 원소의 상대 순서 보장을 설명한다.
- 안정성과 결정적인 보조 키를 구분한다.
- 비교자와 라이브러리 계약을 검증한다.

## 감점 포인트

- 안정 정렬이면 입력과 무관하게 같은 결과라고 말한다.
- 모든 정렬 알고리즘이 안정적이라고 말한다.
- 불일치하는 비교자를 안정 정렬이 고쳐준다고 말한다.

## 더 파고들 거리

- 점수 내림차순·가입일 오름차순을 안정 정렬 두 번으로 어떻게 만들까요?
- 제자리 정렬과 안정 정렬은 같은 개념인가요?
- NaN이 비교자에 들어오면 어떤 순서 문제가 생길까요?
