# 복셀 월드를 청크로 스트리밍할 때 충돌·경로·시야가 청크 경계에서 틀어지지 않게 하려면 무엇을 관리해야 하나요?

## 구두 답변

청크는 로딩·저장·파생 데이터 재생성의 단위를 줄이는 방법이지 물리 세계가 청크 경계에서 끊긴다는 뜻이 아닙니다. 충돌·경로·raycast가 경계 밖 이웃을 보지 못하면 실제 벽을 빈 공간으로 처리하거나, 반대로 미로딩을 장애물로 처리해 경로를 잃습니다. 따라서 **미로딩 상태와 빈 복셀**(unloaded versus empty voxel)을 별도의 상태로 표현하고, 검사 종류별로 보수적 차단·지연·재시도 정책을 정해야 합니다.

### 좌표와 경계 이웃

월드 좌표를 청크 좌표와 내부 좌표로 나누는 규칙은 양수만으로 검증하면 안 됩니다. 청크 크기가 `C`일 때 -1을 0 방향으로 절삭하면 청크 0의 내부 -1처럼 잘못 표현될 수 있으므로 floor division으로 청크 좌표를 구하고 내부 좌표를 `0..C-1`에 둡니다. 세 축의 모서리에서는 최대 8개 이웃 청크가 관련될 수 있고, 캐릭터 반경·ray 길이·경로 footprint에 따라 한 셀보다 넓은 halo가 필요합니다. 경계 복셀이 바뀌면 해당 청크만이 아니라 메시·충돌·경로·시야 파생 데이터를 가진 이웃 청크도 무효화합니다. 청크 이웃이 아직 로드되지 않았다면 raycast는 ‘빈 공간’이라는 성공을 반환해서는 안 됩니다. 충돌은 안전을 위해 보수적으로 막고 로딩 완료 뒤 재시도할 수 있으며, 시야는 잠정 실패로 표시할지, 경로는 해당 영역을 통과하지 않는 부분 결과만 허용할지 기능별로 정합니다. 이렇게 하면 미로딩 지연이 게임을 멈출 수 있으므로 최대 대기 시간과 실패 메시지를 둡니다. ghost cell 또는 halo 영역을 이웃에서 복사해두면 경계 조회를 줄일 수 있지만, 원본과 halo의 버전을 함께 확인해야 낡은 벽을 사용하지 않습니다.

### 로딩·언로딩 수명

한 요청이 청크 데이터를 읽는 동안 언로드가 일어나면 포인터가 해제되거나 한 검사에서 서로 다른 버전의 셀이 섞일 수 있습니다. 읽기 작업이 참조하는 청크를 작업 끝까지 고정하거나, 원자적으로 교체되는 불변 스냅샷과 참조 카운트·epoch를 사용하겠습니다. 청크 버전과 이웃 버전이 요구된 일관성에 맞지 않으면 경로 결과에 잠정 상태를 붙이고 실행 전에 거절합니다. 수정은 원본 변경 버전부터 발급하고 충돌·경로·시야 파생 데이터의 적용 버전을 기록합니다. 테스트는 음수 좌표, 한 셀·세 축 경계, 로딩 중 raycast, 경계 복셀 수정, 이웃 동시 언로드, 모서리의 다중 청크, 긴 ray를 포함합니다. 청크 크기는 파일 크기만 보지 않고 경계 재생성 폭, 이웃 조회량, 캐시 지역성, 로딩 지연과 메모리를 함께 측정합니다. 청크 경계를 **데이터 경계로만 유지하고 물리 경계로 오인하지 않는 것**이 핵심입니다. 경계에서 필요한 이웃 폭은 청크 크기보다 에이전트와 질의 범위로 정합니다.

캐릭터 반경이 작아도 충돌 shape가 경계를 넘어가면 옆 청크가 필요하고, 긴 ray는 여러 청크의 로딩 상태를 순서대로 확인해야 합니다. halo를 복사한다면 원본 변경 시 이웃을 갱신하고, 갱신 전 halo를 최신으로 표시하지 않겠습니다. 로딩 완료를 기다리는 동안 입력을 모두 멈추면 게임 정지가 커질 수 있으므로 안전 구역과 로딩 중 진입 차단 영역을 구분합니다. 충돌은 보수적으로 막되 시야·렌더링은 잠정 상태를 사용할 수 있고, 결과에 청크 버전을 넣어 늦은 메시지가 최신 상태를 덮지 않게 하겠습니다.

## 득점 포인트

- 미로딩과 실제 빈 공간을 구분하고 기능별 보수 정책을 둔다.
- 음수 좌표 floor 규칙과 경계 이웃 무효화를 설명한다.
- 언로드 경합에서 스냅샷·참조 수명·버전을 관리한다.

## 감점 포인트

- 로드되지 않은 청크를 무조건 빈칸으로 반환한다.
- 양수 좌표만으로 청크 변환을 검증한다.
- 언로드 중인 청크의 포인터를 계속 사용해도 안전하다고 말한다.
