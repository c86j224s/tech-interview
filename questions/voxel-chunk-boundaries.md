# 복셀 월드를 청크로 스트리밍할 때 충돌·경로·시야가 청크 경계에서 틀어지지 않게 하려면 무엇을 관리해야 하나요?

## 구두 답변

청크는 로딩·저장·재생성 단위를 줄이는 방법이지 월드의 물리적 경계를 만드는 방법이 아닙니다. 충돌·경로·raycast는 청크 밖의 이웃까지 볼 수 있어야 하므로, 이웃 청크를 로드하지 않았다는 이유로 실제 벽을 빈 공간으로 처리하면 벽 통과나 잘못된 경로가 생깁니다. 미로딩 상태와 실제 빈 복셀을 별도로 표현하고, 충돌·경로·시야 검사의 요구에 따라 보수적 차단이나 지연을 선택해야 합니다.

월드 좌표를 청크 좌표와 내부 좌표로 바꾸는 규칙은 음수와 경계에서 명시합니다. 예를 들어 좌표를 청크 크기로 나눌 때 0 방향 절삭을 사용하면 -1이 잘못된 청크와 내부 위치로 갈 수 있으므로 floor division과 음수가 아닌 내부 좌표를 일관되게 사용하겠습니다. 청크 변경은 경계 이웃의 메시·경로·충돌 파생 데이터도 무효화해야 합니다.

동시에 로딩·언로딩과 읽기가 일어나면 읽기 작업이 참조하는 청크 데이터를 작업 끝까지 유지하거나 버전 스냅샷을 사용합니다. 이웃 청크가 아직 없으면 raycast를 실패시키거나 보수적으로 막고, 언제 재시도할지 정합니다. 청크 버전이 서로 다르면 경로 계산을 잠정 결과로 표시하거나 일관된 버전이 될 때까지 기다립니다.

테스트는 음수 좌표, 모서리·세 축 경계, 청크 로딩 중 raycast, 경계 복셀 수정, 언로드와 읽기 경합을 포함합니다. 청크 크기는 저장 효율뿐 아니라 이웃 조회·경계 재생성·캐시 지역성까지 포함해 정하겠습니다.

## 득점 포인트

- 미로딩과 빈 공간을 구분하고 보수적 경계 정책을 정한다.
- 음수 좌표·floor 규칙과 경계 이웃 무효화를 설명한다.
- 버전과 참조 수명을 로딩·언로딩 동시성에 연결한다.

## 감점 포인트

- 청크 밖을 무조건 빈칸으로 처리한다.
- 양수 좌표만으로 좌표 변환을 검증한다.
- 언로드 중인 데이터를 읽어도 수명 문제가 없다고 말한다.

## 더 파고들 거리

- ghost cell·halo 영역이 이웃 조회를 어떻게 줄이나요?
- 청크 버전이 다를 때 경로 결과를 언제 거절하나요?
- 청크 크기 변경이 갱신 폭과 캐시 지역성에 미치는 영향은 무엇인가요?
