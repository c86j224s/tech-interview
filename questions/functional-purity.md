# 같은 인자를 넘겼는데 함수 결과가 호출 시각과 전역 설정에 따라 달라집니다. 순수 함수로 만들려면 무엇을 바꿔야 하나요?

## 구두 답변

순수 함수는 같은 입력에 항상 같은 결과를 내고, 호출 자체로 외부 상태를 바꾸거나 관찰하지 않는 함수입니다. 따라서 현재 시각을 직접 읽거나 전역 환율을 조회하거나 파일에 로그를 쓰는 함수는 결과 또는 외부 상태가 호출 환경에 의존하므로 순수하지 않습니다. 순수하다는 말은 함수가 유용한 일을 하지 않는다는 뜻이 아니라, 계산과 부수효과의 경계를 분리한다는 뜻입니다.

예를 들어 `priceWithTax(price)`가 전역 `currentTaxRate`를 읽으면 같은 가격도 설정 변경에 따라 달라집니다. 세율을 인자로 받아 `priceWithTax(price, taxRate)`로 계산하게 하면 계산 부분은 순수해집니다. 현재 시각이 필요하면 시각을 읽는 얇은 경계에서 시간을 값으로 얻어 순수 계산 함수에 전달하겠습니다. 계산 결과를 DB에 저장하거나 화면에 표시하는 일은 별도의 효과 단계가 맡도록 하면 테스트에서 입력과 결과를 직접 비교할 수 있습니다.

순수 함수는 캐시, 병렬 실행, 재시도, 테스트 격리에 유리하지만 모든 코드를 순수하게 만들 수는 없습니다. 네트워크·파일·DB·난수는 실제 시스템의 목적에 필요한 효과입니다. 효과를 없애기보다 효과가 발생하는 위치와 순서를 명확히 하고, 효과를 감싼 경계에서 실패·재시도·중복을 처리하겠습니다. 특히 전달한 객체를 몰래 수정하면 결과뿐 아니라 호출자의 상태도 바뀌므로, 함수의 순수성을 말할 때 입력 값 변경 여부도 확인해야 합니다.

## 득점 포인트

- 동일 입력 동일 결과와 외부 상태 변경 부재라는 순수 함수의 두 조건을 구분한다.
- 시계·설정·난수 같은 비결정성을 입력으로 받아 계산과 효과를 분리한다.
- 부수효과를 제거하는 대신 경계에 모아 실패와 재시도 정책을 명시한다.

## 감점 포인트

- 함수가 값을 반환하기만 하면 순수하다고 말한다. 전역 상태를 변경하거나 입력 객체를 수정할 수 있다.
- 외부 호출이 없으면 순수하다고 한다. 전역 설정이나 현재 시각을 읽는 것도 결과를 바꾼다.
- 함수형 설계는 모든 I/O를 금지한다고 말한다. 효과는 필요하며 중요한 것은 경계와 순서다.

## 더 파고들 거리

- 순수 함수의 결과를 메모이제이션할 때 입력 객체의 동일성과 해시 기준을 어떻게 정할까요?
- 난수 생성기를 순수 계산과 결합해야 할 때 seed와 상태를 어떤 값으로 전달할까요?
- 부수효과가 여러 개일 때 실패 중간 상태와 재시도 중복을 어떤 테스트로 검증할까요?
