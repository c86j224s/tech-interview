# 클라이언트가 이동 위치와 공격 결과를 서버에 보냅니다. 서버는 무엇을 그대로 받아들이고 무엇을 다시 계산해야 하나요?

## 구두 답변

클라이언트가 보낸 위치나 피해량을 그대로 최종 상태로 받아들이기보다, 입력 의도와 서버가 아는 상태로 허용 여부와 결과를 결정한다는 뜻입니다. 서버 권위는 클라이언트를 전혀 믿지 않는다는 구호보다 어떤 값이 주장이고 어떤 값이 확정인지 나누는 계약입니다.

예를 들어 클라이언트가 “이 적에게 피해 100을 줬다”고 보내더라도 서버는 거리·공격 가능 상태·소모 자원을 확인해 실제 결과를 정해야 합니다. 반면 사용자가 어느 방향으로 움직이려 했는지는 입력 의도로 받을 수 있습니다. 서버의 확정 전 화면에서 먼저 움직여 반응을 빠르게 만드는 것이 클라이언트 예측이며, 나중에 서버 결과와 다르면 보정합니다.

이동 요청이라면 속도·현재 상태·충돌·입력 순서를 확인하겠습니다. 공격 요청은 대상 거리, 자원, 재사용 대기, 실행 가능한 상태인지 검사해야 합니다. 매 요청을 지나치게 비싸게 검증하면 남용에 취약해질 수 있어 싼 형식·권한 검사부터 하고 필요한 계산을 제한하겠습니다.

네트워크 지연 때문에 클라이언트 예측과 서버 결과가 다를 수 있습니다. 서버는 입력 번호와 확정 상태를 보내 클라이언트가 보정할 수 있게 하되, 지연이 있었다는 이유로 임의의 과거 행동을 무제한 허용하지 않겠습니다. 테스트는 중복·역순·오래된 입력과 비정상 속도·거리, 정상 고지연 사용자를 함께 포함합니다. 보안과 반응성 사이에서 허용할 보정 범위를 명시하는 것이 중요합니다.

## 득점 포인트

- 입력 의도와 서버 확정 상태·피해를 구분한다.
- 검증 순서와 계산·입력 빈도 제한을 제시한다.
- 클라이언트 예측과 서버 확정의 차이, 오래된 입력의 허용 범위를 설명한다.

## 감점 포인트

- 클라이언트 피해량·위치를 그대로 신뢰한다.
- 서버 권위면 지연 보정이 필요 없다고 말한다.
- 오래된 입력을 제한 없이 재현한다.

## 더 파고들 거리

- 확인 이후 입력을 어떤 순서로 재적용할까요?
- 입력 번호 중복·누락 시 어떤 계약을 둘까요?
- 서버 검증 계산 남용을 어떤 상한으로 막을까요?
