# Argo CD sync wave와 hook은 DB 마이그레이션에 어떤 도움이 되나요?

## 구두 답변

sync wave는 리소스 적용 순서를 나누는 데, hook은 동기화 전후의 작업을 실행하는 데 사용할 수 있습니다. DB 마이그레이션을 앱보다 먼저 실행하는 흐름에 도움이 되지만 순서 설정만으로 스키마 호환성과 롤백이 해결되지는 않습니다.

새 앱이 읽을 컬럼을 먼저 추가하고 백필을 별도 단계로 수행하는 식으로 구성할 수 있습니다. 다만 migration job이 재실행될 수 있으므로 멱등성과 진행 상태가 필요합니다. hook 성공이 실제 데이터 검증 완료를 뜻하도록 해야 하고, 앱이 새 스키마를 요구하는 시점과 모든 구버전이 호환되는 기간을 확인하겠습니다.

긴 백필을 동기화 전체의 무제한 대기로 넣으면 배포가 오래 막힐 수 있습니다. 저는 짧은 구조 추가와 장기 데이터 이관을 분리하고 각 완료 기준을 명확히 하겠습니다. 실패한 hook의 재시도·삭제 정책과 로그 보존도 확인합니다. 테스트는 이미 적용된 마이그레이션 재실행, 일부 실패, 앱 롤백을 포함합니다. 도구는 적용 순서를 도울 뿐 데이터 변경을 되돌리는 보장은 주지 않습니다.

## 득점 포인트

- 순서와 데이터 호환성을 구분한다.
- hook 재실행의 멱등성을 확보한다.
- 장기 이관과 배포를 적절히 분리한다.

## 감점 포인트

- wave 순서면 모든 서비스 준비가 자동 보장된다고 말한다.
- hook은 한 번만 실행된다고 가정한다.
- 앱 롤백이 DB도 원래대로 만든다고 말한다.

## 더 파고들 거리

- Health 판정이 다음 wave 진행에 어떤 영향을 주나요?
- hook 로그가 지워지기 전에 실패 근거를 어떻게 보존할까요?
- 여러 앱이 같은 DB를 바꿀 때 동기화 소유권은 어떻게 정할까요?
