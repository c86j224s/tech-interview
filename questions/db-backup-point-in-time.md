# 백업 뒤 실수로 데이터를 삭제했습니다. 삭제 직전 시점 복구에는 전체 백업 외에 무엇이 필요한가요?

## 구두 답변

특정 시점 복구는 기준 백업과 그 이후 연속된 변경 로그를 이용해 원하는 지점까지 재생하는 방식입니다. 로그 일부가 없거나 기준 백업과 맞지 않으면 목표 시점에 도달하지 못할 수 있습니다.

### 동작 원리와 전제

잘못된 DELETE가 커밋된 시각·transaction·로그 위치를 찾아 그 직전까지 복구합니다. 운영 DB를 즉시 덮기보다 별도 환경에서 복원하고 필요한 행과 관계를 검증합니다. 벽시계만으로 경계를 고르면 시계 오차나 동시 거래를 놓칠 수 있어 엔진의 복구 목표 표현을 확인합니다.

### 선택과 실패 처리

복원 DB가 옛 outbox나 미처리 메시지를 포함하면 소비자가 실제 결제·메일을 다시 실행할 수 있습니다. 외부 효과를 격리하고 원장과 대사합니다. 삭제된 일부 행을 운영에 되돌릴 때도 이후 정상 변경과 충돌하지 않게 키·버전·참조를 확인합니다.

### 구체적인 사례와 검증

백업이 오전 1시이고 삭제가 10시 5분이라면 1시 이후 로그가 연속적으로 있어야 10시 4분대 상태에 도달할 수 있습니다. 단순히 최근 파일 하나를 복사했다고 복구 체인이 완성되는 것은 아닙니다. 별도 환경에서 복원한 뒤 주문·결제 참조와 합계를 검증하고 필요한 행만 가져오는 경우 운영의 이후 정상 변경과 대조합니다. 복구 데이터의 개인정보 접근권한과 임시 환경의 외부 통신도 제한합니다. 훈련은 파일 복원 완료 시점에서 끝내지 않고 앱이 필요한 스키마·키·설정으로 읽고 쓰는지까지 확인합니다. 이 절차의 시간을 실제 RTO에 포함하겠습니다.

백업 파일 존재뿐 아니라 로그 연속성·암호화 키·스키마·복구 시간과 실제 데이터 검증을 정기 시험합니다. RPO와 RTO는 설정 간격이 아니라 복구한 최신 유효 변경과 서비스 재개 시점으로 측정합니다. 복제본이 같은 삭제를 따라갔다면 독립 백업을 대신하지 못합니다.

## 득점 포인트

- 핵심 구분: 특정 시점 복구는 기준 백업과 그 이후 연속된 변경 로그를 이용해 원하는 지점까지 재생하는 방식입니다.
- 선택 조건: 복원 DB가 옛 outbox나 미처리 메시지를 포함하면 소비자가 실제 결제·메일을 다시 실행할 수 있습니다.
- 검증 기준: 백업 파일 존재뿐 아니라 로그 연속성·암호화 키·스키마·복구 시간과 실제 데이터 검증을 정기 시험합니다.

## 감점 포인트

- 전체 백업 파일 하나만 있으면 그 이후 모든 시점으로 복원할 수 있다고 한다.
