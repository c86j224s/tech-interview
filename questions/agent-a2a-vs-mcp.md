# 사내 도구를 연결하는 MCP가 있는데 원격 전문 에이전트와는 왜 A2A 같은 별도 계약을 검토하나요?

## 구두 답변

MCP는 주로 도구와 자료를 AI 애플리케이션에 제공하는 연결 계약이고, A2A는 독립적인 원격 에이전트에게 목표와 메시지를 전달하고 작업 상태·산출물을 주고받는 상호운용 계약입니다. 둘은 경쟁하는 만능 대체재라기보다 경계가 다릅니다. 원격 에이전트가 내부적으로 어떤 모델이나 MCP 도구를 쓰는지 공개하지 않아도 작업을 맡길 수 있습니다.

### 함수 호출과 목표 위임

주문 ID로 주문을 조회하는 기능은 입력과 결과가 비교적 명확한 도구 호출에 가깝습니다. '이 기간의 비용 이상을 조사해 근거 보고서를 만들어 달라'는 요청은 원격 담당자가 여러 단계를 선택하고 중간 입력을 요구할 수 있습니다. 이 경우 단일 반환값 외에 작업 ID, 진행 상태, 산출물, 실패·거절·추가 입력의 의미가 필요합니다. 다만 복잡한 일을 한다는 이유만으로 항상 A2A가 필요한 것은 아니며 단순 서비스 API가 충분할 수도 있습니다.

2026년 9월 11일 확인한 A2A 명세는 1.0.0을 최신 발행 버전으로 안내하며 Agent Card, 작업 수명, 메시지와 artifact, 스트리밍·조회 등을 설명합니다. Agent Card의 skill은 원격 에이전트가 제공한다고 설명한 능력이며, 파일 기반 Agent Skills의 SKILL.md와 같은 개념으로 혼동하지 않습니다. 명세 버전과 실제 서버 지원을 확인하고 선택 기능은 광고된 범위에서만 사용하겠습니다.

### 상호운용성과 신뢰는 별개입니다

프로토콜이 맞아도 원격 에이전트가 사실을 틀리게 보고하거나 과도한 자료를 요구할 수 있습니다. 사용자 목표·허용 데이터·비용·행동 범위를 좁혀 전달하고 반환 결과를 검증합니다. 상대가 작업을 완료했다고 표시하면 수명상 종료된 것이지만, 산출물이 원래 요구를 충족하는지는 별도 승인 기준입니다. 인증된 상대라는 사실이 모든 답변을 참으로 만들지는 않습니다.

MCP 도구로 A2A 원격 에이전트를 감싼 어댑터도 가능하지만 두 계층의 요청 ID·작업 ID·취소·오류를 잃지 않아야 합니다. 연결이 끊겼을 때 원격 작업이 계속되는지와 재접수 중복을 검사합니다. 도입 효과는 에이전트 수가 아니라 서로 다른 구현 사이의 작업 위임·복구·인가가 명확해지는지로 판단하겠습니다. 공통 프로토콜은 통합 비용을 줄이는 출발점이며 조직 간 책임과 데이터 공개 정책을 대신하지 않습니다.

### 실행 사례로 확인합니다

같은 '보고서 작성' 기능도 서버가 고정된 템플릿에 데이터를 채워 반환하면 보통의 도구로 충분할 수 있습니다. 원격 담당자가 범위를 협의하고 자료 부족을 질문하며 여러 산출물을 장기간 만드는 경우에는 task 중심 계약의 가치가 커집니다. 프로토콜 선택은 내부에 LLM이 있는지가 아니라 클라이언트가 관찰해야 할 수명과 상호작용에 달려 있습니다. 하나의 시스템에서 MCP로 사내 자료를 읽고 A2A로 외부 전문 분석을 맡길 수도 있지만, 그 경계에서 필요한 데이터만 전달하고 원래 작업과 원격 task를 연결합니다. 두 프로토콜이 있다고 재위임·취소·결과 검증이 자동으로 통합되는 것은 아닙니다.

## 득점 포인트

- 도구·자료 연결과 독립 원격 에이전트의 목표 위임을 구분한다.
- Agent Card·작업 상태·산출물과 실제 검증 책임을 설명한다.
- 중첩 어댑터에서도 식별자·취소·인가 경계를 보존한다.

## 감점 포인트

- A2A가 MCP를 모든 용도에서 대체한다고 한다.
- Agent Card의 skill과 SKILL.md 패키지를 동일 규약으로 본다.
- 프로토콜 완료 상태를 산출물 정확성의 증명으로 취급한다.
