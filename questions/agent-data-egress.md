# 에이전트가 읽을 수 있는 사내 자료를 외부 모델이나 도구에 보내려 합니다. 읽기 권한과 외부 전송 권한은 어떻게 다루나요?

## 구두 답변

사내 자료를 읽을 수 있다는 사실은 그 내용을 임의의 외부 서비스로 전송할 수 있다는 뜻이 아닙니다. 데이터 분류·사용 목적·목적지·사용자 동의와 조직 정책을 기준으로 별도의 전송 결정을 해야 합니다. 모델이 도구를 선택하더라도 실행 계층에서 나갈 데이터와 목적지를 검사하겠습니다. 외부 전송은 나중에 삭제해도 복사·로그·캐시에 남을 수 있습니다.

### 전송 경로를 모두 셉니다

직접 업로드뿐 아니라 검색어, URL 쿼리, 오류 보고, 원격 에이전트 메시지, 도구 인자도 데이터가 나가는 경로입니다. 모델에 비밀값을 넣은 뒤 '출력하지 말라'는 지시만으로 보호하지 않습니다. 자격 증명은 필요한 실행기에서만 사용하고, 민감 자료는 과제에 필요한 최소 필드로 줄이거나 허용된 내부 처리 경로를 선택합니다. 요약·임베딩도 원본의 정보를 담을 수 있어 무조건 익명이라고 보지 않습니다.

목적지 allowlist는 유용하지만 허용된 대형 서비스의 임의 사용자 공간으로 업로드할 수 있다면 충분하지 않을 수 있습니다. 도메인뿐 아니라 계정·조직·경로·행동·수신자를 검증합니다. URL을 도구가 대신 방문하는 경우 내부망 주소와 리다이렉트·DNS 변화를 검사해 SSRF와 내부 자료 전달을 제한합니다. 이런 정책은 모델이 제안한 URL을 신뢰하지 않는 계층에서 실행해야 합니다.

### 정책과 사용자 확인

외부 보고서 작성에 자료 전송이 필요하면 어떤 항목이 어디로 가고 무엇이 저장되는지 사용자에게 알리고 필요한 승인을 받습니다. 마스킹은 이름만 지우는 것으로 충분하지 않을 수 있으므로 재식별 가능한 조합과 로그도 확인합니다. DLP 탐지는 알려진 비밀 패턴을 찾는 보조 장치이며 모든 민감 의미를 완벽히 이해하지는 못합니다. 접근 제어·데이터 최소화·목적지 제한과 함께 사용합니다.

평가에서는 합성 민감 데이터가 검색어·도구 오류·메모리·첨부·하위 에이전트로 새는지 추적합니다. 차단된 호출의 근거는 남기되 검사 로그 자체에 원문 비밀을 복제하지 않습니다. 전송 허용 후에도 보존 기간·삭제·감사 요구를 서비스 계약과 맞춰야 합니다. 에이전트의 유용성을 높이기 위해 연결을 늘릴수록 가능한 데이터 이동 조합도 커지므로, 읽기 권한과 전송 권한을 끝까지 분리하는 것이 필요합니다.

### 실행 사례로 확인합니다

예를 들어 사내 문서 요약을 외부 번역 도구에 보낼 때 이름을 제거했어도 계약 금액·날짜·제품 조합으로 고객이 식별될 수 있습니다. 필요한 문장만 선택하고 내부 모델이나 승인된 제공자를 사용하는 대안을 비교합니다. 사용자가 자료를 업로드했다고 모든 연결 서비스로의 재전송을 승인한 것은 아니므로 목적지와 목적을 구분합니다. 전송 정책을 검사하는 계층이 실제 payload를 보고 있는지도 중요합니다. 모델이 생성한 코드가 직접 네트워크를 사용하면 정식 도구 인자 검사만으로 놓칠 수 있으므로 sandbox의 egress 통제와 함께 적용합니다. 로그·실패 보고·재시도 경로도 같은 정책을 통과해야 합니다.

## 득점 포인트

- 읽기와 외부 전송 권한·목적·보관 정책을 분리한다.
- 검색어·URL·로그·위임 등 간접 전송 경로도 검사한다.
- 목적지·데이터 최소화·DLP·사용자 승인을 계층적으로 적용한다.

## 감점 포인트

- 읽을 수 있는 자료는 어느 외부 도구에도 보낼 수 있다고 한다.
- 요약이나 임베딩은 항상 비민감 데이터라고 본다.
- 도메인 허용이나 DLP 하나로 모든 유출을 막는다고 한다.
