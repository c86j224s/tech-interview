# 서브뷰의 `frame`을 바꿨는데 예상 위치가 아니거나 회전 뒤 크기가 이상합니다. `frame`과 `bounds`를 어떤 좌표계에서 사용해야 하나요?

## 구두 답변

`frame`은 뷰의 사각형을 부모 뷰 좌표계에서 표현한 값입니다. 따라서 부모 안에서 어디에 놓이고 얼마나 차지하는지를 볼 때 유용합니다. `bounds`는 뷰 자신의 좌표계에서 그릴 영역을 나타내며, 일반적으로 원점이 `(0, 0)`이고 크기는 뷰의 내부 크기입니다. 자식 뷰를 배치하거나 그리는 코드는 부모의 좌표계와 자식의 내부 좌표계를 구분해야 하므로, 한 값을 다른 의미로 바꿔 읽으면 위치가 어긋납니다.

예를 들어 부모의 `bounds`가 `(0, 0, 300, 200)`이고 자식의 `frame`이 `(20, 30, 100, 40)`이면 자식은 부모 좌표에서 그 위치에 놓입니다. 자식의 `bounds.origin`을 `(10, 0)`으로 바꾸면 자식 내부 좌표의 기준이 이동하여 같은 자식 콘텐츠를 다른 위치에서 보게 됩니다. `UIScrollView`가 스크롤할 수 있는 이유도 콘텐츠 배치와 별개로 `bounds.origin`을 이동시키기 때문입니다. 즉 bounds의 원점이 항상 0이어야 한다고 가정하면 스크롤과 커스텀 뷰 구현을 망가뜨릴 수 있습니다.

변환(transform)이 없는 단순한 뷰에서는 frame으로 위치와 크기를 조정해도 직관적입니다. 그러나 UIView에 항등이 아닌 transform이 있으면 UIKit 문서상 frame은 정의되지 않은 값으로 취급하므로 읽거나 수정하는 근거로 사용하지 않아야 합니다. 화면에 보이는 모양의 경계 상자가 필요하면 좌표 변환을 이용해 별도로 구해야 합니다. 이때는 `center`, `bounds`, `transform`을 각각 조정하고, 필요한 좌표 변환은 `convert(_:to:)`나 `convert(_:from:)`으로 명시합니다.

오토레이아웃을 사용하는 화면에서는 매번 frame을 수동 수정하기보다 제약 조건을 바꾸고 레이아웃 패스 뒤의 frame을 관찰하는 편이 맞습니다. 애니메이션 중에는 presentation layer의 화면 위치와 모델 뷰의 frame이 다를 수도 있습니다. 따라서 문제를 고칠 때는 먼저 어느 좌표계의 값인지, transform과 오토레이아웃이 개입했는지, bounds origin이 이동했는지를 확인한 뒤 조정 대상을 선택해야 합니다.

## 득점 포인트

- frame은 부모 좌표계, bounds는 자기 좌표계의 그리기 영역이라는 구분을 예로 설명한다.
- UIScrollView처럼 bounds.origin이 이동할 수 있고 원점이 항상 0이 아니라는 조건을 안다.
- transform이 있으면 frame 대신 center·bounds·transform과 명시적 좌표 변환을 사용한다.

## 감점 포인트

- frame과 bounds가 같은 좌표계의 단순한 위치·크기 값이라고 설명한다.
- 모든 UIView의 bounds.origin이 영원히 `(0, 0)`이라고 단정한다.
- 오토레이아웃이 관리하는 frame을 수동으로 계속 덮어써 제약 조건과 싸운다.

## 더 파고들 거리

- 회전된 뷰의 표시 영역이 필요할 때 frame에 의존하지 않고 bounds의 좌표를 어떻게 변환할까요?
- 중첩된 뷰 사이에서 `convert`를 사용해 화면 좌표와 로컬 좌표를 오가는 예를 만들어 보세요.
- 오토레이아웃 레이아웃 패스 전후와 애니메이션 presentation layer의 값을 어떻게 측정할지 검증해 보세요.
