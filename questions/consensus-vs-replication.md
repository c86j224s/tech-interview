# 같은 데이터를 여러 서버에 복제했는데 장애 후 두 서버가 자신을 리더라고 주장합니다. 복제만으로 해결되지 않는 문제는 무엇이며 합의가 필요한 부분은 어디인가요?

## 구두 답변

복제는 여러 곳에 데이터를 보관하는 것이고, 합의는 장애와 메시지 지연 속에서도 어떤 값을 결정할지 참여자들이 일치시키는 문제입니다. 데이터를 복사해 두었다고 동시에 생긴 서로 다른 변경 중 무엇이 정답인지 자동으로 정해지는 것은 아닙니다.

리더 하나가 변경을 복제하는 시스템이라면 리더가 죽은 뒤 누가 다음 리더가 되고 어떤 기록을 이어받을지가 중요합니다. 두 노드가 자신이 리더라고 생각해 서로 다른 변경을 성공시킬 수 있다면 복제본은 많아도 안전하지 않습니다. Raft나 Paxos 같은 합의는 정해진 장애 모델 안에서 이미 결정된 값이 뒤집히지 않도록 규칙을 제공합니다.

저는 먼저 필요한 결정의 범위와 장애 가정을 확인하겠습니다. 일반적인 Raft는 악의적으로 거짓말하는 노드를 견디는 비잔틴 합의가 아니라 중단·복구·통신 장애를 다룹니다. 합의가 있더라도 애플리케이션의 중복 요청과 외부 부수 효과는 별도입니다. 테스트도 복사본 수만 확인하지 않고 리더 장애 후 이미 성공한 변경이 보존되는지 보겠습니다.

## 득점 포인트

- 복제와 결정의 역할을 구분한다.
- 리더 교체에서 안전성을 설명한다.
- 장애 모델과 명령 재처리의 멱등성을 분리한다.

## 감점 포인트

- 복제본이 많으면 자동 합의라고 말한다.
- Raft가 악의적인 노드도 무조건 견딘다고 말한다.
- 합의만으로 외부 작업 중복까지 없어진다고 말한다.
