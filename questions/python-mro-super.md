# Python 다중 상속에서 super()를 호출했더니 예상한 부모와 다른 클래스의 메서드가 실행됩니다. 호출 순서는 어떻게 정해지며 협력적으로 초기화하려면 무엇을 맞춰야 하나요?

## 구두 답변

다중 상속에서 메서드 탐색 순서는 클래스의 MRO(Method Resolution Order)에 저장되며, Python 3에서는 C3 선형화 규칙으로 계산됩니다. C3는 자식 클래스가 부모보다 먼저 나오고, 각 부모 목록의 순서를 보존하며, 같은 클래스를 중복 방문하지 않는 일관된 순서를 만들려고 합니다. 그래서 단순히 왼쪽 부모 트리를 끝까지 훑는 방식이 아니며, 모순된 상속 그래프는 클래스 정의 시 `TypeError`가 됩니다.

```python
class A:
    def f(self): print("A")
class B(A):
    def f(self): print("B"); super().f()
class C(A):
    def f(self): print("C"); super().f()
class D(B, C):
    pass

print([cls.__name__ for cls in D.__mro__])
D().f()
```

출력은 `['D', 'B', 'C', 'A', 'object']`와 `B`, `C`, `A`입니다. 여기서 `super()`는 “내 부모 A”가 아니라 실제 객체 타입의 MRO에서 현재 메서드를 정의한 클래스 뒤를 따라 다음 메서드 구현을 찾습니다. 따라서 B가 `super().f()`를 호출하면 C로 이어지고, 각 클래스가 협력적으로 `super()`를 호출해야 다이아몬드 구조의 모든 구현이 한 번씩 실행됩니다.

실무에서는 다중 상속을 쓰더라도 모든 참여 클래스의 메서드 시그니처와 `super()` 호출 규칙을 맞추겠습니다. 한 클래스가 부모 메서드를 이름으로 직접 호출하면 다음 MRO를 건너뛰어 중복 실행이나 일부 초기화 누락이 생길 수 있습니다. 반대로 서로 협력하지 않는 외부 클래스들을 억지로 섞기보다 합성으로 경계를 나누는 편이 예측 가능할 때가 많습니다.

## 득점 포인트

- `D.__mro__`의 순서와 C3가 부모 순서·단조성·중복 방지를 함께 만족시키는 목적을 설명한다.
- `super()`를 직접 부모 호출이 아니라 MRO의 다음 구현을 찾는 위임으로 설명한다.
- 다이아몬드 상속에서 각 클래스가 협력적으로 `super()`를 호출해야 한다는 조건을 든다.

## 감점 포인트

- `super()`가 언제나 바로 왼쪽 부모만 호출한다고 말한다.
- MRO가 메서드 정의를 복사해 하나로 합친다고 설명한다.
- 한 클래스만 `super()`를 호출해도 모든 부모가 자동으로 실행된다고 단정한다.
