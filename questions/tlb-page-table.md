# 큰 메모리 영역을 불규칙하게 읽는 프로그램에서 TLB miss가 늘었습니다. TLB는 주소 변환 비용을 어떻게 줄이며 miss와 페이지 폴트는 어떻게 다른가요?

## 구두 답변

TLB는 최근 사용한 가상 페이지와 물리 프레임의 변환 정보를 캐시합니다. 적중하면 페이지 테이블을 여러 단계 따라가는 비용을 줄일 수 있습니다. 데이터 캐시가 원소의 내용을 보관하는 것과 주소 변환 캐시는 목적이 다릅니다.

TLB에 없다는 것은 변환 정보를 다시 찾아야 한다는 뜻이지 데이터 페이지가 디스크에 있다는 뜻은 아닙니다. 페이지 테이블에 유효한 매핑이 있다면 테이블 탐색으로 해결할 수 있습니다. 페이지 폴트는 매핑이나 권한 상태 때문에 운영체제 처리가 필요한 별도의 사건입니다.

넓은 메모리를 불규칙하게 접근하면 데이터 캐시뿐 아니라 TLB의 범위도 넘을 수 있습니다. 큰 페이지는 한 항목으로 더 넓은 범위를 덮지만 내부 낭비와 할당·압축 비용이 생길 수 있습니다. 저는 실제 접근 패턴에서 TLB 미스와 페이지 폴트, 캐시 미스를 나눠 측정하겠습니다. 프로세스 전환 때의 주소 공간 태그 지원도 영향을 주므로 모든 전환이 항상 전체 TLB를 지운다고 단정하지 않겠습니다.

## 득점 포인트

- 변환 캐시와 데이터 캐시를 구분한다.
- TLB 미스와 페이지 폴트를 나눈다.
- 큰 페이지와 주소 공간 전환의 조건을 확인한다.

## 감점 포인트

- TLB 미스면 반드시 디스크 I/O라고 말한다.
- 큰 페이지에는 비용이 없다고 말한다.
- 모든 하드웨어에서 전환 시 전체 변환 캐시가 비워진다고 말한다.

## 더 파고들 거리

- ASID나 PCID는 주소 공간의 변환을 어떻게 구분하나요?
- 페이지 테이블을 바꿀 때 다른 코어의 오래된 TLB는 어떻게 처리하나요?
- 연속 배열과 포인터 추적의 TLB 사용은 어떻게 다를까요?
