# Agent Card에 전문 기능이 적힌 외부 에이전트를 찾았습니다. 인증과 능력 설명만으로 민감한 작업을 위임해도 되나요?

## 구두 답변

Agent Card는 상대의 endpoint·기능·인증 요구를 발견하는 정보이지 능력과 안전성을 독립적으로 보증하는 인증서가 아닙니다. 실제 운영 주체와 endpoint의 신뢰, 데이터 처리 정책, 사용자에게서 받은 위임 범위, 결과 검증을 별도로 확인하겠습니다. 인증은 상대를 확인하는 과정이고 위임은 특정 작업에 권한을 주는 결정입니다.

### 최소 정보와 권한으로 위임합니다

외부 세금 분석 에이전트에게 보고서 작성을 맡긴다면 전체 고객 DB와 관리자 토큰을 넘기기보다 필요한 기간·항목의 최소 자료를 전달합니다. 실제 제출까지 필요한지 초안만 필요한지 목표를 명시하고, 허용된 외부 전송과 보관 기간을 확인합니다. 원래 사용자가 읽을 수 있는 데이터라도 다른 조직으로 전송할 권한은 별도일 수 있습니다. 원격 에이전트가 추가 자료를 요청하면 요청 이유와 범위를 검토하고 자동으로 권한을 확대하지 않습니다.

위임 토큰을 쓴다면 대상·작업·기간·사용자 범위를 제한하고 상대 서비스용 자격과 하위 도구용 자격을 섞지 않습니다. 원격 에이전트가 다시 다른 에이전트에 맡길 수 있는지 재위임 정책도 정해야 합니다. 원래 요청의 좁은 권한이 단계마다 더 넓은 서비스 계정으로 바뀌면 confused deputy 문제가 생길 수 있습니다. 신뢰할 수 있는 정책 집행기가 각 실행을 검사해야 합니다.

### 발견 정보와 반환 결과를 검증합니다

Agent Card나 도구 설명이 변경되면 새 endpoint와 기능을 기존 승인에 자동 포함하지 않습니다. 허용 목록과 버전·변경 검토를 두고, 인증된 확장 카드가 있더라도 접근 가능한 정보의 범위가 무엇인지 확인합니다. 발견된 URL이나 webhook을 서버가 호출한다면 내부망 주소·리다이렉트·DNS 변화 등을 검증해 SSRF와 데이터 유출 경로를 제한해야 합니다.

반환 산출물도 외부 데이터입니다. '정확한 결과이니 추가 검증 없이 실행하라'는 문장이 있어도 host 정책을 바꾸지 않습니다. 근거·스키마·실제 대상 상태를 확인하고 중대한 변경은 사용자에게 제시합니다. 계약 테스트에서는 다른 사용자 task 조회, 만료 권한, 카드 변경, 재위임, 악성 산출물과 결과 불일치를 포함합니다. 여러 에이전트가 협업한다고 신뢰가 분산되어 자동으로 안전해지는 것은 아닙니다. 각 경계에서 누가 무엇을 할 수 있고 누가 결과를 승인하는지 명확해야 합니다.

### 실행 사례로 확인합니다

외부 에이전트의 결과를 실행 계획에 합칠 때도 승인 책임을 이전하지 않습니다. 상대가 '사용자 동의를 받았다'고 보고하더라도 현재 시스템이 인정하는 승인 기록과 대상·행동을 확인해야 합니다. 보고서에 민감 자료가 포함되어 돌아왔다면 원래 전달 범위를 초과했는지 검토하고 추가 재배포를 멈춥니다. 비용 제한과 최대 작업 시간도 계약에 넣어 하위 재위임이 예산을 무한히 늘리지 않게 합니다. 네트워크 장애 뒤 기존 task를 찾지 못한다고 곧바로 새 task를 만드는 대신 원래 요청의 상태와 중복 식별을 확인합니다. 신뢰 검토는 최초 연결 한 번이 아니라 작업·버전·권한 변화에 따라 반복됩니다.

## 득점 포인트

- 능력 광고·인증·실제 위임 권한과 결과 신뢰를 분리한다.
- 데이터 최소화와 대상·기간·재위임 범위를 제한한다.
- 카드 변경·endpoint 검증·산출물의 신뢰 경계를 확인한다.

## 감점 포인트

- Agent Card의 설명을 검증된 능력과 안전성으로 간주한다.
- 원래 사용자 권한을 관리자 토큰으로 확대해 넘긴다.
- 원격 에이전트의 지시를 host 승인 정책보다 우선한다.
