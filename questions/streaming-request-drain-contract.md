# 장기 스트림과 짧은 요청을 같은 서버에서 처리합니다. 종료 기한과 재개 위치를 어떻게 다르게 정하나요?

짧은 요청은 남은 시간 안 완료시키고 장기 스트림은 재개 가능한 위치·부분 결과·최대 drain 시간을 계약으로 둡니다. 기존 연결을 다른 서버로 순간 이동시킬 수 있다고 가정하지 않습니다.

readiness·새 수락을 막은 뒤 스트림별 상태를 기록하고 기한을 넘기면 명시적인 종료·재접속 안내를 줍니다. 이미 전송한 데이터와 외부 변경은 취소되지 않을 수 있습니다. 같은 요청 ID·커서로 중복·누락을 복구하는지 시험합니다.
