# Paxos로 명령 로그를 계속 기록하려고 합니다. Multi-Paxos는 반복 비용을 어떻게 줄이며 리더가 바뀌면 무엇을 이어받나요?

## 구두 답변

단일 Paxos는 하나의 슬롯에서 하나의 값을 안전하게 선택하는 문제입니다. 복제 로그를 만들려면 명령마다 슬롯을 두고 같은 합의 절차를 반복해야 합니다. Multi-Paxos는 안정적인 리더가 자신의 ballot(제안 번호)에 대해 한 번 prepare 약속을 확보한 뒤, 그 약속이 유효한 동안 여러 슬롯의 accept(값을 수락하는 단계)를 진행해 매 슬롯마다 prepare를 반복하는 비용을 줄이는 운영 형태입니다. 각 슬롯은 여전히 하나의 값만 결정합니다.

리더가 바뀌면 새 리더는 과거 슬롯의 acceptor 응답을 수집해 이미 선택됐거나 높은 ballot에서 수락된 값을 보존해야 합니다. 빈 슬롯을 임의의 새 명령으로 덮거나 최신 슬롯부터 적용하면 로그 상태 머신의 순서와 안전성이 깨집니다. 결정된 슬롯은 그대로 이어받고, 비어 있는 구간은 no-op 등 프로토콜 규칙으로 채워 적용 순서를 유지할 수 있습니다.

안정 리더는 진행과 처리량을 돕지만 합의 규칙을 대신하지 않습니다. 여러 슬롯을 묶거나 겹쳐 처리하면 슬롯별 합의가 끝나는 순서는 달라질 수 있습니다. 그러나 상태 머신에는 앞선 슬롯의 결정을 확보한 뒤 로그 순서대로 적용해야 합니다. 리더 충돌, 지연된 accept, 빈 슬롯, 중복 client 명령을 재현해 안전성(서로 다른 값 결정 없음)과 진행성(언젠가 결정)을 별도로 확인하겠습니다.

## 득점 포인트

- 단일 값과 여러 로그 슬롯의 관계를 설명한다.
- 안정 리더가 prepare 왕복을 줄이는 조건을 명시한다.
- 리더 변경 시 과거 accept와 빈 슬롯 복구를 강조한다.

## 감점 포인트

- Multi-Paxos가 한 슬롯에 여러 값을 결정한다고 말한다.
- 새 리더가 과거 수락 기록을 버리고 최신 번호부터 시작한다고 말한다.
- 리더 선출만 있으면 Paxos 안전성 규칙이 필요 없다고 말한다.

## 더 파고들 거리

- pipeline 슬롯이 역순으로 선택돼도 적용 순서를 어떻게 유지할까요?
- Raft와 Multi-Paxos의 리더 변경·로그 복구 규칙은 어떤 점에서 다른가요?
