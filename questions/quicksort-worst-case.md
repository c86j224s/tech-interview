# 퀵 정렬로 무작위 데이터는 빠르게 처리했지만 정렬된 입력에서는 급격히 느려집니다. 피벗과 분할이 어떤 영향을 주며 최악의 경우를 어떻게 줄이나요?

## 구두 답변

퀵 정렬은 피벗을 기준으로 원소를 나누고 각 구간을 다시 정렬합니다. 분할이 균형적이면 단계마다 문제 크기가 줄지만, 매번 한쪽에 거의 모든 원소가 남으면 비교가 반복돼 최악 비용이 제곱 수준으로 커질 수 있습니다.

첫 원소를 피벗으로 고르는 단순 구현에 이미 정렬된 입력을 주면 이런 불균형이 생길 수 있습니다. 피벗을 무작위로 고르거나 여러 후보에서 선택하면 특정 입력의 영향을 줄일 수 있지만 모든 구현의 최악 보장이 자동으로 바뀌는 것은 아닙니다. 같은 값이 많은 입력은 세 구간으로 나누는 방식이 도움이 될 수 있습니다.

저는 직접 정렬을 구현하기보다 표준 라이브러리의 보장을 확인하고, 필요하면 깊이가 커질 때 다른 알고리즘으로 전환하는 introsort 같은 전략을 비교하겠습니다. 재귀 깊이도 스택 안전성과 연결됩니다. 테스트는 정렬·역정렬·동일 값·무작위 입력을 포함해 시간과 비교 횟수를 봅니다. 평균 성능이라는 설명에 입력 분포와 피벗 정책을 함께 붙여야 합니다.

## 득점 포인트

- 분할 불균형으로 최악 비용을 설명한다.
- 피벗·중복값 처리·깊이 제어를 구분한다.
- 편향된 입력을 테스트한다.

## 감점 포인트

- 퀵 정렬은 항상 O(n log n)이라고 말한다.
- 무작위 피벗이면 절대 최악이 없다고 말한다.
- 중복 값과 재귀 깊이를 무시한다.
