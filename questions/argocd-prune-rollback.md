# Argo CD의 prune과 Git revert를 사용할 때 무엇을 주의하나요?

## 구두 답변

prune은 원하는 선언에서 사라진 리소스를 실제 클러스터에서도 제거하는 동작입니다. 코드 정리처럼 보여도 저장소나 외부 자원과 연결된 객체를 지우면 데이터와 서비스에 영향을 줄 수 있습니다. Git revert 역시 선언을 되돌리는 것이지 이미 발생한 외부 효과를 모두 복원하는 것은 아닙니다.

리소스 이름을 변경했을 때 생성과 삭제 순서, 소유권이 어떻게 해석되는지 확인하겠습니다. Namespace나 PVC처럼 영향 범위가 큰 객체는 자동 삭제 정책과 보호 장치를 명확히 해야 합니다. 리소스를 남기도록 설정하면 안전할 수 있지만 오래된 객체가 계속 남아 비용이나 보안 문제가 생길 수 있어 정리 책임이 필요합니다.

롤백 전에 이전 앱이 현재 데이터와 호환되는지 확인하고, 비밀키 회수처럼 되돌리면 안 되는 변경도 구분하겠습니다. 저는 예상 diff를 검토하고 작은 집단에서 적용한 뒤 실제 Health와 사용자 오류를 확인합니다. 테스트는 리소스 제거와 이름 변경, 데이터 스키마 변화 뒤 revert를 포함합니다. 되돌릴 수 있다는 인상보다 어떤 상태는 자동 복원되지 않는지 아는 것이 중요합니다.

## 득점 포인트

- 선언 삭제와 실제 자원 영향을 연결한다.
- revert와 데이터 복구를 분리한다.
- 보호·잔존 자원의 책임을 정한다.

## 감점 포인트

- Git을 되돌리면 모든 데이터도 복원된다고 말한다.
- 모든 리소스에 자동 prune을 무검토 적용한다.
- 삭제 방지만 하면 운영 비용이 없다고 말한다.

## 더 파고들 거리

- 긴급 롤백 중 자동 동기화가 다시 최신 버전을 적용하지 않게 하려면 어떻게 할까요?
