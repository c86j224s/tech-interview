# 비밀번호 재설정 링크를 발급합니다. 토큰을 길게 무작위로 만들면 어떤 조건이 더 필요한가요?

## 구두 답변

예측 불가능성 외에 대상 사용자·용도·짧은 수명·단일 사용·안전한 전달과 로그 비노출이 필요합니다. 토큰 소유가 계정 변경 권한으로 이어지므로 발급·소비·재사용의 상태를 설계해야 합니다.

### 동작 원리와 전제

서버에는 토큰 원문 대신 해시를 저장하고 소비 시 만료와 미사용 조건을 원자적으로 바꿉니다. 두 요청이 동시에 같은 토큰을 쓰면 한 번만 성공해야 합니다. 재발급 때 이전 토큰을 모두 무효화할지 정책을 정합니다.

### 선택과 실패 처리

링크는 신뢰된 origin으로 만들고 URL 토큰이 Referer·분석 로그·외부 자산으로 새지 않게 합니다. 존재하지 않는 계정에 대한 응답과 타이밍에서 계정 열거를 줄입니다. 성공 후 기존 세션·갱신 토큰의 처리와 사용자 알림을 정합니다.

### 구체적인 사례와 검증

토큰의 사용 여부를 먼저 조회하고 나중에 삭제하는 두 단계는 동시 요청이 모두 통과할 수 있습니다. 미사용·미만료 조건과 계정 변경을 같은 transaction이나 원자 상태 전이로 묶습니다. 비밀번호 변경 성공 뒤 토큰만 남으면 재사용 경로가 생길 수 있으므로 실패 순서를 시험합니다. 재설정 링크가 외부 이미지·분석 스크립트를 포함한 페이지로 이어지면 URL이 로그나 Referer에 남는지 확인합니다. 사용자에게는 토큰 원문을 진단 로그로 보내라고 요구하지 않고 추적 ID로 문제를 조사합니다. 기본 인증이 강하더라도 이 복구 경로가 더 약하면 계정 보안이 그 수준으로 낮아질 수 있습니다.

동시 소비·만료 직전·재발급·잘못된 host·링크 재생·지원센터 복구를 시험합니다. 긴 토큰은 약한 이메일 계정이나 피싱 경로까지 보호하지 않으므로 위험에 맞는 재인증과 복구 정책을 함께 봅니다.

## 득점 포인트

- 핵심 구분: 예측 불가능성 외에 대상 사용자·용도·짧은 수명·단일 사용·안전한 전달과 로그 비노출이 필요합니다.
- 선택 조건: 링크는 신뢰된 origin으로 만들고 URL 토큰이 Referer·분석 로그·외부 자산으로 새지 않게 합니다.
- 검증 기준: 동시 소비·만료 직전·재발급·잘못된 host·링크 재생·지원센터 복구를 시험합니다.

## 감점 포인트

- 무작위 토큰이면 단일 사용·만료·동시 소비 검사는 필요 없다고 한다.
