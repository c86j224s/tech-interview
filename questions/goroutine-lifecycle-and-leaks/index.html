01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

요청마다 고루틴을 만드는 것 자체는 자연스러운 패턴입니다. 다만 가볍다는 것이 끝없이 만들어도 된다는 뜻은 아닙니다. 런타임이 많은 고루틴을 여러 OS 스레드에 나눠 실행해 주더라도, 끝나지 않은 작업이 잡고 있는 메모리와 연결까지 없애 주지는 않기 때문입니다.

고루틴은 Go 런타임이 관리하는 실행 흐름입니다. 잠든 고루틴도 스택과 참조 중인 데이터를 유지할 수 있어 CPU를 거의 쓰지 않는다고 비용이 없는 것은 아닙니다. 요청이 완료되면 줄어드는 대기와, 받을 사람이 없는 채널에 영원히 보내려는 대기를 나눠 보는 것이 핵심입니다.

예를 들어 외부 API를 호출하는 고루틴을 요청마다 만든다고 하겠습니다. 외부 응답이 느려지면 기존 작업이 끝나기 전에 새 작업이 들어와 고루틴 수가 쌓입니다. 같은 요청량에서 처리 시간이 길어지면 진행 중인 작업도 그만큼 늘어나는 것입니다. 이때 CPU는 낮아도 응답 버퍼와 연결 풀은 부족해질 수 있습니다. 저는 고루틴 수가 늘었다는 이유만으로 누수라고 단정하지 않고, 외부 대기 시간과 요청 종료 후 감소 여부를 함께 보겠습니다.

실제 누수는 종료할 수 없는 대기에서 생기기도 합니다. 요청이 취소돼 결과를 받을 사람이 없어졌는데, 작업 고루틴이 채널로 결과를 보내려다 계속 멈춰 있는 경우입니다. 이 고루틴은 일을 하지 않더라도 참조 중인 데이터를 유지합니다. context 취소를 전달하는 것만으로 자동 종료되지는 않으므로, 채널 대기에서도 취소를 확인하고 빠져나오게 해야 합니다. 부모 작업은 취소를 알린 뒤 자식들이 실제로 종료됐는지도 확인해야 합니다.

외부 API 지연으로 쌓이는 문제라면 동시에 호출할 작업 수부터 제한하겠습니다. 다만 고루틴을 먼저 만든 뒤 세마포어에서 기다리게 하면 대기 고루틴은 계속 늘 수 있습니다. 저는 가능하면 작업을 만들기 전에 실행 허가를 받고, 기다리는 요청 수에도 상한을 두겠습니다. 상한에 도달하면 무조건 더 받기보다 제한된 시간만 기다리거나 재시도 가능한 실패를 돌려주는 정책을 정하겠습니다.

원인을 찾을 때는 pprof의 고루틴 덤프에서 어떤 호출 위치에 대기가 몰렸는지 보겠습니다. 부하를 끈 뒤에도 같은 채널 전송에서 작업이 남으면 종료 경로를 의심하고, 외부 요청이 끝나며 정상 감소한다면 과도한 동시성이 문제인지 보겠습니다. 고루틴 개수 하나보다 어디서 기다리며 언제 끝나야 하는지를 기준으로 판단하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 정상 적체와 누수를 구분한다. 하위 응답 지연 및 부하 종료 뒤 감소 여부로 서로 다른 원인을 판단한다.
  • 취소 가능한 종료 경로를 설명한다. 채널 대기에서도 취소를 확인하고 실제 자식 작업 종료까지 책임진다.
  • 생성 전후의 제한 효과를 구분한다. 고루틴 내부 세마포어만으로 대기 작업 수가 제한되지 않음을 짚는다.
  • 프로파일에서 행동으로 이어 간다. 대기 스택과 자원 회복을 보고 종료 경로 수정과 진입 제어 중 무엇이 필요한지 정한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • “고루틴이 많으면 무조건 누수다”라고 말한다. 부하와 정상적인 대기 증가일 수 있어 수명과 회복 여부를 봐야 한다.
  • “context를 취소하면 하위 고루틴이 강제 종료된다”고 말한다. 작업이 취소 신호를 확인하고 반환해야 한다.
  • “GC가 사용하지 않는 고루틴을 회수한다”고 말한다. 블로킹된 실행 흐름과 그 참조는 종료 경로 없이 남을 수 있다.
  • “작업자 수를 제한했으니 메모리는 안전하다”고 말한다. 대기열과 대기 고루틴도 자원을 보유한다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • G·M·P와 GOMAXPROCS는 각각 무엇이며, OS 스레드 수의 상한과 왜 다른가요?
  • goroutine·block·mutex 프로파일은 현재 대기와 누적 대기를 관찰하는 데 어떤 차이가 있나요?
  • 서버 종료 시 새 요청 차단, 취소 전파, 자식 작업 대기와 강제 종료 기한을 어떻게 정할까요?
  • 요청이 끝나도 반드시 완료해야 하는 작업은 요청 고루틴과 어떻게 분리해 관리해야 할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
