01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

RDB는 특정 시점의 메모리 상태를 파일로 저장하는 스냅샷이고, AOF는 쓰기 명령을 기록해 재시작 때 재생하는 방식입니다. 따라서 RDB는 마지막 스냅샷 이후 변경을 잃을 수 있고, AOF의 유실 범위는 명령이 디스크에 얼마나 자주 fsync됐는지에 따라 달라집니다. 어느 방식도 설정만 보고 무손실이라고 말할 수 없습니다.

RDB는 파일이 비교적 간결해 백업·복구가 단순하고 재생 비용이 예측 가능할 수 있지만, 스냅샷 사이의 쓰기를 복구하지 못합니다. AOF는 더 촘촘한 복구 지점을 제공할 수 있지만 로그가 커지고 rewrite가 필요합니다. rewrite는 누적 명령을 현재 상태에 가까운 짧은 기록으로 정리하는 과정이지, 장애 전후의 모든 쓰기 내구성을 자동으로 높이는 기능은 아닙니다. 실제 복구 우선순위와 파일 형식은 운영 버전과 설정에서 확인하겠습니다.

백그라운드 fork 기반 저장이나 rewrite 동안에는 추가 I/O와 copy-on-write 메모리 증가가 생길 수 있습니다. 정상 유휴 상태의 메모리만 보고 한도를 잡지 않고 쓰기 부하 중 피크를 측정하겠습니다. 복제본은 장애 대응에 도움이 되지만 논리 오류나 잘못 삭제한 데이터도 복제할 수 있으므로 독립 백업을 대체하지 않습니다.

검증은 파일이 만들어졌는지가 아니라 저장 직후 강제 중단 후 재시작해 허용한 유실 시간과 복구 목표를 만족하는지 확인하는 방식이어야 합니다. AOF 마지막 부분 손상, rewrite 중 중단, 저장 장치 오류도 복구 절차에 포함하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • RDB 스냅샷·AOF 명령 기록과 fsync 유실 범위를 구분한다.
  • rewrite·fork의 메모리와 I/O 피크를 설명한다.
  • 복제와 독립 백업, 실제 재시작 검증을 분리한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • AOF면 모든 설정에서 무손실이라고 말한다.
  • RDB 완료 시점에 이후 쓰기까지 포함된다고 말한다.
  • 복제본이 독립 백업을 완전히 대신한다고 말한다.
