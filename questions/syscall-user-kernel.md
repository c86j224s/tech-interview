# 파일을 읽는 시스템 호출이 일반 함수 호출보다 비싸다고 합니다. 사용자 모드에서 커널로 들어갈 때 무엇이 달라지며 항상 다른 스레드로 전환되나요?

## 구두 답변

일반 함수는 보통 같은 사용자 실행 환경 안에서 호출되지만, 시스템 호출은 파일·소켓 같은 보호된 자원 기능을 요청하기 위해 커널의 정해진 진입점을 사용합니다. 권한 수준과 실행 경로가 바뀌는 것과 다른 스레드로 CPU가 넘어가는 것은 같은 사건이 아닙니다.

캐시된 짧은 작업을 커널이 바로 끝내면 같은 스레드가 사용자 모드로 돌아올 수 있습니다. 반면 읽을 데이터가 없어 블로킹되면 스케줄러가 다른 실행 흐름을 선택할 수 있습니다. 그래서 시스템 호출 횟수와 컨텍스트 스위치 횟수가 일대일이라고 보지 않겠습니다.

작은 작업을 자주 요청하면 진입·복귀, 인자 검증과 복사 비용이 누적될 수 있어 배치나 버퍼링이 도움이 됩니다. 하지만 배치가 클수록 대기와 메모리 사용이 늘 수 있습니다. 저는 호출 빈도와 실제 블로킹 시간, 전송 바이트를 함께 측정하겠습니다. libc 함수 중 사용자 공간에서 끝나는 것도 있으므로 함수 이름만 보고 시스템 호출이라고 판단하지 않겠습니다.

## 득점 포인트

- 권한 전환과 스레드 전환을 구분한다.
- 즉시 완료와 블로킹 경로를 설명한다.
- 배치의 비용과 라이브러리 경계를 확인한다.

## 감점 포인트

- 시스템 호출마다 프로세스가 바뀐다고 말한다.
- 모든 표준 라이브러리 함수가 커널에 들어간다고 말한다.
- 호출 수 감소만으로 지연 개선을 확정한다.

- 비동기 I/O 배치가 시스템 호출과 완료 처리 비용을 어떻게 나누나요?
