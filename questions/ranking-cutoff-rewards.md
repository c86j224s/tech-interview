# 게임 랭킹 마감 뒤 늦게 도착한 점수와 보상 지급을 어떤 기준 버전으로 확정하고 재처리하나요?

## 구두 답변

먼저 마감의 권위 있는 기준을 정해야 합니다. 서버가 이벤트를 받은 시각을 기준으로 할지, 신뢰 가능한 게임 이벤트의 발생 시각을 기준으로 할지에 따라 늦은 점수의 처리 결과가 달라집니다. 여러 서버의 벽시계를 그대로 비교하면 경계가 흔들리므로 이벤트에 시즌·규칙 버전과 서버가 부여한 순서 또는 검증 가능한 발생 정보를 넣겠습니다.

발생 시각을 인정한다면 허용 지연 창을 정하고, 그 창이 끝난 뒤 집계 버전을 봉인합니다. 예를 들어 `season=7, cutoffVersion=184`를 보상 계산의 입력으로 고정하면 봉인 후 들어온 이벤트가 화면 순위를 바꾸더라도 이미 확정한 대상이 달라지지 않습니다. 늦은 이벤트를 폐기할지 다음 집계에 넣을지, 부정 판정 뒤 보상을 회수·추가 지급할지는 정정 이벤트로 감사 가능하게 남겨야 합니다.

기본 보상 지급은 `계정·시즌·보상종류`처럼 업무상 지급 권리를 식별하는 키로 멱등 처리하겠습니다. 확정 버전은 어떤 집계 결과를 근거로 지급했는지 기록하는 메타데이터로 남기되, 기본 지급의 중복 방지 키에 포함하지 않습니다. 작업자가 지급 성공 후 완료 표시 전에 죽을 수 있으므로, 지급 시스템이 제공하는 지급 권리 키나 지급 원장을 사용하고 재시작 때 같은 키를 재처리해도 한 번만 남는지 확인하겠습니다. 마감 뒤 정정이 필요하면 기존 지급을 새 확정 버전으로 다시 지급하지 않고, 별도의 조정 ID와 차액·회수 정책으로 기록하겠습니다. 실시간 순위는 잠정 표시일 수 있지만, 보상은 반드시 어떤 확정 버전에서 계산된 결과인지 재현 가능해야 합니다.

테스트에는 마감 직전·직후 이벤트, 허용 지연 경계, 동점, 집계 일부 실패, 지급 응답 유실, 부정 점수 정정을 넣습니다. 성공 기준은 화면의 일시적 순위가 아니라 같은 버전과 정책으로 재계산해도 대상과 지급 기록이 일치하는지입니다.

## 득점 포인트

- 마감 시각·이벤트 시각·권위 버전을 구분한다.
- 봉인된 집계 버전과 늦은 이벤트·정정 정책을 명시한다.
- 보상 고유 키와 지급 재시작의 중복 방지를 설명한다.

## 감점 포인트

- 서버별 현재 시각만으로 모든 경계를 결정한다.
- 지급 중인 실시간 랭킹을 계속 보상 기준으로 사용한다.
- 작업 재실행 때 이미 지급한 항목을 구분하지 않는다.
