# 복셀 원본이 바뀔 때 충돌·경로·시야 파생 데이터를 서로 다른 버전으로 사용하지 않게 갱신하는 방법은 무엇인가요?

## 구두 답변

복셀 원본을 새 버전으로 바꾸는 것과 그 원본에서 만든 충돌 인덱스·경로 그래프·시야 데이터가 모두 새 버전이 되는 것은 별개입니다. 파생 데이터가 서로 다른 지형 버전을 보면 새 벽을 통과하거나 없는 길을 선택할 수 있습니다. 각 변경에 원본 버전을 부여하고 파생 데이터에도 `sourceVersion`과 적용 상태를 기록하겠습니다.

영향 범위가 작은 변경이라면 해당 청크와 경계 이웃을 무효화하고 파생 데이터를 비동기로 재생성할 수 있습니다. 화면 메시지는 잠시 이전 버전을 사용해도 되지만, 서버 충돌은 새 벽을 즉시 막아야 할 수 있습니다. 그 경우 보수적인 임시 충돌층을 적용하거나 해당 영역 이동을 제한하고, 임시 정책의 최대 지속 시간을 둡니다.

재생성이 끝나면 부분 결과를 공유하지 않고 완성된 스냅샷을 원자적으로 교체합니다. 생성 중 원본이 다시 바뀌면 생성 작업이 시작할 때 읽은 버전과 현재 버전을 비교해 오래된 결과를 폐기하거나 최신 변경을 포함해 재생성합니다. 이전 버전을 읽는 요청이 남아 있을 수 있으므로 참조 수명이나 epoch를 사용해 교체 직후 메모리를 해제하지 않습니다.

검증은 연속 파괴·복원, 경계 이웃 변경, 생성 중 워커 중단, 오래된 결과 도착, 충돌·경로·시야의 동시 조회를 포함합니다. 생성 속도뿐 아니라 안전상 허용되지 않는 버전 조합이 사용자에게 노출되지 않는지를 확인하겠습니다.

## 득점 포인트

- 원본 버전과 파생 데이터의 적용 위치를 기록한다.
- 기능별 이전 버전 허용·보수적 임시 정책을 구분한다.
- 버전 검사와 원자적 교체·이전 참조 수명을 설명한다.

## 감점 포인트

- 원본 변경 즉시 모든 파생 데이터가 최신이라고 말한다.
- 부분 생성 결과를 바로 서비스한다.
- 늦게 끝난 생성 작업의 버전 검사를 생략한다.

## 더 파고들 거리

- 원본·파생 버전 차이를 어떤 지표와 경보로 관찰하나요?
- 계속 변경되는 영역의 재생성 작업을 어떻게 병합하나요?
- 임시 충돌층이 이동을 오래 막지 않게 어떤 상한을 두나요?
