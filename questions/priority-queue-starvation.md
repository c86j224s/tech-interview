# 우선순위가 높은 요청부터 처리하면 낮은 요청은 어떻게 보호하나요?

## 구두 답변

높은 요청이 계속 들어오면 낮은 요청이 영원히 기다리는 기아가 생길 수 있습니다. 우선순위 큐는 순서를 정할 뿐 최소한의 진행을 보장하지는 않습니다. 저는 중요도가 낮다는 것과 무기한 지연돼도 된다는 것을 구분하겠습니다.

관리 요청을 사용자 요청보다 먼저 처리하더라도 관리 트래픽이 폭증하면 일반 기능이 멈출 수 있습니다. 클래스별 최소 실행 예산을 주거나 일정 비율로 번갈아 처리하는 가중 공정 정책을 사용할 수 있습니다. 오래 기다린 요청의 우선순위를 높이는 aging도 가능하지만, 이미 데드라인을 넘긴 작업을 승격해 자원을 낭비하지 않게 해야 합니다.

작업 비용이 크게 다르면 요청 개수 비율만 맞춰도 실행 시간을 공정하게 나누지 못합니다. 저는 실행 시간과 보유 자원을 측정해 긴 작업을 별도 큐로 분리하거나 한 번에 사용할 예산을 제한하겠습니다. 중요한 요청의 응답 목표와 낮은 요청의 최대 대기 조건을 함께 정하고, 고우선순위 부하를 지속적으로 주입해 둘 다 유지되는지 확인하겠습니다. 우선순위는 과부하에서 무엇을 먼저 지킬지 정하는 정책이지 전체 용량을 늘리는 방법은 아닙니다.

## 득점 포인트

- **우선순위와 진행 보장을 구분한다.** 낮은 요청의 기아를 다룬다.
- **최소 예산과 데드라인을 정한다.** 가중 처리·aging의 조건을 설명한다.
- **비용 차이를 반영한다.** 요청 수와 실행 자원 공정성을 나눈다.

## 감점 포인트

- **우선순위 큐만 두면 공정하다고 말한다.** 기아가 가능하다.
- **오래된 요청은 무조건 실행한다.** 이미 쓸모없는 작업일 수 있다.
- **요청 수 비율이면 자원 비율도 같다고 말한다.** 작업 비용이 다르다.
