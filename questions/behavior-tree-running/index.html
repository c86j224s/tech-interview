01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

Behavior Tree 노드는 성공·실패뿐 아니라 아직 진행 중이라는 Running을 반환할 수 있습니다. 이동이나 공격 준비처럼 여러 틱에 걸친 행동을 표현하기 위해서입니다. 하지만 상위 조건이 바뀌었을 때 진행 중 행동을 어떻게 중단하고 자원을 정리할지도 정의해야 합니다.

Behavior Tree는 조건과 행동을 트리로 조합해 NPC의 다음 행동을 선택하는 방식입니다. Running은 이동처럼 아직 끝나지 않은 행동을 뜻하고, abort는 다른 행동을 선택하면서 이전 행동을 중단하는 절차입니다. 예를 들어 도주를 시작한 뒤 예전 추적 경로가 도착해도 현재 이동 목표를 덮어쓰면 안 됩니다.

NPC가 목표로 이동하는 동안 더 높은 우선순위의 도주 조건이 생겼다고 하겠습니다. 트리를 다시 평가해 다른 행동을 선택하더라도 이전 경로 요청과 애니메이션·타이머가 남으면 늦은 완료가 새 행동을 덮을 수 있습니다. 저는 행동 인스턴스나 세대 번호를 두고 abort 시 예약과 요청을 취소하거나 결과를 무효화하겠습니다.

매 틱 모든 조건을 다시 볼지 일부 변화 이벤트에 반응할지는 비용과 반응성의 교환입니다. 공유 blackboard의 값이 어떤 틱과 행동에 속하는지도 정해야 합니다. 테스트는 목표 변경·사망·이동 실패·중단 직후 완료를 포함해 상태가 섞이지 않는지 확인하겠습니다. 트리 모양을 만드는 것보다 Running 행동의 수명과 중단 계약이 실제 안정성을 좌우합니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 진행 중 행동의 수명을 설명한다.
  • abort와 늦은 완료 무효화를 연결한다.
  • 평가 비용과 반응성을 구분한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 트리에서 다른 노드를 선택하면 이전 작업도 자동 종료된다고 말한다.
  • blackboard 값을 버전 없이 아무 행동에서나 덮는다.
  • 모든 노드는 한 틱 안에 끝난다고 가정한다.
