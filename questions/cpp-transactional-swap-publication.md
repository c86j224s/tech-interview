# 여러 필드의 새 상태를 준비한 뒤 swap으로 게시하려 합니다. 강한 예외 보장을 위해 무엇을 임시 상태에 묶나요?

## 구두 답변

모든 새 필드와 필요한 자원을 임시 객체에서 완성하고 검증한 뒤 던지지 않는 교체로 게시해야 강한 예외 보장을 설계하기 쉽습니다. 일부만 원본에 반영한 뒤 예외가 나면 swap 한 번으로 원복되지 않습니다.

allocator·비교자·swap의 noexcept 조건을 확인합니다. 이 보장은 예외 시 논리 상태의 보존이며 여러 스레드의 원자적 공개와는 별도입니다. 독자는 락이나 불변 root 게시를 따라야 하며 외부 DB·파일의 효과는 별도 transaction·내구 절차가 필요합니다.

- 모든 새 필드와 필요한 자원을 임시 객체에서 완성하고 검증한 뒤 던지지 않는 교체로 게시해야 강한 예외 보장을 설계하기 쉽습니다. 일부만 원본에 반영한 뒤 예외가 나면 swap 한 번으로 원복되지 않습니다.
- 독자는 락이나 불변 root 게시를 따라야 하며 외부 DB·파일의 효과는 별도 transaction·내구 절차가 필요합니다.
