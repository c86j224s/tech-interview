01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

짧은 코드는 입력 편의를 위한 연결 수단이지 그 자체로 충분한 신원 증명이 아닙니다. 어떤 기기의 어떤 요청을 승인하는지 사용자가 확인할 수 있어야 하고, 코드는 짧은 시간에 한 번만 사용되도록 해야 합니다. QR에 들어 있는 값도 로그인 권한을 줄 수 있다면 비밀처럼 다뤄야 합니다.

콘솔은 로그인을 기다리는 기기이고, 휴대폰은 이미 계정을 인증한 뒤 그 기기를 승인하는 역할입니다. 휴대폰 화면에는 승인할 기기와 계정, 요청 목적이 보여야 합니다. 코드가 일치한다는 사실만으로 사용자가 바로 그 기기에 접근권을 주려 했다고 확정해서는 안 됩니다.

콘솔에 코드를 표시하고 휴대폰에서 승인한다면, 휴대폰에서 로그인한 계정과 대상 기기·요청 목적을 명시하겠습니다. 단순히 코드가 맞으면 자동 승인하기보다 사용자가 연결을 확인하게 합니다. 코드를 추측하는 요청에는 횟수 제한을 두고, 인증되지 않은 코드 생성·조회 API도 남용에 견딜 수 있어야 합니다. 긴 기기 자격과 사용자가 입력하는 짧은 코드를 분리하는 방법도 있습니다.

승인은 원자적으로 소비해 동시 요청이 두 기기에 같은 권한을 만들지 못하게 하겠습니다. 기기의 폴링은 간격과 만료를 지키게 하고, 사용자가 거절하거나 세션을 바꾸면 원래 요청이 계속 승인되지 않게 하겠습니다. 테스트에서는 만료·재사용·잘못된 기기·동시 승인·응답 유실을 확인하겠습니다. 특히 코드를 다른 사람에게 입력하게 유도하는 상황을 줄이려면 화면에 대상과 목적을 분명히 보여 주는 것이 중요합니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 코드와 신원 증명을 구분한다. 사용자 승인과 대상 바인딩을 설명한다.
  • 일회성·만료·추측 제한을 설계한다. 동시 소비를 원자적으로 처리한다.
  • 정상 UX와 오인 승인을 함께 본다. 기기와 목적을 확인하게 한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • QR이면 안전하다고 말한다. 안에 든 자격의 유출과 재사용 위험이 있다.
  • 코드만 맞으면 모든 기기를 연결한다. 요청과 기기 바인딩이 필요하다.
  • 폴링을 빠르게 할수록 좋다고 말한다. 부하와 남용을 제한해야 한다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 승인 응답이 유실됐을 때 기기는 어떤 상태 조회로 결과를 확인할까요?
  • 기기 자격을 저장할 안전한 공간이 없으면 세션 수명을 어떻게 정할까요?
  • 피싱으로 다른 사람의 코드를 승인하는 실수를 어떻게 줄일까요?
