# 운영 테이블에 온라인 인덱스를 추가하려 합니다. online이면 잠금과 서비스 영향이 전혀 없나요?

## 구두 답변

온라인 인덱스 생성은 일반 작업과의 동시성을 높이는 기능이지 모든 잠금·I/O·로그·디스크 비용을 제거하지 않습니다. 시작·종료 시 메타데이터 잠금과 장기 transaction 때문에 대기가 생길 수 있습니다.

### 동작 원리와 전제

생성 동안 기존 데이터를 읽고 동시 변경을 반영해 유효한 인덱스로 게시해야 합니다. 엔진마다 단계·취소·실패 후 잔여 객체가 다르므로 버전과 옵션을 확인합니다. 고유 인덱스라면 생성 중 들어온 중복 때문에 마지막 단계에서 실패할 수도 있습니다.

### 선택과 실패 처리

사본에서 실제 크기로 시간·공간·로그·복제 지연을 측정하고 디스크 여유와 부하 상한을 확보합니다. lock timeout과 중단·재시작 절차를 준비합니다. 실패한 invalid 인덱스가 남았다면 상태를 확인한 뒤 정리하며 이름만 존재한다고 사용 가능하다고 보지 않습니다.

### 구체적인 사례와 검증

인덱스 생성이 끝날 때 긴 transaction이 메타데이터 잠금을 막아 최종 전환이 지연될 수 있습니다. 생성 중 CPU가 낮다고 안전하다고 판단하지 않고 대기 원인과 세션 수명을 봅니다. 취소하면 임시 파일이나 invalid 객체가 남는지 엔진 절차를 확인합니다. 고유 인덱스는 기존 중복 정리와 동시 쓰기의 새 중복 방지가 모두 필요합니다. 완료 후 기존 쿼리가 새 인덱스를 선택해 오히려 특정 파라미터에서 느려질 수도 있으므로 대표 질의를 다시 측정합니다. online이라는 옵션명보다 실제 단계와 장애 시 남는 상태를 운영 지침으로 남기겠습니다.

생성 중 쓰기·장기 읽기·취소·디스크 부족·중복 삽입을 시험합니다. 새 인덱스가 실제 질의에 쓰이는지와 쓰기 유지 비용을 확인합니다. 배포 성공은 DDL 반환뿐 아니라 인덱스 유효성·계획·사용자 지연이 목표 안에 들어오는지로 판단합니다.

## 득점 포인트

- 핵심 구분: 온라인 인덱스 생성은 일반 작업과의 동시성을 높이는 기능이지 모든 잠금·I/O·로그·디스크 비용을 제거하지 않습니다.
- 선택 조건: 사본에서 실제 크기로 시간·공간·로그·복제 지연을 측정하고 디스크 여유와 부하 상한을 확보합니다.
- 검증 기준: 생성 중 쓰기·장기 읽기·취소·디스크 부족·중복 삽입을 시험합니다.

## 감점 포인트

- online DDL은 잠금·로그·추가 공간을 전혀 쓰지 않는다고 한다.
