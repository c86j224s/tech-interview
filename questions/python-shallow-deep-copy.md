# Python에서 중첩 리스트를 가진 딕셔너리를 복사한 뒤 리스트를 바꿨더니 원본도 바뀝니다. 얕은 복사와 깊은 복사는 무엇을 공유하며 파일 같은 외부 자원에도 적용할 수 있나요?

## 구두 답변

`copy.copy()`는 새 바깥 객체를 만들지만 내부에서 참조하는 중첩 객체는 원본과 공유합니다. `copy.deepcopy()`는 복사 가능한 구성 요소를 재귀적으로 복제하고, 이미 복사한 객체를 memo에 기록해 같은 객체의 반복 참조와 순환 참조를 처리하려고 합니다. 따라서 얕은 복사는 구조의 한 단계만 분리하고 깊은 복사는 더 넓은 그래프를 분리하는 선택입니다.

```python
import copy

original = {"items": [1]}
shallow = copy.copy(original)
deep = copy.deepcopy(original)
shallow["items"].append(2)
print(original["items"])
print(deep["items"])
```

출력은 `[1, 2]`와 `[1]`입니다. `shallow["items"]`와 `original["items"]`가 같은 리스트를 가리키지만, `deep`의 리스트는 별도이기 때문입니다. 반대로 최상위 값만 교체하는 `shallow["items"] = []`는 원본 딕셔너리의 키를 바꾸지 않으므로, 어떤 변경을 할지에 따라 공유 범위를 확인해야 합니다.

`deepcopy`가 임의의 객체 그래프를 완전히 독립된 실행 자원으로 만들어 주는 것은 아닙니다. 파일·소켓·스레드 락·DB 연결 같은 외부 자원은 복제할 수 없거나 복제해도 의미가 없고, 사용자 정의 클래스는 `__copy__`·`__deepcopy__`가 규칙을 바꿀 수 있습니다. 큰 그래프를 깊게 복사하면 시간과 메모리 비용도 큽니다. 불변 자료구조나 명시적 변환 함수가 더 안전한 경계라면 그것을 선택하고, 복사 뒤 실제로 공유되면 안 되는 노드만 테스트하겠습니다.

## 득점 포인트

- 얕은 복사는 바깥 객체만, 깊은 복사는 중첩 복사까지 시도한다는 차이를 출력으로 증명한다.
- 깊은 복사가 memo와 사용자 정의 훅을 사용하며 모든 외부 자원을 복제하지는 않는다고 설명한다.
- 변경 범위·그래프 크기·불변 변환 가능성을 기준으로 복사 방식을 선택한다.

## 감점 포인트

- `copy.copy`가 중첩 리스트까지 재귀적으로 복제한다고 말한다.
- `deepcopy`하면 파일·소켓·락도 독립적으로 사용할 수 있다고 단정한다.
- 복사된 두 객체가 모든 내부 노드에서 반드시 서로 다르다고 주장한다.
