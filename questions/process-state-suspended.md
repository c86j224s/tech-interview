# 프로세스가 실행되지 않는데 하나는 Ready, 다른 하나는 Blocked 상태입니다. 각각 무엇을 기다리며 CPU를 더 배정하면 둘 다 바로 실행할 수 있나요?

## 구두 답변

Ready는 실행할 준비는 됐지만 CPU 배정을 기다리는 상태이고, Blocked는 I/O나 동기화 조건 같은 사건을 기다려 지금은 실행을 이어 갈 수 없는 상태입니다. 둘 다 CPU를 안 쓰는 모습일 수 있지만 해결해야 하는 자원이 다릅니다.

실행 가능한 작업이 너무 많아 밀린다면 스케줄링 경쟁과 CPU 용량을 봐야 합니다. 반면 DB 응답을 기다리는 작업이라면 CPU를 늘려도 DB가 끝나기 전에는 진행할 수 없습니다. Suspended는 실행 집합에서 잠시 제외하거나 메모리 상태를 옮기는 등의 관리 상태를 가리키는 모델로, 단순한 사건 대기와 구분합니다. 실제 상태 이름과 표시 방식은 OS마다 다릅니다.

장기·중기·단기 스케줄러라는 교과서 구분도 입장할 작업, 일시 제외할 작업, 지금 CPU를 줄 작업의 책임을 나눠 설명하는 것입니다. 저는 운영 도구의 상태 이름을 바로 이 모델과 동일시하지 않고 문서와 대기 원인을 확인하겠습니다. 실행 큐와 I/O 대기, 락 스택을 나눠야 잘못된 증설을 피할 수 있습니다.

## 득점 포인트

- CPU 배정 대기와 사건 대기를 구분한다.
- 논리 상태 모델과 OS 표시를 나눈다.
- 대기 원인에 맞는 자원을 조사한다.

## 감점 포인트

- CPU를 안 쓰면 모두 같은 대기라고 말한다.
- Blocked 프로세스는 CPU만 주면 진행한다고 말한다.
- Suspended와 I/O 대기를 항상 같은 뜻으로 쓴다.

- 실행 큐 지연과 락 대기 시간을 어떻게 나눠 측정할까요?
