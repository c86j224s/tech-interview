# 모델의 하이퍼파라미터를 여러 번 바꿔 가장 좋은 결과를 골랐습니다. 훈련·검증·테스트 데이터를 어떻게 분리해야 성능을 공정하게 추정할 수 있나요?

## 구두 답변

훈련 데이터는 모델의 파라미터를 학습하는 데 쓰고, 검증 데이터는 학습률·모델 크기·특징 선택·정규화 강도 같은 선택을 비교하는 데 씁니다. 테스트 데이터는 모든 선택을 끝낸 뒤 처음 보는 데이터처럼 한 번 사용해 최종 일반화 성능을 추정합니다. 검증 결과를 보고 계속 설계를 바꾸는 순간 검증 세트도 선택 과정의 정보가 되므로, 테스트 세트는 그보다 더 바깥에 두어야 합니다.

분할은 단순히 행을 무작위로 나누는 문제가 아닙니다. 같은 사용자나 같은 시간 구간에서 나온 서로 의존하는 기록이 train과 validation에 함께 들어가면 모델이 패턴을 미리 본 것처럼 성능이 부풀 수 있습니다. 시간 순서가 중요한 예측은 과거로 훈련하고 미래로 검증합니다. 처음 보는 사용자에 대한 일반화가 목표라면 사용자를 기준으로 나누고, 기존 사용자의 미래 행동을 예측한다면 시간 분할과 예측 시점의 정보 범위가 더 중요할 수 있습니다. 전처리도 분할 뒤 훈련 데이터로 평균·분산·어휘·결측 대체 규칙을 학습한 후 다른 세트에 고정 적용해야 합니다.

데이터가 적으면 교차 검증으로 훈련 영역 안에서 여러 검증 접기를 돌려 선택의 변동을 줄일 수 있습니다. 그래도 최종 테스트 세트를 각 접기의 점수를 보고 모델을 고르는 데 사용하면 테스트가 검증 세트처럼 오염됩니다. 모델을 고른 뒤 테스트에서 한 번 평가하고, 그 결과를 보고 다시 바꾸었다면 새 독립 테스트 세트나 재수집한 평가 자료가 필요합니다.

보고할 때는 어떤 데이터를 언제 사용했는지, 전처리와 특징 생성이 어느 분할에서 fit됐는지, 여러 번 실험한 횟수와 최종 테스트의 단일 평가 여부를 함께 기록합니다. 테스트 점수는 미래 운영 성능의 확정값이 아니라 해당 표본과 분할 규칙 아래의 추정치입니다. 데이터 분포가 바뀌면 시간 기반 검증이나 운영 후 모니터링이 추가로 필요하며, 테스트를 숨겨 두는 규율이 모델 선택보다 더 중요한 이유도 여기에 있습니다.

## 득점 포인트

- 훈련은 파라미터, 검증은 선택, 테스트는 최종 추정이라는 역할을 분리한다.
- 사용자·시간 의존성과 전처리 fit까지 포함해 정보 유출 경로를 구체적으로 설명한다.
- 테스트 결과를 보고 다시 수정하면 새 독립 평가가 필요하다는 판단을 완결한다.

## 감점 포인트

- 검증 점수가 가장 좋았던 모델을 테스트 데이터로 계속 튜닝한다.
- 전체 데이터의 평균·분산을 먼저 계산한 뒤 train과 validation에 나눠 적용한다.
- 행 단위 무작위 분할이면 시간 누수나 동일 사용자 누수가 없다고 단정한다.

## 더 파고들 거리

- 시계열 예측에서 rolling validation과 단일 holdout을 어떤 조건으로 선택할지 비교해 보세요.
- 교차 검증의 접기 수와 분산을 모델 선택의 불확실성과 연결해 설명해 보세요.
- 실험 추적 기록에 데이터 버전·전처리 fit 범위·하이퍼파라미터를 어떻게 남길지 정해 보세요.
