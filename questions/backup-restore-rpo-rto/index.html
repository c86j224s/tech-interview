01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

백업 파일이 만들어졌다는 것과 실제 서비스를 복구할 수 있다는 것은 다릅니다. 복원이 가능한지, 필요한 암호화 키와 설정이 있는지, 정해진 시간 안에 다시 서비스할 수 있는지 확인해야 합니다. 허용할 데이터 유실인 RPO와 복구 시간인 RTO를 먼저 정하겠습니다.

매일 백업한다면 최근 변경을 얼마나 잃을 수 있는지와 로그를 이용한 시점 복구가 가능한지 봐야 합니다. 복제본은 빠른 전환에 도움이 되지만 잘못된 삭제도 복제될 수 있어 백업을 완전히 대체하지는 않습니다. 저는 별도 환경에서 실제 복원을 수행하고 주요 업무 불변식과 데이터 건수, 계정 접근이 정상인지 검증하겠습니다.

복구 시간에는 데이터 복사만이 아니라 새 인프라 준비, 키 접근, DNS·트래픽 전환, 캐시 예열도 포함됩니다. 절차가 특정 사람의 기억에만 있으면 장애 중 오래 걸릴 수 있어 실행 가능한 복구 지침과 권한을 준비하겠습니다. 백업 접근은 제한하되 원본 계정이나 지역이 불능이어도 복구할 수 있는지 확인해야 합니다. 성공 기준은 백업 작업의 녹색 표시보다 실제 복구 훈련에서 약속한 유실과 시간 범위 안에 들어오는지입니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 백업과 복구를 구분한다. 실제 복원과 업무 검증을 수행한다.
  • 목표를 구체화한다. 유실과 시간의 범위를 정한다.
  • 의존성까지 포함한다. 키·권한·트래픽·예열을 확인한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 복제본이 있으니 백업은 필요 없다고 말한다. 논리 오류도 복제될 수 있다.
  • 파일 생성 성공이면 복구도 성공이라고 말한다. 손상·키·절차 문제가 남는다.
  • RTO를 데이터 복사 시간만으로 계산한다. 운영 복원 단계가 포함돼야 한다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 시점 복구에서 잘못된 변경 직전을 어떻게 정확히 찾을까요?
  • 복구 훈련 데이터의 개인정보 노출을 어떻게 제한할까요?
  • 여러 서비스의 백업 시점이 다르면 업무 일관성은 어떻게 복구할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
