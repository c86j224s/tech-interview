01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

일반적인 B-tree 계열 복합 인덱스는 앞쪽 컬럼부터 차례대로 비교하는 순서로 정렬되기 때문에 컬럼 순서가 중요합니다. 예를 들어 고객 ID와 주문 시각 순서의 인덱스라면, 같은 고객의 주문들이 모여 있고 그 안에서 주문 시각순으로 정렬됩니다. 특정 고객의 최근 주문을 찾는 쿼리에는 잘 맞지만, 모든 고객의 주문을 시각만으로 찾을 때는 같은 방식으로 좁은 범위를 바로 찾기 어렵습니다.

그래서 인덱스는 컬럼만 보고 정하기보다 실제 WHERE 조건과 정렬, 반환할 행 수를 함께 보고 설계해야 합니다. 앞쪽 컬럼에 동등 조건을 적용해 범위를 좁히고, 그다음 컬럼으로 범위 검색이나 정렬을 처리하는 구성이 유용한 경우가 많습니다. 다만 여러 동등 조건 사이의 순서는 다른 쿼리에서 어떤 조건이 자주 생략되는지도 고려해야 합니다.

앞쪽 컬럼에 범위 조건이 있으면 뒤쪽 컬럼의 조건만으로 연속된 탐색 범위를 더 줄이기 어려운 경우가 많습니다. 그렇다고 뒤쪽 컬럼이 아무 역할도 못 하는 것은 아닙니다. 인덱스 안에서 추가 필터링을 하거나 필요한 데이터를 인덱스만으로 반환하는 데 쓰일 수 있습니다. 구체적인 탐색 방식과 최적화 지원은 데이터베이스마다 다릅니다.

인덱스를 넓게 만들면 읽기에는 유리할 수 있지만, 저장 공간과 캐시 사용량이 늘고 INSERT나 UPDATE에서 유지할 데이터도 많아집니다. 반환용 컬럼은 데이터베이스가 지원한다면 포함 컬럼으로 두어 탐색 키와 구분하는 방법도 있습니다. 하지만 이것도 공짜는 아니므로 실제로 줄어드는 테이블 접근 비용과 비교해야 합니다.

최종적으로는 대표적인 데이터와 파라미터로 실행 계획을 확인하겠습니다. 인덱스를 사용했다는 사실만 보지 않고 실제 읽은 행 수, 반환한 행 수, 추가 정렬과 테이블 조회, 쓰기 비용을 함께 측정해야 합니다. 결국 컬럼 순서는 선택도가 높은 컬럼을 무조건 앞에 놓는 규칙이 아니라, 주요 쿼리들이 데이터를 찾는 경로에 맞춰 정하는 문제입니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 복합 인덱스의 정렬 구조를 설명한다. 앞쪽 컬럼이 같을 때 다음 컬럼으로 정렬된다는 구조를 쿼리 예와 연결한다.
  • 필터와 정렬을 함께 고려한다. 동등 조건, 범위 조건, ORDER BY, 조회 건수에 따라 유리한 순서가 달라짐을 설명한다.
  • 탐색과 추가 필터링을 구분한다. 뒤쪽 컬럼이 탐색 범위를 크게 줄이지 못해도 인덱스 내부 필터나 커버링에 활용될 수 있다고 짚는다.
  • 실행 계획과 실제 비용으로 검증한다. 읽은 행 수와 쓰기 부담까지 포함해 판단한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • “선택도가 높은 컬럼을 무조건 맨 앞에 둔다”고 말한다. 동등 조건 조합, 정렬 요구, 다른 쿼리에서의 재사용을 함께 봐야 한다.
  • “첫 컬럼 조건이 없으면 인덱스는 절대로 사용되지 않는다”고 말한다. 효율적인 선두 키 탐색이 어려운 것과 인덱스 스캔이나 DB별 최적화를 사용할 수 없는 것은 다르다.
  • “범위 조건 뒤의 컬럼은 완전히 쓸모없다”고 말한다. 추가 필터링이나 커버링 등의 용도로 활용될 수 있다.
  • “인덱스를 사용하면 튜닝이 끝났다”고 판단한다. 넓은 인덱스 스캔이나 많은 테이블 조회가 여전히 큰 비용을 만들 수 있다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • WHERE 조건에는 잘 맞지만 ORDER BY에는 맞지 않는 인덱스를 어떻게 평가해야 할까요?
  • 키 컬럼과 포함 컬럼은 정렬, 탐색, 저장 비용에서 어떤 차이가 있을까요?
  • 특정 값에 데이터가 몰려 있으면 같은 쿼리도 파라미터에 따라 실행 계획이 달라져야 할까요?
  • 큰 OFFSET을 사용하는 페이지 조회와 마지막으로 읽은 키를 사용하는 조회는 인덱스 접근에서 어떻게 다를까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
