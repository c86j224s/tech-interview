# 새 기능을 끈 뒤에도 그 기능이 발행한 이벤트가 도착합니다. 소비자의 호환·보정·중복 처리는 어떻게 유지하나요?

## 구두 답변

플래그는 앞으로 선택할 코드 경로를 바꾸지만 이미 발행한 이벤트를 지우지 않습니다. 소비자는 이전·새 event version을 지원하거나 명시적인 보정·격리 정책으로 처리해야 합니다.

중복 이벤트는 ID로 막고 현재 상태의 허용 전이를 검사합니다. 외부 결제·메일은 플래그 off로 rollback되지 않습니다. 노출 version·이벤트·원장과 사용자 결과를 연결해 rollback 후 남은 효과와 미완료를 대사합니다.
