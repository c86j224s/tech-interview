# 한 작업자가 DB와 객체 저장소에 씁니다. 한곳의 펜싱 검사만으로 전체 작업을 보호할 수 있나요?

## 구두 답변

DB가 옛 token을 거절해도 객체 저장소가 같은 검사를 하지 않으면 작업 일부는 여전히 오염될 수 있습니다. 모든 실제 변경 지점의 권위 검사와 원자 범위를 명시해야 합니다.

자원이 조건부 쓰기를 지원하면 epoch·version을 사용하고 지원하지 않으면 단일 실행 지점·멱등 API·보상·대사를 검토합니다. 한곳의 락이 외부 결제를 transaction에 포함하지는 않습니다. 부분 성공 뒤 재개가 어떤 효과를 다시 만들지 시험합니다.
