# 같은 폼과 목록이 브라우저마다 다르게 보입니다. 기본 스타일을 초기화하는 reset과 차이를 보정하는 normalize 중 무엇을 선택하고, 접근성은 어떻게 확인하나요?

## 구두 답변

reset과 normalize는 브라우저마다 다른 기본 스타일 때문에 생기는 차이를 다루지만 목표가 다릅니다. reset은 여백·제목 크기·목록 표시처럼 기본 선언을 넓게 제거해 디자인 시스템이 처음부터 값을 정하도록 합니다. normalize는 유용한 기본 의미와 구조를 가능한 한 보존하면서 브라우저 간 차이와 오래된 구현의 불일치를 보정합니다. 따라서 둘 중 하나가 항상 더 현대적이거나 더 빠른 선택은 아닙니다.

reset을 적용하면 `h1`, `p`, `ul`의 시각적 구분과 여백을 직접 다시 설계해야 합니다. 이 과정에서 제목의 계층, 목록의 불릿, 링크의 식별성, 포커스 표시까지 빠뜨리면 시각적으로는 깔끔해도 접근성이 나빠질 수 있습니다. 특히 `outline: none`처럼 키보드 포커스를 없애는 규칙은 reset의 필수 요소가 아니며, 대체 포커스 스타일 없이 제거해서는 안 됩니다.

normalize는 기본 스타일을 전부 없애지 않으므로 콘텐츠 중심 페이지나 브라우저 의미를 활용하는 화면에 시작점으로 쓰기 쉽습니다. 반면 프로젝트가 강한 디자인 시스템과 자체 컴포넌트만으로 화면을 구성하고 모든 요소의 여백·타이포그래피·폼 스타일을 명시하려면 작은 범위의 reset이 더 예측 가능할 수 있습니다. 어느 쪽이든 최신 브라우저에서 실제로 필요한 보정만 남기고 오래된 브라우저용 규칙을 무비판적으로 복사하지 않겠습니다.

선택 후에는 스크린 리더의 제목·목록 구조, 키보드 탭 순서와 포커스 표시, 기본 버튼·입력 컨트롤의 조작 가능성을 확인하겠습니다. reset과 normalize는 의미론적 HTML을 대신하지 않으며, CSS로 보이지 않게 만들었다고 접근성 트리에서도 사라진다는 뜻도 아닙니다. 시각적 일관성과 브라우저 기본값 보존 중 어느 쪽이 제품 화면의 변경 범위와 접근성 검증 비용에 맞는지 정해 적용하겠습니다.

## 득점 포인트

- reset의 제거 목표와 normalize의 일관성 보정 목표를 구분한다.
- 기본 스타일 제거가 제목·목록·포커스 접근성에 미치는 영향을 설명한다.
- 화면 유형과 디자인 시스템 범위에 따른 선택 기준을 제시한다.

## 감점 포인트

- reset과 normalize가 같은 방식으로 모든 기본 스타일을 삭제한다고 말한다.
- 포커스 표시를 없애도 키보드 사용성에 영향이 없다고 말한다.
- normalize를 넣으면 접근성 검증이 필요 없다고 단정한다.
