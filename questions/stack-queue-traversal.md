# 되돌리기 기능과 먼저 들어온 작업 처리는 왜 각각 스택과 큐에 어울리나요?

## 구두 답변

스택은 마지막에 넣은 것을 먼저 꺼내고, 큐는 먼저 넣은 것을 먼저 꺼냅니다. 되돌리기는 가장 최근 동작을 먼저 취소해야 해서 스택이 자연스럽고, 접수 순서대로 일을 처리하려면 큐가 맞습니다. 이름보다 어떤 순서를 보존해야 하는지부터 확인하겠습니다.

동작 A 다음 B를 실행했다면 되돌리기는 B 다음 A여야 앞선 상태로 돌아가기 쉽습니다. 작업 큐에서는 A를 먼저 받았으면 먼저 꺼내지만, 여러 워커가 병렬 처리한다면 완료도 A가 먼저라는 보장은 없습니다. 큐의 인출 순서와 작업 결과의 반영 순서는 구분해야 합니다.

구현에는 배열이나 연결 구조를 쓸 수 있습니다. 배열 큐에서 매번 앞 원소를 지우고 모두 당기면 비싸므로 원형 버퍼나 앞뒤 인덱스를 사용할 수 있습니다. 서버 큐에는 용량과 가득 찼을 때의 정책도 필요합니다. 저는 빈 상태·꽉 찬 상태·여러 번 넣고 빼는 경계와 실제 완료 순서를 테스트하겠습니다. 자료구조의 순서 규칙이 작업의 순서를 대신 보장하는 범위를 정확히 알아야 합니다.

## 득점 포인트

- 후입선출과 선입선출을 작업 순서에 연결한다.
- 인출과 완료 순서를 구분한다.
- 큐 구현의 이동 비용과 상한을 설명한다.

## 감점 포인트

- FIFO 큐면 병렬 완료도 FIFO라고 말한다.
- 배열 앞 삭제의 이동 비용을 무시한다.
- 빈 큐와 포화 큐를 같은 상태로 처리한다.
