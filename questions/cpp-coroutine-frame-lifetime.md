# C++ 코루틴에서 중단 중인 객체와 버퍼의 수명은 어떻게 관리하나요?

## 구두 답변

코루틴은 함수가 중단돼도 나중에 이어서 실행할 상태를 프레임에 유지합니다. 하지만 프레임에 참조가 들어 있다고 참조 대상의 수명까지 늘어나지는 않습니다. 호출자가 넘긴 객체가 먼저 파괴되면 재개 시 잘못된 메모리를 사용할 수 있습니다.

예를 들어 지역 버퍼를 참조하는 비동기 쓰기를 시작하고 호출자가 반환한다고 하겠습니다. 쓰기가 끝나기 전에 버퍼가 없어지면 위험합니다. 저는 비동기 작업이 버퍼를 소유하게 하거나, 완료가 확인될 때까지 소유 객체를 유지하도록 계약을 정하겠습니다. 멤버 코루틴이 this를 참조하는 경우에도 객체가 코루틴보다 오래 사는지 따로 확인해야 합니다. 캡처가 있는 코루틴 람다도 클로저와 프레임 수명을 혼동하기 쉽습니다.

취소 때는 더 조심해야 합니다. 기다리기를 포기했다고 실행 중 I/O가 프레임을 더 이상 참조하지 않는 것은 아닙니다. 완료 콜백이 다시 resume할 수 있는 상태에서 프레임을 파괴하면 오류가 납니다. 취소와 완료 중 누가 최종 정리를 하는지 한 상태 전이로 관리하고, 다시 재개되지 않는다는 보장이 생긴 뒤 파괴하겠습니다. 테스트에서는 즉시 완료, 늦은 완료, 취소 직후 완료를 각각 재현하겠습니다. 코루틴 문법이 콜백 코드를 짧게 해 주지만 수명 계약을 없애 주는 것은 아닙니다.

## 득점 포인트

- **프레임과 참조 대상의 수명을 구분한다.** 지역·this·캡처 수명을 따로 본다.
- **완료까지 소유권을 유지한다.** I/O와 프레임 파괴의 순서를 정한다.
- **취소·완료 경합을 검증한다.** 한 번의 재개와 정리 책임을 명확히 한다.

## 감점 포인트

- **코루틴 지역 변수라면 모든 참조도 안전하다고 말한다.** 참조 대상은 별도로 사라질 수 있다.
- **취소하면 즉시 프레임을 파괴한다.** 완료가 뒤늦게 접근할 수 있다.
- **shared_ptr 하나면 재개 경쟁도 해결된다고 말한다.** 수명과 실행 상태는 다르다.
