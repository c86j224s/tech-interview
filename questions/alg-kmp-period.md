# 문자열이 반복 블록으로 이루어졌는지 prefix function으로 판단할 때 나눗셈 조건은 무엇인가요?

## 구두 답변

길이 `n`인 문자열의 마지막 접두 함수 값을 `π[n-1]`이라 하면 `k=n-π[n-1]`를 최소 반복 블록의 후보로 계산합니다. 이때 반드시 `n % k == 0`인지 확인해야 합니다. 나누어떨어지면 길이 `k`의 접두 블록이 전체를 반복하고, 아니면 `k`는 단지 접두와 접미가 겹친 뒤 남은 후보 길이일 뿐 전체 반복 주기가 아닙니다.

`ababab`에서는 `π[5]=4`이므로 `k=2`입니다. `6 % 2=0`이고 접두 `ab`를 세 번 이어 붙인 문자열이므로 반복 블록 길이는 2입니다. 반면 `ababa`에서도 `π[4]=3`이라 `k=2`가 나오지만 `5 % 2=1`입니다. `aba`라는 border가 있다고 해서 문자열 전체가 `ab`의 반복이라고 말할 수 없습니다. 마지막 한 블록이 완전히 채워지지 않기 때문입니다.

이 조건은 최소 후보를 빠르게 얻는 방법이지, 입력 단위나 빈 문자열 정책까지 정해 주지는 않습니다. 빈 문자열은 보통 별도 반환 규칙을 두고, 비ASCII 입력은 π를 계산한 단위와 블록 길이 단위를 동일하게 유지해야 합니다.

왜 `k`가 후보가 되는지는 마지막 border의 길이를 보면 분명합니다. `π[n-1]` 길이만큼의 접두와 접미가 같다면, 접미를 시작하는 위치는 `n-π[n-1]`인 `k`입니다. `n`이 `k`의 배수라면 이 겹침이 한 블록씩 반복되는 경계를 만들고, 더 짧은 블록이 가능했다면 마지막 border가 더 길어져야 하므로 후보도 최소입니다. 반대로 배수가 아니면 겹치는 prefix와 suffix 사이에 남는 부분이 블록 단위로 채워지지 않습니다.

실제 코드에서는 길이 1 문자열이나 빈 문자열을 먼저 처리하는 것이 안전합니다. `π[n-1]` 접근 전에 `n=0`을 검사하고, `n=1`이면 `k=1`로 반복 여부를 정의합니다. 또한 문자열을 정규화하거나 대소문자를 접는 단계가 있다면 판정 전에 처리해야 합니다. 원본 표시 문자열의 반복 여부와 검색 키의 반복 여부를 섞으면 결과를 재현하기 어렵습니다.

## 득점 포인트

- `k=n-π[n-1]`를 구하고 `n%k==0`을 확인한다.
- border 존재와 전체 반복 주기를 구분한다.
- `ababa`를 반례로 나눗셈 조건의 필요성을 설명한다.

## 감점 포인트

- 나눗셈 검사를 생략하고 k를 항상 주기로 반환한다.
- π 값 자체를 반복 횟수로 오해한다.

## 더 파고들 거리

- `π` border 사슬을 따라가며 `n`을 나누는 후보만 남기면 최소 주기와 더 긴 유효 주기를 분리할 수 있습니다.
- 스트림 종료 시점의 전체 길이와 마지막 `π` 값이 필요하며, 중간 prefix만으로 최종 반복 여부를 확정할 수 없습니다.
