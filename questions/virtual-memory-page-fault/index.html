01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

페이지 폴트는 접근한 가상 주소를 현재 페이지 테이블 상태로 즉시 처리할 수 없어 운영체제가 개입했다는 사건이지, 곧바로 물리 메모리 부족이라는 뜻은 아닙니다. 지연 할당된 익명 메모리를 처음 쓸 때 실제 물리 페이지를 연결할 수 있고, 메모리 매핑 파일의 페이지를 처음 읽을 때 파일에서 가져올 수 있습니다. 잘못된 주소나 쓰기 권한 위반도 폴트로 발생하지만 이는 프로그램 오류로 종료될 수 있습니다.

디스크 접근 없이 페이지 테이블·공유 페이지 처리로 끝나는 마이너 폴트와 저장 장치에서 읽어야 하는 메이저 폴트를 구분합니다. 서버가 시작하며 큰 버퍼를 예약하고 요청 때 처음 접근한다면 초기 폴트 증가는 정상일 수 있습니다. 예열로 첫 요청 지연을 줄일 수 있지만 사용하지 않을 페이지까지 실제로 채워 시작 시간과 메모리 점유를 늘릴 수 있습니다.

운영 중 메이저 폴트, 디스크 대기, RSS 감소·메모리 압력이 함께 늘면 작업 집합이 메모리에 남지 못하고 반복해서 읽히는지 확인합니다. 프로세스의 가상 주소 예약량과 RSS, 호스트 reclaim/swap, 페이지 폴트 종류, 저장 장치 지연을 같은 시간축에서 봅니다. 단순히 메모리를 더 주기 전에 캐시 크기와 동시성, 접근 지역성을 줄여 필요한 페이지를 유지할 수 있는지 검토합니다.

테스트는 첫 접근 예열 전후, 매핑 파일 접근, 메모리 압력, 권한 위반을 분리합니다. 폴트 수 자체가 아니라 어느 종류의 폴트가 어떤 사용자 지연과 함께 늘었는지를 기준으로 원인을 판단하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 페이지 준비·파일 매핑·접근 오류와 메모리 부족을 구분한다.
  • 마이너·메이저 폴트와 RSS·디스크 대기를 연결한다.
  • 예열의 지연 개선과 메모리·시작 비용을 비교한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 모든 페이지 폴트가 스왑을 뜻한다고 말한다.
  • 가상 주소 예약량을 실제 상주 메모리로 해석한다.
  • 메모리를 늘리면 접근 오류와 작업 집합 문제도 항상 해결된다고 말한다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 메모리 매핑 파일의 첫 접근과 일반 read의 비용은 어떻게 다른가요?
  • 대형 페이지가 주소 변환과 메모리 낭비에 만드는 교환은 무엇인가요?
  • copy-on-write가 마이너 폴트와 RSS 증가를 어떻게 연결하나요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
