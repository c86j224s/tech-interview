01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

재시도는 일시 실패에서 다시 성공할 기회를 주지만, 하위가 계속 실패하는 동안에는 부하를 더할 수 있습니다. 서킷 브레이커는 실패가 누적된 의존성으로의 호출을 잠시 막아 자원을 보호하고 회복 기회를 주는 장치입니다. 다만 모든 오류를 하위 장애로 세어서는 안 됩니다.

예를 들어 사용자 입력 오류가 많다고 결제 서비스 전체 호출을 차단하면 정상 요청까지 막습니다. 저는 타임아웃과 연결 실패, 서버 오류 중 어떤 것을 실패로 볼지 정하고, 최소 요청량과 관찰 구간을 두겠습니다. 회로가 열리면 무의미하게 대기하지 않고 빠르게 실패시키거나 기능에 맞는 대체 결과를 돌려줍니다. 금전 처리라면 가짜 성공 대신 재시도 가능한 상태를 명시해야 합니다.

회복을 확인할 때 모든 요청을 한꺼번에 다시 보내면 재차 무너질 수 있습니다. 제한된 시험 요청으로 성공을 확인한 뒤 점진적으로 허용하겠습니다. 또한 브레이커는 동시 실행 수 제한이나 데드라인을 대체하지 않습니다. 실패 판정이 나기 전에도 느린 요청이 쌓일 수 있기 때문입니다. 테스트는 장애 진입과 회복, 짧은 출렁임을 재현해 정상 요청을 과도하게 막지 않으면서 큐와 연결이 보호되는지 확인하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 재시도와 차단의 역할을 구분한다. 지속 장애에서 부하 증폭을 막는다.
  • 실패 분류와 표본 조건을 정한다. 입력 오류를 전체 장애로 취급하지 않는다.
  • 회복과 다른 제한을 결합한다. 시험 요청·동시성·데드라인을 설명한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 모든 오류를 같은 실패로 센다. 정상 기능까지 차단할 수 있다.
  • 차단하면 성공처럼 응답한다. 업무 계약을 깨뜨릴 수 있다.
  • 브레이커가 큐 크기도 제한한다고 말한다. 별도의 진입 제어가 필요하다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 인스턴스별 브레이커와 공유 상태 브레이커는 어떤 장단점이 있나요?
  • half-open 시험 요청이 실제 부하를 대표하지 못하면 어떻게 할까요?
  • 대체 캐시 결과를 제공할 때 허용 가능한 오래됨은 어떻게 정할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
