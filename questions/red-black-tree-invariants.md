# 검색 트리에 삽입과 삭제가 반복돼도 한쪽으로 치우쳐 조회가 느려지지 않게 하려 합니다. Red-Black Tree는 어떤 규칙을 복구해 높이를 제한하나요?

## 구두 답변

Red-Black Tree는 각 노드의 색과 경로의 검은 노드 수에 관한 규칙으로 한쪽 경로만 지나치게 길어지는 것을 막습니다. 단순히 빨강과 검정을 번갈아 칠하는 트리는 아닙니다. 빨간 노드끼리는 부모·자식으로 이어지지 않고, 한 노드에서 아래의 NIL 잎까지 가는 경로들은 같은 검은 높이를 가져야 합니다.

이 규칙이면 긴 경로에도 빨간 노드가 연속해서 붙지 못하므로 짧은 경로에 비해 무한히 늘어날 수 없습니다. 삽입으로 빨간 부모와 빨간 자식이 생기거나 삭제로 검은 높이가 달라지면 재색칠과 회전으로 복구합니다. 회전은 키의 중위 순서를 유지하면서 연결 모양을 바꾸는 연산입니다.

저는 색 규칙만 검사하지 않고 BST의 정렬 조건과 부모 포인터, 삭제한 노드의 수명도 함께 테스트하겠습니다. 루트와 NIL의 색을 어떻게 표현하는지도 구현 규약으로 고정해야 합니다. 라이브러리를 쓴다면 내부 회전을 직접 제어하기보다 비교자와 반복자 무효화 계약을 확인하겠습니다. 균형 보장의 이득은 있지만 삽입·삭제가 공짜가 되는 것은 아닙니다.

## 득점 포인트

- 빨간 연속 금지와 검은 높이를 설명한다.
- 회전이 키 순서를 유지함을 짚는다.
- 색·정렬·포인터 불변식을 함께 검증한다.

## 감점 포인트

- 모든 부모와 자식 색은 반드시 다르다고 말한다.
- 회전으로 키의 정렬 의미도 바뀐다고 말한다.
- 색만 맞으면 모든 구현이 안전하다고 말한다.

## 더 파고들 거리

- 높이의 최악 상한은 검색 비교 횟수와 어떻게 연결될까요?
