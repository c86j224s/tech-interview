# 긴 계산 작업과 짧은 대화형 요청이 CPU를 함께 씁니다. FCFS, SJF, Round Robin은 대기 시간을 어떻게 바꾸나요?

## 구두 답변

FCFS는 먼저 들어온 일을 먼저 실행하므로 단순하지만 긴 작업 뒤의 짧은 작업들이 오래 기다릴 수 있습니다. SJF는 짧은 작업을 우선해 특정 전제에서 평균 대기를 줄일 수 있지만 실제로 다음 실행 시간을 정확히 아는 것은 어렵습니다. Round Robin은 일정 시간씩 실행 기회를 나눠 대화형 작업의 반응성을 높이는 방식입니다.

긴 작업 하나가 CPU를 오래 쓰면 짧은 입력 처리도 멈춘 것처럼 느껴질 수 있습니다. 시간을 나눠 실행하면 짧은 작업이 먼저 반응할 기회를 얻지만 전환 비용이 추가됩니다. SJF처럼 짧은 작업만 계속 우선하면 긴 작업의 기아도 고려해야 합니다.

저는 평균 완료 시간과 첫 응답 시간, 공정성 중 어떤 목표가 중요한지 먼저 정하겠습니다. 실제 운영체제는 여러 정책과 우선순위를 조합하므로 교과서 모델을 그대로 특정 OS 구현이라고 부르지 않겠습니다. 같은 작업 도착 순서와 실행 길이로 정책을 시뮬레이션하고, 평균만 아니라 최장 대기와 전환 횟수를 비교하겠습니다.

## 득점 포인트

- 정책별 실행 순서와 목표를 구분한다.
- 짧은 작업 우선의 예측·기아 문제를 설명한다.
- 평균과 반응성·공정성을 함께 비교한다.

## 감점 포인트

- SJF는 실제 실행 시간을 항상 안다고 말한다.
- FCFS는 긴 작업의 영향을 받지 않는다고 말한다.
- 교과서 정책을 현재 모든 OS의 정확한 구현으로 단정한다.

## 더 파고들 거리

- SRTF는 실행 중 더 짧은 작업이 오면 어떻게 하나요?
- 작업 길이를 과거 기록으로 예측할 때 어떤 오차가 생기나요?
- 우선순위와 공정성을 함께 보장하려면 무엇이 필요할까요?
