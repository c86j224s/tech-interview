# 동시에 최대 10개 작업만 허용하려 합니다. 뮤텍스와 세마포어는 어떻게 다르게 쓰이나요?

## 구두 답변

뮤텍스는 보통 한 실행 흐름이 공유 상태를 독점하게 하는 소유권 기반 잠금이고, 세마포어는 사용 가능한 허가 수를 세어 동시 진입을 제한합니다. 한 번에 한 명만 들어가는 임계 구역과 최대 10개 작업을 진행시키는 제한은 목적이 다릅니다.

세마포어가 10개의 허가를 가지면 작업 시작 전에 하나를 얻고 종료 때 돌려줍니다. 오류나 취소 경로에서 반환하지 않으면 실제 작업은 없는데도 모두 대기하는 허가 누수가 생깁니다. 반대로 얻지 않은 허가를 반환하면 제한보다 많은 작업이 들어갈 수 있습니다.

세마포어가 여러 작업을 허용한다고 공유 데이터 수정까지 안전한 것은 아닙니다. 그 데이터는 별도 잠금이나 소유권 규칙이 필요합니다. 이진 세마포어와 뮤텍스도 소유 스레드·해제 규칙·우선순위 처리 등이 같다고 일반화하지 않겠습니다. 저는 제한하려는 자원과 허가 수명을 명확히 정하고, 예외·조기 취소·대기 취소에서 수가 복구되는지 테스트하겠습니다.

## 득점 포인트

- 소유 잠금과 허가 개수를 구분한다.
- 취득·반환의 수명과 누수를 설명한다.
- 동시성 제한과 데이터 보호를 분리한다.

## 감점 포인트

- 세마포어를 쓰면 내부 데이터도 자동 안전하다고 말한다.
- 이진 세마포어와 뮤텍스의 계약이 항상 같다고 말한다.
- 성공 경로에서만 허가를 반환한다.

## 더 파고들 거리

- 세마포어 대기 중 취소됐는지 허가를 얻은 뒤 취소됐는지 어떻게 구분할까요?
- FIFO가 아닌 허가 분배에서 기아를 어떻게 막을까요?
- 서로 다른 비용의 작업에 가중 허가를 주려면 어떻게 할까요?
