# 여러 스레드가 공유 큐에 넣고 꺼내며 큐가 비었을 때 기다립니다. 모니터는 공유 상태·상호 배제·조건 대기를 어떻게 묶어 관리하나요?

## 구두 답변

모니터는 공유 상태와 그 상태를 다루는 연산, 상호 배제와 조건 대기를 한 구조로 묶어 설명하는 동기화 추상화입니다. 언어나 라이브러리가 이를 직접 지원하기도 합니다. 핵심은 공유 상태에 접근하는 경로가 같은 규칙을 따르도록 만드는 것입니다.

작업 큐 모니터라면 put과 take가 큐의 내부 잠금 아래에서 실행되고, 비어 있으면 take가 조건을 기다립니다. 대기하면서 잠금을 놓아야 생산자가 들어와 작업을 넣을 수 있습니다. 깨어난 뒤 조건을 다시 확인해야 하는지는 모니터의 알림 의미에 달려 있으며, Java나 일반적인 조건 변수의 Mesa식 동작에서는 재검사가 필요합니다.

저는 모니터라고 이름 붙였다는 이유로 외부 참조까지 안전하다고 보지 않겠습니다. 내부 컬렉션을 그대로 반환해 호출자가 잠금 없이 수정하면 보호가 깨집니다. 긴 외부 호출을 잠금 안에 넣는 것도 경합과 교착을 만들 수 있습니다. 테스트는 빈 큐·가득 찬 큐·종료와 재진입을 포함해 잠금 규칙을 우회하는 경로가 없는지 확인하겠습니다.

## 득점 포인트

- 상태·연산·상호 배제·대기를 묶는 의미를 설명한다.
- 대기 중 잠금 해제와 재검사를 연결한다.
- 외부 참조와 긴 호출의 한계를 확인한다.

## 감점 포인트

- 모니터면 모든 외부 사용도 자동 동기화된다고 말한다.
- 대기하면서 잠금을 계속 소유해도 된다고 말한다.
- 모든 언어의 signal 의미가 같다고 말한다.

- 모니터 내부에서 사용자 콜백을 호출하면 어떤 재진입이 생길까요?
