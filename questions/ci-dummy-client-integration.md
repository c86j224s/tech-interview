# 서버 리팩토링을 검증하는 더미 클라이언트는 부하 도구와 무엇이 다른가요?

## 구두 답변

부하 도구는 처리량과 지연을 측정하는 목적이 크고, 더미 클라이언트 기반 통합 테스트는 실제 프로토콜과 상태 전이가 이전 계약을 유지하는지 확인하는 데 쓸 수 있습니다. 많은 접속을 만든다는 공통점은 있지만 성공 기준은 다릅니다.

로그인·캐릭터 생성·이동·전투·재접속을 일정한 시나리오로 실행하고 서버 응답과 최종 상태의 불변식을 검사하겠습니다. 단순히 연결이 끊기지 않았다는 것보다 중복 보상이나 세션 유실이 없는지가 중요합니다. 테스트 데이터와 난수 시드, 시간 의존성을 통제해 실패를 재현할 수 있게 해야 합니다.

실제 클라이언트와 프로토콜 구현을 일부 공유하면 편하지만 같은 버그를 양쪽이 함께 갖고 통과할 수 있습니다. 중요한 직렬화와 경계 조건은 독립적인 계약 테스트도 두겠습니다. CI에서는 짧고 결정적인 핵심 시나리오를 먼저 실행하고 긴 부하·장애 테스트를 별도 단계로 나눌 수 있습니다. 리팩토링 전후 성능뿐 아니라 관찰 가능한 행동이 유지되는지를 기준으로 검증하겠습니다.

## 득점 포인트

- 성능 시험과 동작 계약 검증을 구분한다.
- 상태 불변식과 재현 정보를 기록한다.
- 공유 구현의 맹점과 CI 범위를 다룬다.

## 감점 포인트

- 접속 성공이면 모든 통합 동작이 맞다고 말한다.
- 서버와 같은 코드로 검증하니 오류를 놓칠 수 없다고 말한다.
- 불안정한 긴 테스트만 매 커밋에 무조건 실행한다.

## 더 파고들 거리

- 서버 패킷 순서가 비결정적일 때 테스트 기대값은 어떻게 표현할까요?
- 과거 패킷 로그 재생과 상태 기반 시나리오는 어떤 차이가 있나요?
- 실패한 테스트의 월드 상태를 작게 축소해 재현하려면 어떻게 할까요?
