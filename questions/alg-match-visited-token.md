# Kuhn 알고리즘에서 각 시작 정점마다 visited를 초기화하지 않고 timestamp token을 쓰는 이유는 무엇인가요?

## 구두 답변

Kuhn의 한 번의 augmentation DFS 안에서는 같은 오른쪽 정점을 반복 방문하지 않아야 순환과 중복 재귀를 막을 수 있습니다. 하지만 다음 시작 정점의 DFS에서는 매칭이 이미 달라졌기 때문에 과거 탐색에서 방문한 정점을 다시 시도해야 합니다. `seen[v]`에 boolean을 영구 저장하는 대신 탐색마다 `attempt`를 증가시키고, `seen[v] == attempt`일 때만 이번 DFS의 방문으로 간주하는 timestamp token을 쓰면 이 두 요구를 동시에 만족합니다.

예를 들어 `attempt=7`에서 `R2`를 방문해 `seen[R2]=7`이 되었다고 하겠습니다. 현재 DFS가 끝난 뒤 새 왼쪽 정점에서 `attempt=8`로 시작하면 `seen[R2]=7`은 현재 세대가 아니므로 R2를 다시 검사합니다. 이때 매칭 배열에는 직전 augmentation의 재배치가 반영되어 있으므로, 과거에는 막혔던 상대가 새 증가 경로의 일부가 될 수 있습니다. 반대로 같은 attempt 안에서 재방문을 허용하면 `L1→R1→old L→R1` 같은 순환성 탐색이 생길 수 있습니다.

토큰은 매번 배열 전체를 false로 채우는 비용을 줄이는 구현 기법이기도 합니다. 다만 정수 토큰이 언젠가 래핑될 수 있으므로, 충분히 큰 타입을 쓰거나 포화 시 `seen` 전체를 0으로 초기화해야 합니다. 전역 visited를 영구 유지하면 정확성 문제가 생기고, 매번 전체 배열을 초기화하면 정확성은 유지되지만 시작 정점 수와 오른쪽 정점 수가 큰 경우 초기화 비용이 추가됩니다.

토큰의 정확한 범위는 구현에 따라 오른쪽 정점 또는 왼쪽 정점이지만, “한 번의 증가 시도에서만 순환을 차단한다”는 범위는 바뀌지 않습니다. 예를 들어 `R1`이 `L0`와 매칭되고 `L1`이 `R1`을 요청하면 `L0`를 재귀 호출합니다. 같은 시도에서 `R1`을 다시 허용하면 `L0`가 또 `R1`을 요청하는 고리가 생깁니다. 반대로 `L1` 시도가 실패한 뒤 매칭이 다른 시작점에서 바뀌었다면 token을 새로 발급해야 새 경로를 볼 수 있습니다. 전체 배열 초기화는 정확하지만 매번 오른쪽 정점 수만큼 쓰기 작업을 하며, token 방식은 보통 시도당 실제 방문분만 기록합니다.


## 득점 포인트

- 방문의 범위를 “한 augmentation DFS”로 한정하고 다음 DFS에서 재사용하지 않는다고 설명한다.
- `seen[R2]=7`과 `attempt=8`의 비교로 재방문 허용을 구체적으로 보인다.
- token은 시간 최적화일 뿐 매칭 갱신 불변식을 대체하지 않는다고 말한다.

## 감점 포인트

- 한 번 방문한 정점은 전체 실행에서 다시 보면 안 된다고 말한다.
- token을 바꾸면 매칭 배열도 자동으로 초기화된다고 가정한다.
- 토큰 래핑 또는 boolean 배열 초기화 비용을 전혀 고려하지 않는다.

## 더 파고들 거리

- 오른쪽 정점이 아니라 왼쪽 정점을 방문 표식으로 삼는 구현에서 순환 방지 범위가 어떻게 달라지는지 비교해 보세요.
- 실패한 DFS에서 기록한 방문 표식을 다음 성공 시도에 재사용하면 어떤 경로를 놓칠 수 있는지 작은 그래프로 설명해 보세요.
