# 두 지역이 같은 문서를 독립적으로 수정했을 때 Lamport 시계와 벡터 시계는 무엇을 알 수 있고 무엇을 결정하지 못하나요?

## 구두 답변

Lamport 시계는 각 이벤트에 논리 번호를 붙여 인과관계가 앞선 이벤트보다 뒤의 이벤트가 작은 번호를 갖지 않도록 합니다. A 이벤트의 정보를 받은 뒤 B 이벤트가 발생했다면 A→B라는 인과관계가 있으므로 `L(A) < L(B)`가 됩니다. 반대로 숫자가 더 크다는 사실만으로 두 이벤트 사이에 실제 인과관계가 있었다고 역으로 판단할 수는 없습니다.

벡터 시계는 참여자별 진행 번호를 저장합니다. 한 버전의 모든 성분이 다른 버전보다 작거나 같고 적어도 하나가 작으면, 작은 벡터가 선행하고 큰 벡터가 후속입니다. 어느 쪽도 다른 쪽보다 모든 성분이 작거나 같지 않으면 서로의 변경을 보지 못한 동시 변경입니다.

| 비교 예 | 해석 |
| --- | --- |
| `[1,0]`과 `[0,1]` | 어느 쪽도 선행하지 않는 동시 변경 |
| `[1,0]`과 `[1,1]` | `[1,0]`이 선행하고 `[1,1]`이 후속 |

두 지역이 같은 문서를 독립적으로 수정하면 벡터 비교 결과를 병합·충돌 UI·사용자 확인으로 보낼 수 있습니다. 그러나 시계는 충돌을 감지할 뿐 문장이나 필드를 자동으로 합치지 않습니다. 참여자 수와 동적 membership(참여 노드가 들어오고 나가는 변화)이 커지면 벡터 메타데이터와 정리 정책의 비용도 커집니다. 오래된 참여자의 항목을 너무 일찍 지우면 동시 변경을 잘못된 선후 관계로 볼 수 있습니다. 단일 권위 저장소에서 순서를 정할 수 있다면 단순 버전이 더 적합할 수 있습니다. 메시지 지연과 독립 수정, 인과적 수정, 동시 수정 후 병합을 재현해 시계의 판정과 실제 콘텐츠 병합을 별도로 검증하겠습니다.

## 득점 포인트

- Lamport의 인과관계 보존과 역추론 불가를 명확히 한다.
- 벡터 비교의 포함 관계와 동시성 판정을 사례로 설명한다.
- 시계와 콘텐츠 병합 정책 및 메타데이터 비용을 분리한다.

## 감점 포인트

- Lamport 숫자의 대소가 곧 원인·결과라고 말한다.
- 벡터 시계가 충돌 내용을 자동 병합한다고 말한다.
- 참여자 증가에 따른 벡터 크기와 membership 비용을 무시한다.
