# 목록의 중간에 항목을 자주 삽입해 성능을 개선하려 합니다. 배열을 연결 리스트로 바꾸기 전에 삽입 위치를 찾는 방식과 조회 패턴을 왜 확인해야 하나요?

## 구두 답변

중간 삽입이 많다는 사실만으로 연결 리스트를 선택하지는 않겠습니다. 연결 리스트가 유리한 것은 삽입할 노드의 위치를 이미 알고 있고, 그 노드를 찾는 비용과 순회 비용이 감당될 때입니다. 위치가 인덱스로 주어지거나 조건을 검사하며 앞에서부터 찾아야 한다면 탐색 비용까지 포함해야 합니다. 반대로 배열은 중간 원소를 이동해야 하지만 연속 메모리와 캐시 지역성을 활용하므로 작은 원소를 많이 순회하는 실제 작업에서는 더 빠를 수 있습니다.

### 조회 패턴과 메모리 비용을 함께 봅니다

배열에서 i번째 위치에 넣으면 뒤 원소를 한 칸씩 옮겨야 하므로 이동량이 커질수록 비용이 증가합니다. 연결 리스트는 대상 노드의 앞뒤 링크만 바꾸면 되지만, i번째 노드를 찾는 과정은 앞에서부터 따라가야 합니다. 따라서 ‘중간 삽입 O(1)’이라는 말은 반복자나 노드 포인터를 이미 갖고 있다는 조건부 설명입니다. 따라서 위치를 찾는 시간과 실제 구조 변경 시간을 합산해 자료구조를 비교해야 합니다.

예를 들어 메시지 목록에서 우선순위가 낮아지는 지점을 찾아 새 항목을 넣는다면, 매번 선형 탐색을 한 뒤 연결하는 구조는 배열의 이동 비용을 피했을 뿐 전체 비용을 없애지 못합니다. 반대로 편집기가 커서가 가리키는 노드나 반복자를 유지하고 그 주변에 삽입한다면 리스트의 장점이 분명해집니다. 다만 삽입·삭제로 반복자나 인덱스가 무효화되는 규칙은 언어와 구현마다 확인해야 합니다.

### 실제 접근 패턴으로 선택합니다

배열은 임의 위치 조회와 순차 순회에 강하고, 연결 리스트는 링크를 알고 있는 국소적인 삽입·삭제에 강합니다. 노드마다 포인터와 별도 할당 정보가 붙기 때문에 리스트는 메모리 사용량과 캐시 누락이 늘 수 있습니다. 원소가 큰 객체라면 데이터를 직접 옮기는 배열 대신 객체 포인터 배열을 두는 절충도 가능합니다. 이 경우 이동은 포인터 크기만큼 줄지만 간접 참조가 추가됩니다.

저는 실제 삽입 위치를 얻는 방법, 조회와 순회의 비율, 원소 크기, 삭제 빈도, 메모리 할당기를 함께 측정하겠습니다. 배열의 이동량만 세거나 리스트의 링크 변경만 세면 판단이 틀릴 수 있습니다. 임의 조회가 많으면 배열 또는 균형 트리를, 양끝 작업이 많으면 deque를 검토하겠습니다. 테스트는 정렬·역정렬 입력, 중간 삽입, 반복자 보존, 빈 목록과 마지막 위치를 포함해 총 처리 시간과 최대 지연을 비교하겠습니다.

추가로 메모리 관리 방식도 선택의 일부입니다. 리스트의 각 노드가 개별 할당되면 할당기 경합과 단편화가 생길 수 있고, 노드 풀을 사용하면 지역성은 개선되지만 풀 고갈과 회수 시점이 필요합니다. 배열은 재배치 때 큰 연속 영역이 필요하므로 메모리가 조각난 환경에서 확장이 실패할 수 있습니다. 읽기 전용 순회가 많은 목록이면 한 번 구성한 연속 배열과 별도 위치 색인을 두는 편이 링크 포인터보다 단순할 수 있습니다. 결국 “삽입이 많다”를 삽입 위치를 알고 있는지, 같은 항목을 얼마나 자주 다시 읽는지, 객체 수명이 어떻게 관리되는지로 풀어 써야 정확한 선택이 됩니다.

반복자가 있는 이중 연결 리스트에서는 노드 삭제가 상수 시간일 수 있지만 단일 연결 리스트는 직전 노드도 알아야 합니다. 삭제할 노드만 알고 다음 값을 복사하는 편법은 마지막 노드에서 불가능하고 객체 정체성도 바꾸므로 일반 해법이 아닙니다. API가 어떤 핸들을 제공하는지부터 확인하겠습니다.

## 득점 포인트

- 삽입 위치를 찾는 비용과 이미 위치를 아는 뒤의 링크 변경 비용을 분리한다.
- 배열의 이동 비용뿐 아니라 연속 메모리·캐시 지역성과 리스트의 할당·포인터 비용을 비교한다.
- 조회·순회·반복자 무효화·원소 크기를 포함한 실제 접근 패턴으로 자료구조를 선택한다.

## 감점 포인트

- 중간 삽입이면 연결 리스트가 항상 O(1)이라고 단정하고 위치 탐색 조건을 빠뜨린다.
- 배열의 원소 이동만 보고 캐시 지역성과 포인터 간접 참조 비용을 무시한다.
- 삽입·삭제 뒤에도 모든 인덱스나 반복자가 계속 유효하다고 가정한다.

## 더 파고들 거리

- 원소 대신 포인터를 배열에 저장할 때 이동 비용과 캐시 비용이 어떻게 맞바뀌는지 설명해 보세요.
- 반복자를 오래 보관하는 자료구조에서 삽입·삭제가 참조를 무효화하는 조건을 비교해 보세요.
- 양끝 삽입·삭제와 임의 위치 조회가 함께 필요할 때 deque와 균형 트리를 어떻게 구분할지 말해 보세요.
