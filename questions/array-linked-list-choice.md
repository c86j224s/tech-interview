# 목록의 중간에 항목을 자주 삽입해 성능을 개선하려 합니다. 배열을 연결 리스트로 바꾸기 전에 삽입 위치를 찾는 방식과 조회 패턴을 왜 확인해야 하나요?

## 구두 답변

연결 리스트는 삽입할 위치의 노드를 이미 알고 있다면 주변 링크만 바꿀 수 있습니다. 하지만 몇 번째 위치인지 찾아야 한다면 앞에서부터 따라가는 탐색 비용이 먼저 듭니다. 중간 삽입이 빠르다는 설명에는 위치를 알고 있다는 전제가 있습니다.

배열은 중간을 비우기 위해 뒤 원소를 이동하지만 연속 메모리를 읽어 캐시를 활용하기 좋습니다. 연결 리스트는 노드별 할당과 포인터 추적이 필요해서 이론적인 연산 수가 적어도 실제로 느릴 수 있습니다. 예를 들어 목록에서 조건에 맞는 항목을 찾아 삽입한다면 탐색과 삽입을 합쳐 비교해야 합니다.

저는 임의 위치 조회, 순회, 삽입 위치를 얻는 방법, 원소 크기를 먼저 확인하겠습니다. 반복자나 포인터를 유지해야 한다면 변경 시 무효화 규칙도 중요합니다. 실제 요청 패턴으로 할당 횟수와 전체 처리 시간을 비교하겠습니다. 자료구조 선택은 삽입 한 줄의 복잡도가 아니라 위치 탐색부터 결과 사용까지의 비용으로 해야 합니다.

## 득점 포인트

- 위치 탐색과 링크 변경 비용을 구분한다.
- 연속 메모리와 노드 할당의 차이를 설명한다.
- 조회·순회·무효화까지 함께 비교한다.

## 감점 포인트

- 연결 리스트 중간 삽입은 언제나 전체 O(1)이라고 말한다.
- 배열 이동 비용만 보고 캐시와 할당을 무시한다.
- 원소 포인터가 변경 후에도 항상 유효하다고 가정한다.

## 더 파고들 거리
