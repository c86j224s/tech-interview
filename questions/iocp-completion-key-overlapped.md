# 한 소켓에서 수신과 송신을 동시에 제출했습니다. IOCP 완료를 받을 때 어느 연결의 어느 작업인지 completion key와 OVERLAPPED로 어떻게 구분하나요?

## 구두 답변

completion key는 보통 완료 포트에 연결한 핸들의 맥락을, OVERLAPPED는 개별 비동기 작업의 맥락을 찾는 데 사용합니다. 같은 소켓에서 여러 작업을 제출할 수 있으므로 연결과 작업을 구분해야 합니다. 키 하나만으로 수신인지 송신인지, 어느 버퍼의 완료인지 알 수 있다고 가정하지 않겠습니다.

completion key는 핸들을 완료 포트에 연결할 때 정하는 값이고, OVERLAPPED는 각 중첩 I/O 제출 때 전달하는 작업별 구조체입니다. 다음처럼 한 연결의 여러 작업이 같은 연결 키를 공유하면서 서로 다른 작업 구조체를 가질 수 있습니다.

| 작업 | completion key | OVERLAPPED 주소 |
|---|---|---|
| 연결 A의 수신 | 연결 A를 찾는 키 | 수신 컨텍스트의 주소 |
| 연결 A의 송신 | 같은 연결 A 키 | 송신 컨텍스트의 주소 |

OVERLAPPED 자체에 모든 업무 필드가 들어 있는 것은 아닙니다. 보통 이를 포함한 사용자 작업 컨텍스트에 종류와 버퍼를 보관합니다.

연결 객체를 completion key와 연결하고, 작업마다 OVERLAPPED를 포함한 컨텍스트에 작업 종류와 버퍼를 보관하는 구성이 가능합니다. 완료를 받으면 연결을 찾고 작업 컨텍스트로 돌아가 반환 바이트 수와 오류를 해석합니다. 같은 OVERLAPPED를 미완료 작업 여러 개에 재사용하면 결과를 구분할 수 없고 메모리가 손상될 수 있습니다.

중요한 것은 포인터를 키에 넣었다고 객체가 자동으로 살아 있는 것은 아니라는 점입니다. 종료 중에도 미완료 작업이 남았다면 연결과 컨텍스트의 수명을 유지해야 합니다. 저는 제출·완료·정리를 작업 ID로 기록해 누락과 이중 해제를 점검하겠습니다. 핸들 식별과 개별 작업 식별을 분리하면 수신·송신·종료가 겹치는 서버의 상태를 훨씬 명확하게 관리할 수 있습니다.

## 득점 포인트

- **연결과 작업을 구분한다.** 키와 OVERLAPPED의 역할을 설명한다.
- **작업별 컨텍스트를 유지한다.** 종류·버퍼·결과를 연결한다.
- **포인터 수명을 별도로 보장한다.** 키가 소유권을 만들지 않음을 짚는다.

## 감점 포인트

- **키 하나가 모든 I/O를 구분한다고 말한다.** 여러 작업이 같은 핸들에서 진행된다.
- **미완료 작업에 OVERLAPPED를 재사용한다.** 상태가 섞일 수 있다.
- **키에 저장하면 객체가 자동 유지된다고 말한다.** 수명은 애플리케이션 책임이다.

## 더 파고들 거리

- 작업별 참조와 연결별 참조는 언제 획득·해제할까요?
- 사용자 정의 완료 패킷과 커널 I/O 완료는 어떻게 구분할까요?
