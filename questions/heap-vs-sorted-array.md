# 우선순위가 있는 작업을 계속 추가하면서 가장 작은 값의 작업부터 꺼내려 합니다. 힙과 정렬된 배열의 삽입·조회·삭제 비용을 어떻게 비교하나요?

## 구두 답변

최소 힙은 부모가 자식보다 크지 않다는 부분적인 순서만 유지합니다. 그래서 루트가 최솟값인 것은 알지만 배열 전체가 정렬된 상태는 아닙니다. 정렬된 배열은 모든 원소의 순서를 알고 있는 대신 새 값을 넣을 때 자리를 만들 비용이 생길 수 있습니다.

최소 힙에서 루트를 꺼내면 마지막 원소를 루트로 옮기고 자식과 비교해 내려보내며 규칙을 복구합니다. 새 원소는 끝에 넣고 부모와 비교하며 올립니다. 높이가 로그 수준인 완전 이진 트리 형태를 배열로 표현하므로 최솟값 조회는 O(1), 삽입과 추출의 재정렬은 O(log n)입니다. 배열 확장이 발생하는 삽입은 별도의 복사 비용이 들 수 있습니다. 반면 정렬된 배열은 삽입 위치를 이진 탐색해도 뒤 원소 이동에 O(n)이 들 수 있습니다. 최솟값을 배열 끝에 두면 추출은 O(1)로 할 수 있으므로, 새 작업이 계속 들어오는지 미리 정렬한 것을 꺼내기만 하는지에 따라 선택이 달라집니다.

반면 힙에서 임의의 값이나 특정 사용자의 순위를 찾는 것은 별도 인덱스가 없으면 빠르지 않습니다. 저는 다음 실행 작업 선택처럼 최우선 항목을 반복 추출하는 용도에 쓰고, 범위 조회나 전체 순위가 필요하면 정렬 구조를 비교하겠습니다. 테스트는 동일 우선순위의 처리 규칙과 우선순위 변경을 포함합니다. 힙 안의 객체 값만 바꾸고 재정렬하지 않으면 구조가 깨질 수 있습니다.

## 득점 포인트

- 부분 순서와 전체 정렬을 구분한다.
- 삽입·추출의 규칙 복구를 설명한다.
- 임의 조회와 변경의 한계를 다룬다.

## 감점 포인트

- 힙 배열을 앞부터 읽으면 정렬돼 있다고 말한다.
- 모든 값의 검색도 로그 시간이라고 말한다.
- 우선순위 필드만 바꾸고 힙을 갱신하지 않는다.
