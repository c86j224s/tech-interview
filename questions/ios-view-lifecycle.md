# 화면으로 돌아올 때 `viewDidLoad`의 갱신 코드가 다시 실행되지 않습니다. `viewDidLoad`, `viewWillAppear`, `viewDidAppear`를 어떻게 나눠야 하나요?

## 구두 답변

`viewDidLoad`는 뷰 컨트롤러의 뷰가 처음 로드된 뒤 한 번 초기화할 때 쓰는 지점이고, `viewWillAppear`와 `viewDidAppear`는 화면이 다시 나타날 때마다 호출될 수 있는 지점입니다. 그래서 버튼 연결, 정적 제약 조건, 데이터 소스 설정처럼 뷰 자체에 한 번만 필요한 준비는 `viewDidLoad`에 둡니다. 다른 화면에서 바뀐 프로필이나 목록을 다시 읽어 화면에 반영하는 코드를 여기에만 두면, 뒤로 돌아왔을 때 오래된 값이 남습니다.

`viewWillAppear`는 전환 애니메이션이 끝나기 전에 화면이 나타날 예정임을 알리는 단계입니다. 화면에 들어올 때마다 최신 상태를 반영하거나, 내비게이션 바 설정을 갱신하거나, 관찰을 시작하는 작업에 적합합니다. 다만 이 메서드가 다시 호출될 때마다 서브뷰를 추가하거나 배열에 항목을 append하면 중복이 생깁니다. 반복 실행되어도 같은 결과가 되도록 기존 상태를 대체하고, 관찰자 등록은 등록 여부를 관리하거나 사라질 때 해제해야 합니다.

`viewDidAppear`는 실제 표시 전환이 끝난 뒤 실행되므로 첫 화면 안내, 화면을 기준으로 하는 애니메이션, 사용자에게 보여야 하는 측정 시작처럼 보임이 전제인 작업을 둡니다. 네트워크 응답을 받는 시점과 화면 표시 시점이 엇갈릴 수 있으므로, 비동기 결과를 무조건 화면에 적용하지 말고 현재 뷰 컨트롤러가 여전히 유효한지와 요청 세대가 같은지 확인해야 합니다. 반대로 화면이 사라질 때 취소해야 하는 작업은 `viewWillDisappear` 또는 더 명확한 화면 소유자 수명에 맞춰 정리합니다.

이 구분은 호출 횟수를 외우는 문제가 아니라 상태의 소유권과 반복 가능성을 정하는 문제입니다. 화면이 메모리에서 해제된 뒤 다시 로드되면 `viewDidLoad`도 다시 호출될 수 있으므로 영원히 한 번이라는 뜻은 아닙니다. 한 번만 만들어야 하는 모델이나 서비스는 뷰 컨트롤러의 뷰 수명과 분리하고, 화면에 들어올 때마다 필요한 표현 갱신만 등장 생명주기에 연결하면 중복과 오래된 데이터 문제를 함께 줄일 수 있습니다.

## 득점 포인트

- 초기 뷰 구성과 재등장 때의 데이터 갱신을 `viewDidLoad`와 `viewWillAppear`로 구분한다.
- 반복 호출 지점에서 서브뷰·옵저버·타이머가 중복 생성되지 않도록 멱등성과 정리 시점을 설명한다.
- `viewDidAppear`는 실제 표시 이후라는 전제에 맞는 애니메이션과 사용자 노출 작업에 선택한다.

## 감점 포인트

- `viewDidLoad`가 앱 실행 중 항상 정확히 한 번만 호출된다고 단정한다.
- 화면이 다시 나타날 때마다 `viewWillAppear`에서 서브뷰나 옵저버를 무조건 추가한다.
- 비동기 응답이 도착하면 화면이 이미 사라졌거나 다른 요청이 최신이어도 그대로 반영한다.
