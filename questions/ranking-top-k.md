# 실시간 게임 랭킹에서 상위 K명, 임의 사용자의 순위, 보상 확정을 각각 어떤 자료구조와 기준으로 처리하나요?

## 구두 답변

먼저 필요한 조회를 나눕니다. 상위 K명만 주기적으로 계산하면 전체 점수를 훑으며 크기 K의 최소 힙을 유지할 수 있고, 전체 정렬보다 메모리와 비교 비용을 줄일 수 있습니다. 반면 임의 사용자의 정확한 순위나 주변 순위가 필요하면 힙만으로는 부족하므로 정렬 인덱스, 순서 통계 트리, 또는 미리 계산한 구간별 순위를 검토해야 합니다.

점수 갱신에서는 이전 값을 정확히 제거하고 새 값을 반영해야 하며, 동점이면 점수 외의 안정적인 키를 정해야 합니다. 예를 들어 `(점수 내림차순, 달성 시각 오름차순, 사용자 ID)`를 하나의 비교 규칙으로 고정하면 페이지를 넘길 때 순서가 흔들리지 않습니다. 중복 이벤트를 `INCR`로 그대로 더하면 재전달 때 점수가 부풀 수 있으므로 이벤트 ID나 버전으로 중복을 막거나 최종 절대 점수와 순서를 비교하겠습니다.

실시간 화면은 몇 초의 지연과 캐시를 허용할 수 있지만, 보상은 조회 순간의 움직이는 자료구조를 기준으로 삼으면 안 됩니다. 마감 시점의 집계 버전을 봉인하고 그 버전에서 top-K와 보상 대상을 계산해야 합니다. 샤드 병합이라면 같은 버전과 동점 규칙을 모든 샤드에 적용합니다.

검증은 대규모 동점, 점수 역전, 중복·지연 이벤트, 페이지 경계 갱신을 재현합니다. 성능은 평균 조회 시간만이 아니라 갱신 지연, 메모리, 보상 확정의 재현성까지 함께 평가하겠습니다.

## 득점 포인트

- 조회 요구에 따라 힙·정렬 인덱스·순서 통계를 구분한다.
- 동점 키와 중복 점수 이벤트 처리의 일관성을 설명한다.
- 실시간 표시와 보상 확정 버전을 분리한다.

## 감점 포인트

- 힙 하나로 임의 사용자의 정확한 순위까지 빠르게 제공한다고 말한다.
- 동점 규칙을 생략해 페이지 결과가 안정적이라고 말한다.
- 중복 점수 이벤트를 그대로 누적한다.

## 더 파고들 거리

- 샤드별 후보를 병합할 때 사용자 중복을 어떻게 제거하나요?
- 점수와 시간 우선순위를 안정적인 키로 어떻게 표현하나요?
- 확정 버전 생성 중 들어온 점수는 어느 집계에 넣나요?
