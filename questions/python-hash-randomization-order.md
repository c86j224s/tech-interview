# Python set 순회 결과가 실행마다 달라집니다. 해시 무작위화와 결정적 출력은 어떻게 다루나요?

## 구두 답변

set의 순서를 안정적인 외부 계약으로 사용하면 안 됩니다. 해시와 내부 배치가 순회에 영향을 줄 수 있으며 보안상 해시 무작위화도 실행 간 차이를 만들 수 있습니다. 결정적 출력이 필요하면 명시적인 정렬 기준을 사용합니다.

### 동작 원리와 전제

dict의 삽입 순서 보장과 set의 순서는 구분합니다. 정렬할 때도 문자열 정규화·대소문자·동점 기준이 같아야 결과가 재현됩니다. 테스트를 통과시키려고 보안 관련 무작위화를 무조건 끄기보다 순서에 의존한 코드를 고칩니다.

### 선택과 실패 처리

해시값은 일반적으로 영구 저장 ID나 서버 간 안정적인 파티션 키로 사용하기에 맞지 않을 수 있습니다. 안정적인 해시 알고리즘과 바이트 직렬화 규칙을 별도로 고정합니다. 객체의 가변 필드가 hash·equality를 바꾸면 컬렉션 조회가 깨질 수 있습니다.

### 구체적인 사례와 검증

분산 캐시의 샤드 선택에 프로세스별 hash 값을 그대로 사용하면 서버마다 같은 키가 다른 목적지로 갈 수 있습니다. 안정적인 바이트 인코딩과 명시한 해시 함수를 사용하는 이유입니다. 반대로 테스트 출력 순서가 문제라면 seed를 고정해 원인을 재현할 수는 있지만 외부 결과의 정렬 계약을 고치는 것이 해결입니다. dict도 입력을 set에서 가져오면 삽입 순서 자체가 실행마다 달라질 수 있으므로 dict의 순서 보장만으로 결정성이 생기지 않습니다. 비교 기준과 입력 생성 경로를 함께 검증하고 저장된 ID·서명 입력에 런타임의 우연한 순회 순서를 사용하지 않겠습니다.

프로세스 재시작·다른 seed·입력 순서·동점 데이터를 시험합니다. 원소 집합만 필요한 테스트는 집합으로 비교하고 순서가 계약이면 정렬·보조 키를 검증합니다. 재현성과 보안 무작위화의 책임을 혼동하지 않겠습니다.

## 득점 포인트

- 핵심 구분: set의 순서를 안정적인 외부 계약으로 사용하면 안 됩니다.
- 선택 조건: 해시값은 일반적으로 영구 저장 ID나 서버 간 안정적인 파티션 키로 사용하기에 맞지 않을 수 있습니다.
- 검증 기준: 프로세스 재시작·다른 seed·입력 순서·동점 데이터를 시험합니다.

## 감점 포인트

- dict 삽입 순서 보장 때문에 set에서 만든 결과도 항상 같은 순서라고 한다.
