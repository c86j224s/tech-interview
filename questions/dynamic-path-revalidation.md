# NPC가 경로를 찾은 뒤 문이 닫히거나 목표가 바뀌었습니다. 기존 경로와 뒤늦게 도착한 탐색 결과를 어떻게 처리하나요?

## 구두 답변

경로를 찾을 때 유효했다는 것과 실제 이동할 때도 유효하다는 것은 다릅니다. 저는 경로 결과에 어떤 맵 버전과 이동 조건을 사용했는지 연결하고, 이동 실행 단계에서 가까운 구간의 유효성을 다시 확인하겠습니다. 월드 전체가 바뀔 때마다 모든 경로를 즉시 재탐색하면 비용이 과도해질 수 있습니다.

맵 버전은 탐색에 사용한 지형의 상태를, 요청 세대는 어느 이동 목표에 대한 탐색인지를 식별합니다. 문 변경이 없어도 목표가 바뀌면 이전 요청의 경로는 쓸모없을 수 있습니다. 반대로 목표가 같아도 통로가 막히면 경로 일부를 다시 검사해야 하므로 두 값을 같은 의미로 쓰지 않겠습니다.

문 하나가 닫혔다면 그 문을 지나는 경로만 무효화하는 것이 좋습니다. 경로가 지나가는 타일·영역의 버전을 추적하거나 변경 영역과 교차하는지 검사할 수 있습니다. 움직이는 다른 캐릭터 때문에 잠깐 막혔다면 전체 경로를 다시 찾기보다 대기나 지역 회피가 나을 수 있습니다. 정적 지형 변경과 일시 점유를 구분해야 합니다.

재탐색을 무제한 반복하면 막힌 지역의 많은 NPC가 동시에 CPU를 사용할 수 있어 요청 병합·쿨다운·예산을 둡니다. 오래된 비동기 경로 결과가 새 목표를 덮지 않도록 요청 세대도 확인하겠습니다. 테스트는 문 변경, 목표 변경, 좁은 통로 정체를 섞어 이동의 안전성과 재탐색량을 함께 보겠습니다. 정확성을 위해 검증은 남기되 어느 수준에서 다시 계산할지 비용에 맞춰 정하는 것이 핵심입니다.

## 득점 포인트

- 탐색 시점과 실행 시점을 구분한다.
- 변경 범위와 일시 점유를 나눈다.
- 세대·쿨다운·예산으로 재탐색 폭주를 막는다.

## 감점 포인트

- 한 번 찾은 경로는 도착까지 항상 유효하다고 말한다.
- 모든 위치 변화에 전체 A*를 실행한다.
- 늦은 결과가 새 목표를 덮는 경로를 무시한다.

## 더 파고들 거리

- 증분 경로 탐색은 어떤 변경에서 계산을 재사용할 수 있나요?
- 부분 경로 캐시의 무효화를 어떤 영역 단위로 할까요?
- 목표가 계속 움직일 때 재탐색 주기를 어떻게 정할까요?
