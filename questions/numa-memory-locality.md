# NUMA 서버에서 작업 스레드를 늘렸는데 처리량이 떨어졌습니다. 메모리 배치와 CPU 이동이 원인인지 어떻게 확인하나요?

## 구두 답변

NUMA 서버에서는 모든 CPU가 모든 메모리에 같은 비용으로 접근하지 않습니다. 스레드가 속한 NUMA 노드의 로컬 메모리는 상대적으로 빠르고, 다른 노드의 remote memory는 지연·대역폭 비용이 큽니다. 따라서 코어 수를 늘려도 작업과 데이터가 멀리 배치되거나 노드 간 coherence 트래픽이 커지면 처리량이 떨어질 수 있습니다.

예를 들어 한 초기화 스레드가 큰 배열을 모두 처음 접근하면 first-touch(페이지를 처음 만진 CPU의 NUMA 노드에 배치하는 정책)에서 페이지가 그 스레드의 노드에 몰릴 수 있습니다. 이후 다른 노드의 작업자가 배열을 처리하면 매번 원격 메모리를 읽어 스레드를 늘려도 느려질 수 있습니다. 노드별 메모리 사용량·remote access 비율·메모리 대역폭·스레드 migration을 관찰하고, 각 worker가 자기 구간을 초기화하는 방식과 비교하겠습니다. 작은 데이터가 LLC에 남는 벤치마크는 문제를 숨길 수 있습니다.

지역성이 병목이면 노드별 queue·pool과 조건부 affinity를 사용하되, 한 노드가 과부하인데 다른 노드가 놀면 고정이 오히려 손해입니다. workload가 균일한지에 따라 local-first 후 steal 정책을 검토하고, CPU pinning·메모리 interleave·page placement를 같은 실험에서 비교합니다. 원격 접근 감소가 실제 p99와 처리량 개선으로 이어지는지 실부하로 검증하겠습니다.

## 득점 포인트

- CPU 수와 NUMA 메모리 지역성의 차이를 설명한다.
- first-touch가 페이지 배치를 만드는 사례를 추가한다.
- affinity의 지역성 이득과 부하 불균형 비용을 조건부로 비교한다.

## 감점 포인트

- CPU affinity를 고정하면 항상 빨라진다고 말한다.
- NUMA 노드의 메모리 접근 비용이 모두 같다고 말한다.
- 작은 캐시 친화 벤치마크만으로 원격 메모리 결론을 낸다.

## 더 파고들 거리

- 노드별 pool 사이에 객체를 넘길 때 소유권·수명·해제 비용은 어떻게 달라지나요?
- 메모리 interleave와 작업별 local placement는 어떤 접근 패턴에서 각각 유리한가요?
- CPU를 이동시키는 것과 페이지를 이동시키는 것 중 무엇을 선택할지 어떤 측정이 필요한가요?
