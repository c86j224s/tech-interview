# 지상 이동·셀 단위 변경·3차원 구조가 각각 필요할 때 NavMesh·격자·복셀 중 어떤 경로 공간을 선택하나요?

## 구두 답변

세 표현은 같은 ‘길찾기’라는 이름을 쓰지만 경로 공간의 의미가 다릅니다. NavMesh는 이동 가능한 지표면을 다각형과 인접 포털로 표현해 지상 캐릭터가 넓은 공간을 적은 노드로 탐색하게 합니다. 격자는 공간을 일정한 셀로 나누므로 건설·파괴·셀 점유처럼 국소 변경을 반영하기 쉽습니다. 복셀은 3차원 부피를 표현하므로 층·터널·공중·파괴 가능한 구조를 자연스럽게 담지만 해상도에 따라 메모리와 갱신량이 커집니다. 선택은 기술 이름보다 **이동 공간 표현**(navigation-space representation)의 요구로 결정합니다.

### 선택 기준

평면 지상 이동이 주이고 지형이 자주 바뀌지 않으며 에이전트 반경·경사·계단 규칙이 중요하면 NavMesh를 우선 검토합니다. 다각형 수가 적어 긴 빈 복도를 한 노드씩 저장하지 않고, 포털을 통한 경로 후처리로 지그재그를 줄일 수 있습니다. 반면 셀 단위 건설·채굴·문 변경이 빈번하고 이동 규칙이 셀과 직접 연결된다면 격자가 갱신 단순성과 디버깅 이점을 가집니다. 해상도를 높이면 작은 통로를 표현할 수 있지만 셀 수와 탐색 비용이 늘어납니다. 층이 겹치거나 내부 공간·수직 이동·실제 부피 충돌이 핵심이면 복셀을 검토합니다. 복셀 하나가 비어 있어도 에이전트의 높이와 반경이 통과할 수 있다는 뜻은 아니므로 clearance와 에이전트 능력을 원본에서 파생해야 합니다. 큰 월드를 모두 고해상도로 유지하는 대신 희소 청크, 계층 그래프, 지역별 표현을 조합할 수 있습니다. 예를 들어 NavMesh로 지상 지역 간 연결을 찾고, 동굴 내부는 복셀이나 격자에서 세부 경로를 찾되 경계 포털이 실제로 이어지는지 확인합니다.

### 변경·실행 검증

각 표현은 원본 지형과 파생 데이터의 버전을 가져야 합니다. NavMesh가 굽는 동안 문이 바뀌거나 복셀 청크가 로딩되지 않았는데 빈 공간으로 처리하면 화면 경로와 서버 충돌 판정이 달라집니다. 경로 결과를 적용하기 전에 포털·셀·복셀의 현재 버전과 에이전트 크기를 확인하고, 실제 이동 중에는 동적 장애물과 충돌을 재검증하겠습니다. 탐색 결과의 길이만 비교하지 말고 이동 성공률, 충돌·재탐색률, 메모리, 갱신 지연, 경계 실패를 측정합니다. 테스트는 좁은 통로, 층간 연결, 동적 문, 파괴된 구조, 큰 에이전트, 청크 경계를 포함합니다. 하나의 표현이 모든 요구를 해결한다고 하지 않고, 변경 빈도와 3차원성·정밀도·서버 예산에 맞는 **계층적 경로 공간**(hierarchical navigation space)을 선택하겠습니다. 표현을 선택할 때 bake 비용과 런타임 변경의 책임도 포함해야 합니다.

NavMesh는 장애물 변경 때 지역 재베이크 범위를 관리하고, 격자는 해상도를 높일수록 정확성과 셀 갱신 비용이 함께 늘어납니다. 복셀은 원본을 보존하면서 충돌·시야·이동성 파생 데이터를 재생성해야 하므로 스트리밍과 버전 교체가 설계의 일부입니다. 계층 표현에서 상위 경로가 하위 공간의 통과 가능성을 자동 보장하지는 않습니다. 포털 후보를 선택한 뒤 하위 격자·복셀에서 입구와 출구 사이를 확인하고, 미로딩 영역은 빈 공간으로 간주하지 않겠습니다. 에이전트 크기가 다르면 같은 상위 연결도 하위 포털이 달라질 수 있습니다.

## 득점 포인트

- 표면·셀·부피 표현을 차원·변경 빈도·에이전트 조건과 연결한다.
- NavMesh의 포털, 격자의 갱신성, 복셀의 해상도·메모리 비용을 비교한다.
- 계층 경계의 버전·포털·실제 충돌 검증을 포함한다.

## 감점 포인트

- NavMesh가 모든 동적·3차원 맵에서 자동으로 최적이라고 말한다.
- 복셀 해상도와 2D 격자 비용이 같다고 가정한다.
- 탐색 결과를 서버의 크기·충돌 검증 없이 실행한다.

## 더 파고들 거리

- 지역별 표현을 연결하는 포털이 한쪽 버전만 최신일 때 경로를 언제 보류하나요?
