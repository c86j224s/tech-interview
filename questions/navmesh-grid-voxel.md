# 지상 이동·셀 단위 변경·3차원 구조가 각각 필요할 때 NavMesh·격자·복셀 중 어떤 경로 공간을 선택하나요?

## 구두 답변

격자는 공간을 일정한 셀로 나누어 장애물·건설·파괴를 셀 갱신으로 표현하기 쉽지만 해상도가 높아지면 셀 수와 탐색 비용이 커집니다. NavMesh는 이동 가능한 지표면을 다각형과 인접 포털로 표현하므로 평면 지상 이동에서 적은 노드로 넓은 공간을 다룰 수 있습니다. 복셀은 3차원 부피를 셀로 나타내 층·터널·공중·파괴 가능한 구조에 자연스럽지만 메모리와 갱신 범위가 큽니다.

평면 지상에서 장애물이 드물고 에이전트 크기가 다양하면 NavMesh와 통로 후처리가 유리할 수 있습니다. 셀 단위로 맵이 자주 바뀌면 격자, 실제 부피 충돌과 다층 구조가 중요하면 복셀을 검토합니다. 차원·변경 빈도·에이전트 반경·경로 정밀도·서버 예산을 먼저 정하고, 하나의 표현만 고집하지 않고 지역 연결용 거친 그래프와 내부 세부 공간을 계층적으로 결합할 수 있습니다.

표현 경계의 portal이 실제로 연결되는지, 각 표현의 버전과 충돌 규칙이 일치하는지 검증합니다. 좁은 통로·층간 이동·동적 문·큰 에이전트를 시험해 탐색 시간뿐 아니라 실제 이동·충돌 성공률과 메모리를 비교하겠습니다. 화면상 최단 경로가 서버의 이동 규칙을 만족한다는 보장은 없습니다.

## 득점 포인트

- 표면·셀·부피 표현의 차이를 선택 조건과 연결한다.
- 동적 변경과 에이전트 크기·차원·메모리 비용을 포함한다.
- 계층 공간의 경계 연결과 실제 충돌 검증을 강조한다.

## 감점 포인트

- NavMesh가 모든 동적 맵에서 자동으로 최적이라고 말한다.
- 복셀의 해상도와 2D 격자 비용이 같다고 말한다.
- 탐색 결과를 서버 충돌 검사 없이 신뢰한다.

## 더 파고들 거리

- NavMesh funnel은 portal을 통해 어떤 불필요한 꺾임을 제거하나요?
- 복셀 해상도를 낮추면 어떤 최소 통로와 층 정보를 잃나요?
- 여러 크기 에이전트가 같은 공간 표현을 안전하게 재사용하려면 무엇을 bake해야 하나요?
