# 192.0.2.64/26에서 192.0.2.127과 192.0.2.128은 같은 블록인가요?

## 구두 답변

같은 블록이 아닙니다. `/26`은 32비트 중 앞 26비트를 고정하므로 호스트 부분은 6비트이고 블록 크기는 `2^6=64`개입니다. 64 단위로 정렬하면 `192.0.2.64/26`의 범위는 `.64`부터 `.127`까지이며 `.127`이 마지막 주소입니다. `.128`은 다음 `/26` 경계의 시작입니다.

마지막 옥텟 mask는 `255.255.255.192`입니다. `.127 & 192 = .64`이고 `.128 & 192 = .128`이므로 두 주소의 network result가 다릅니다. 비트로는 `.127=01111111`, mask=`11000000`이라 AND 결과가 `01000000(.64)`이고, `.128=10000000`은 `10000000(.128)`이 됩니다. 이 계산은 prefix membership만 판정합니다. 특정 주소를 host에 배정할 수 있는지, 마지막 주소를 broadcast로 예약하는지, DHCP가 어떤 범위를 임대하는지는 별도의 운영 정책입니다. 실제 장비를 진단할 때는 route와 interface 설정에 `/26`이 정확히 설치되었는지도 확인해야 합니다. 예를 들어 `.127`을 broadcast로 예약하는 전통적인 subnet 사용 규칙을 적용하더라도, 그것이 `.128`과 같은 CIDR 블록이라는 뜻은 아닙니다. 먼저 mask로 네트워크 ID를 계산하고, 그 결과를 사용 가능 주소 정책과 분리해 기록하는 것이 경계 문제에서 가장 안전합니다. 추가로 `/26`의 경계는 마지막 옥텟 숫자를 단순히 64로 나누어 반올림하는 규칙이 아니라, 전체 32비트 주소와 mask의 결과로 결정됩니다. 앞 세 옥텟이 같다는 이 예에서는 숫자 계산이 직관과 맞지만, 다른 옥텟 경계의 `/26`에서는 같은 AND 절차를 적용해야 안전합니다.

## 득점 포인트

- `32-26=6`, `2^6=64`로 경계를 도출합니다.
- mask `255.255.255.192`와 AND 결과를 두 주소에 직접 적용합니다.
- 블록 소속과 host/broadcast 사용 정책을 분리합니다.

## 감점 포인트

- `/26`을 26개 주소로 해석합니다.
- `.127`과 `.128`이 같은 블록이라고 말합니다.
- prefix 계산만으로 사용 가능 주소 정책까지 확정합니다.

## 더 파고들 거리
