# 부모에 글자색을 지정하고 컴포넌트 스타일도 추가했는데 예상과 다른 색이 표시됩니다. 상속과 여러 스타일시트의 선언 중 어떤 값이 적용되는지 어떤 순서로 확인하나요?

## 구두 답변

CSS에서 같은 속성에 여러 선언이 있으면 단순히 선택자가 긴 규칙을 고르는 것이 아니라 cascade 순서로 승자를 정합니다. 먼저 브라우저·사용자·작성자 같은 출처와 `!important`, 애니메이션·트랜지션 여부를 보고, 그 조건이 같으면 레이어와 선택자의 specificity, 그 뒤 @scope를 사용했다면 스코프 근접성, 마지막으로 소스 순서를 비교합니다. 일반적인 작성자 규칙끼리 비교할 때는 ID 선택자가 클래스·속성·가상 클래스보다 강하고, 클래스 계열은 요소 선택자보다 강합니다. specificity가 같다면 뒤에 선언된 규칙이 이깁니다.

다른 출처·중요도·레이어 등의 조건이 같고 p가 .card 안에 있다면 다음 두 규칙 중 두 번째가 이깁니다.

```css
p { color: blue; }
.card p { color: green; }
```

`p`의 색상이 직접 지정되지 않았다면 부모의 `color`처럼 상속되는 속성은 자식으로 전달될 수 있지만, 모든 CSS 속성이 상속되는 것은 아닙니다. 상속은 자식에 직접 적용할 값이 없을 때 등의 규칙에 따라 부모의 값을 사용하는 경로이므로, 부모에 색상을 지정했다고 자식의 직접 선언을 덮을 수 있다고 생각하면 안 됩니다. `initial`, `inherit`, `unset` 같은 전역 값은 이 관계를 의도적으로 바꾸는 도구입니다.

실무에서는 specificity를 계속 높여 해결하기보다 낮고 예측 가능한 선택자와 cascade layer를 사용하겠습니다. `!important`를 반복하면 나중에 정상 규칙으로 되돌리기 어렵고, 컴포넌트 간 의존성이 숨겨집니다. 디버거에서 취소선이 그어진 선언만 볼 것이 아니라 출처·레이어·특이성·상속 여부를 순서대로 확인하면 왜 규칙이 적용되지 않았는지 판단할 수 있습니다.

따라서 ‘더 구체적인 선택자’라는 설명은 앞선 출처·중요도·레이어가 같다는 조건에서만 맞습니다. 같은 specificity라도 선언 순서가 바뀌면 결과가 바뀌므로 스타일시트 로딩 순서와 레이어 설계를 함께 관리하겠습니다.

## 득점 포인트

- cascade가 specificity보다 먼저 비교하는 조건이 있음을 설명한다.
- 상속되는 속성과 직접 선언의 우선 관계를 구분한다.
- 예측 가능한 선택자·레이어와 디버깅 순서를 제시한다.

## 감점 포인트

- 선택자가 긴 규칙은 항상 이긴다고 말한다.
- 모든 CSS 속성이 부모에서 자동 상속된다고 말한다.
- 해결책으로 무조건 ID나 `!important`를 추가한다.

## 더 파고들 거리

- :where와 :is가 specificity를 어떻게 다르게 계산하는지 비교해 보세요.
- cascade layer를 도입할 때 기존 스타일의 우선순위가 어떻게 바뀌나요?
- 상속되지 않는 속성과 `unset`·`inherit`의 결과를 실제 요소 트리에서 확인해 보세요.
