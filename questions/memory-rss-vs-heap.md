# 객체를 해제해 힙 사용량은 줄었는데 프로세스의 RSS는 그대로입니다. 누수인지 재사용 공간인지 어떻게 구분하나요?

## 구두 답변

애플리케이션 객체를 해제하는 것과 운영체제에 페이지를 반환하는 것은 다른 사건입니다. RSS(프로세스의 주소 공간 중 현재 물리 메모리에 올라온 페이지의 크기이며 공유 페이지도 포함)에는 관리 힙 외에 스레드 스택, 공유·파일 매핑, 네이티브 할당 등이 포함될 수 있어 힙만 줄어도 RSS가 그대로일 수 있습니다. 메모리 할당자는 다음 요청에 재사용하려고 arena를 보유할 수 있고, 단편화 때문에 빈 공간이 있어도 한 페이지 전체를 돌려주지 못할 수 있습니다.

부하를 낮춘 뒤 살아 있는 객체, 할당자 보유량, RSS와 PSS의 추세를 각각 보겠습니다. 살아 있는 객체가 안정되고 RSS도 높은 값에서 안정되면 재사용 공간 가능성이 있지만, 반복 부하마다 객체와 RSS가 계속 늘면 참조가 남은 누수를 의심합니다. 큰 객체를 해제해도 같은 페이지에 작은 객체가 남아 있으면 해당 페이지는 반환되지 않을 수 있습니다.

프로세스 메모리 맵, 힙·네이티브 프로파일, 스택·파일 매핑을 구분해 증가 영역부터 좁히겠습니다. 원인이 native allocation인데 GC만 조정하지 않으며, trim을 강제하기 전에 재할당·페이지 fault·지연 비용과 컨테이너 메모리 압력을 비교합니다. 반복 부하와 회복 후 관찰을 통해 실제 한도 초과 위험과 단순 보유 메모리를 분리해 대응하겠습니다.

## 득점 포인트

- 객체 수명·할당자 arena·OS 페이지 반환·RSS 구성요소를 분리한다.
- 안정 추세와 반복 증가로 보유 공간과 누수를 구분한다.
- 힙·네이티브·매핑을 나눠 원인부터 찾는다.

## 감점 포인트

- RSS가 줄지 않으면 항상 메모리 누수라고 말한다.
- GC만 실행하면 모든 프로세스 메모리가 OS로 반환된다고 말한다.
- 메모리 반환을 자주 할수록 무조건 좋다고 말한다.
