# 2차 인증을 강하게 해도 복구 수단이 약하면 어떤 문제가 생기나요?

## 구두 답변

공격자가 주 인증을 통과하지 못해도 복구 흐름으로 같은 권한을 얻을 수 있다면 전체 보안은 약한 경로에 맞춰집니다. 따라서 2차 인증 추가만이 아니라 수단 분실·기기 교체·고객 지원을 통한 복구까지 같은 계정 접근 경계로 봐야 합니다.

보안 키를 사용해도 이메일 하나만으로 즉시 모든 수단을 교체할 수 있다면 이메일 탈취가 우회 경로가 됩니다. 저는 복구 수단별 신뢰 수준을 정하고, 민감한 변경에는 최근 인증이나 추가 증명을 요구하겠습니다. 복구 직후에는 고위험 작업을 일정 조건 아래 제한하거나 기존 수단에 알림을 보내는 방법도 있습니다. 다만 알림 자체를 소유권 증명의 대체로 보지는 않겠습니다.

복구 코드는 충분히 예측하기 어렵게 만들고 한 번 사용한 것은 다시 쓰지 못하게 저장하겠습니다. 지원 담당자의 수동 처리가 있다면 최소 권한과 감사 기록, 고위험 변경의 이중 확인을 둘 수 있습니다. 정상 사용자가 영구히 잠기는 문제도 있어서 보안을 높인다는 이유로 복구를 아예 없애지는 않겠습니다. 테스트는 인증 성공뿐 아니라 수단 추가·삭제·복구 후 세션 회수와 동시 요청에서 코드가 두 번 사용되지 않는지 확인하겠습니다.

## 득점 포인트

- **약한 복구 경로를 전체 보안과 연결한다.** 우회 가능성을 본다.
- **신뢰 수준별 정책을 정한다.** 재인증과 민감 작업 제한을 구분한다.
- **일회성과 감사 가능성을 구현한다.** 복구 코드 재사용·지원 권한을 검증한다.

## 감점 포인트

- **MFA만 켜면 복구도 안전하다고 말한다.** 약한 대체 경로가 남는다.
- **알림만 보내면 소유가 확인됐다고 말한다.** 알림은 증명이 아니다.
- **복구를 없애는 것이 최선이라고 말한다.** 정상 사용자의 접근 회복도 요구사항이다.
