# 3NF를 만족하는 테이블에도 중복이 남아 BCNF로 더 나누려 합니다. 원래 데이터를 복원할 수 있는지와 기존 제약을 계속 검사할 수 있는지는 어떻게 확인하나요?

## 구두 답변

3NF와 BCNF는 모두 함수 종속으로 이상 현상을 줄이지만 조건의 강도가 다릅니다. BCNF는 릴레이션에 성립하는 모든 비자명 함수 종속 X→Y에서 X가 슈퍼키여야 한다고 요구합니다. 3NF는 오른쪽을 단일 속성 A로 나눈 각 비자명 종속 X→A에서 X가 슈퍼키이거나 A가 주요 속성, 즉 어떤 후보키에 속하면 허용하는 예외가 있습니다. 그래서 모든 BCNF 릴레이션은 3NF이지만, 3NF라고 해서 BCNF인 것은 아닙니다.

예를 들어 `학생, 과목, 담당강사` 릴레이션에서 (학생, 과목)→담당강사와 담당강사→과목이 성립한다고 하겠습니다. 후보키는 (학생, 과목)과 (학생, 담당강사)가 될 수 있습니다. 담당강사→과목에서 담당강사는 슈퍼키가 아니므로 BCNF를 위반하지만 과목은 후보키에 포함되는 주요 속성이어서 3NF에서는 허용될 수 있습니다. 이를 담당강사-과목과 학생-담당강사로 나누면 담당강사→과목을 별도 관계에 넣어 중복을 줄일 수 있습니다.

무손실 조인은 분해한 테이블을 공통 속성으로 다시 조인했을 때 원래의 유효한 행 외에 가짜 조합이 생기지 않고 원래 정보를 복원하는 성질입니다. 반면 종속성 보존은 분해한 각 테이블만 검사하고 수정해도 원래 함수 종속을 모두 검사할 수 있는 성질입니다. 두 성질은 서로 다른 기준입니다. 위 예에서는 담당강사→과목 때문에 해당 분해가 무손실일 수 있지만, (학생, 과목)→담당강사를 각 분해 테이블의 제약만으로 직접 검사하지 못해 종속성 보존이 깨질 수 있습니다.

따라서 BCNF가 항상 최선이라고 말할 수는 없습니다. 종속성 보존을 위해 3NF를 유지하며 애플리케이션이나 추가 검사를 단순하게 만들지, 더 엄격한 BCNF로 분해하고 조인 시 전역 제약을 검사할지는 무결성 요구와 갱신 경로를 기준으로 결정해야 합니다. 분해 전후의 함수 종속과 조인 결과를 실제 규칙으로 검증해야 합니다.

## 득점 포인트

- BCNF의 ‘모든 결정자는 슈퍼키’ 조건과 3NF의 주요 속성 예외를 구분한다.
- 무손실 조인은 원래 튜플 복원, 종속성 보존은 분해 후 제약 검사 가능성으로 설명한다.
- BCNF 분해가 종속성 보존을 잃을 수 있는 구체적인 후보키 사례를 제시한다.

## 감점 포인트

- BCNF로 분해하면 모든 함수 종속성이 자동으로 각 테이블에서 보존된다고 말한다.
- 무손실 조인과 종속성 보존을 같은 성질의 다른 이름으로 취급한다.
- 3NF는 항상 BCNF보다 잘못된 설계라고 단정해 종속성 보존의 비용을 무시한다.

## 더 파고들 거리

- 주어진 함수 종속 집합에 대해 두 릴레이션 분해가 무손실인지 확인하는 절차를 연습해 보세요.
- 종속성 보존이 없는 BCNF 설계에서 삽입 시 어떤 전역 검사가 필요한지 구체화해 보세요.
- 3NF 합성 알고리즘과 BCNF 분해 알고리즘이 선택하는 결과를 같은 예제로 비교해 보세요.
