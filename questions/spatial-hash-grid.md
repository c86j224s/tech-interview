# 게임 서버의 공간 해시에서 조회 반경·객체 크기·분포를 바탕으로 셀 크기와 중복 처리를 어떻게 정하나요?

## 구두 답변

공간 해시나 uniform grid는 월드 좌표를 셀 좌표로 바꾸고 셀별 객체 목록을 관리해, 모든 객체를 비교하지 않고 인접 셀의 후보만 검사하는 구조입니다. 셀을 작게 하면 한 셀의 후보 수와 불필요한 거리 검사가 줄 수 있지만 큰 객체가 여러 셀에 들어가 이동 때 갱신이 많아집니다. 셀을 크게 하면 삽입은 단순해도 밀집 셀의 후보 수가 커집니다.

따라서 평균 객체 크기만 보지 않고 조회 반경, 객체의 크기 분포, 이동 속도·갱신률, 한 지점에 몰리는 최악 분포를 사용해 후보 수와 갱신 비용을 측정하겠습니다. 크기가 매우 다른 객체가 섞이면 다단계 격자나 별도 구조가 더 나을 수 있습니다. 해시 버킷이 같다는 것은 해시 충돌일 수도 있으므로 실제 셀 좌표를 비교해야 합니다.

객체가 여러 셀에 등록되면 한 조회에서 같은 객체가 여러 번 후보로 나오므로 객체 ID 기준으로 중복 제거합니다. 이동 때는 이전 셀 목록에서 제거하고 새 셀에 넣으며, 읽기와 갱신이 겹치면 프레임 스냅샷이나 안전한 참조 수명을 사용합니다. 음수 좌표는 언어의 정수 나눗셈이 0 방향으로 버리는지 바닥으로 내리는지 확인해, 경계 양쪽이 일관된 셀에 들어가게 해야 합니다.

테스트는 균일 분포뿐 아니라 핫스팟, 경계·음수 좌표, 고속 이동, 다중 셀 객체를 포함합니다. 평균 조회 시간보다 최악 밀집에서 서버 tick 예산과 메모리 상한을 지키는지가 선택 기준입니다.

## 득점 포인트

- 셀 크기의 후보 검사·갱신 비용을 양쪽으로 비교한다.
- 해시 충돌과 실제 공간 셀을 구분한다.
- 다중 셀 중복·음수 좌표·동시 수명을 검증한다.

## 감점 포인트

- 해시 버킷이 같으면 같은 공간이라고 말한다.
- 객체의 다중 셀 등록에 따른 중복을 무시한다.
- 셀은 작을수록 항상 좋다고 말한다.

## 더 파고들 거리

- 여러 조회 반경을 지원하려면 격자를 어떻게 계층화하나요?
- 쓰기 중인 인덱스를 읽을 때 락과 스냅샷을 어떻게 비교하나요?
- AOI와 정밀 충돌 후보가 같은 인덱스를 써도 되는 조건은 무엇인가요?
