# 해시 테이블에서 다른 키가 같은 버킷에 들어오면 어떻게 구분하나요?

## 구두 답변

해시값이 같다는 것은 같은 키라는 뜻이 아닙니다. 해시는 후보 위치를 고르는 데 쓰고 최종 키의 동일성은 실제 키 비교로 확인합니다. 충돌을 처리하는 대표 방식은 한 버킷에 여러 항목을 연결하는 체이닝과, 다른 빈 칸을 찾아 저장하는 개방 주소법입니다.

체이닝은 충돌 항목을 버킷 안에서 탐색하고 개방 주소법은 정한 탐사 순서를 따라 키나 빈 칸을 찾습니다. 후자에서는 삭제한 칸을 단순한 미사용 칸으로 바꾸면 뒤에 있는 키를 검색하다 일찍 멈출 수 있습니다. 삭제 표시를 남기거나 탐사 연결을 복구하는 규칙이 필요합니다.

저는 키 분포와 부하율, 메모리 지역성, 삭제 빈도를 보고 구현을 선택하겠습니다. 평균 상수 시간도 좋은 분산과 적절한 크기 관리가 전제이며 최악에는 많은 비교가 필요할 수 있습니다. 해시와 동등 비교는 같은 키라면 같은 해시를 반환하도록 일치해야 합니다. 테스트는 의도적인 충돌과 삭제 후 재검색을 포함해 서로 다른 키가 덮이거나 사라지지 않는지 확인하겠습니다.

## 득점 포인트

- 해시 일치와 키 동일성을 구분한다.
- 체이닝과 탐사 방식의 차이를 설명한다.
- 삭제 후 탐색 불변식을 검증한다.

## 감점 포인트

- 해시가 같으면 같은 키로 처리한다.
- 탐사 방식에서 삭제 칸을 무조건 빈 칸으로 만든다.
- 평균 상수 시간을 최악 보장으로 말한다.
