# 메모리가 남아 있는데도 페이지 폴트가 발생하는 이유는 무엇인가요?

## 구두 답변

페이지 폴트는 물리 메모리가 부족하다는 뜻이 아니라, 접근한 가상 주소를 지금 상태로 처리할 수 없어 운영체제의 개입이 필요하다는 뜻입니다. 메모리를 할당받았어도 처음 접근할 때 실제 페이지를 연결하는 경우가 있고, 파일에 매핑된 페이지를 아직 읽지 않은 경우도 있습니다. 그래서 폴트 횟수만 보고 메모리가 부족하다고 판단하지는 않겠습니다.

예를 들어 서버가 시작하면서 큰 버퍼를 예약하고 요청이 올 때 조금씩 사용한다면, 첫 접근에서 폴트가 늘어도 정상일 수 있습니다. 디스크를 읽지 않고 해결되는 마이너 폴트와 저장 장치 접근이 필요한 메이저 폴트를 구분하겠습니다. 지연이 시작 직후에만 높고 이후 안정된다면 필요한 범위를 미리 접근해 예열하는 방법이 있지만, 사용하지 않을 메모리까지 채우면 시작 시간과 실제 메모리 사용량이 늘어납니다.

반면 운영 중 메이저 폴트와 저장 장치 대기가 함께 늘어난다면 작업에 필요한 페이지가 자주 밀려나는지 확인하겠습니다. 프로세스의 상주 메모리와 호스트의 메모리 압력을 함께 보고, 캐시나 작업 동시성을 줄여 필요한 데이터가 메모리에 남도록 하겠습니다. 잘못된 주소나 쓰기 권한 위반도 폴트를 일으키므로, 정상적인 페이지 준비와 프로그램 오류를 구분하는 것이 출발점입니다.

## 득점 포인트

- **페이지 준비와 부족을 구분한다.** 첫 접근·파일 매핑·권한 위반을 서로 다른 원인으로 설명한다.
- **지표를 원인에 연결한다.** 마이너·메이저 폴트와 디스크 대기, 예열 이후의 변화로 판단한다.
- **예열의 비용을 설명한다.** 지연 감소와 시작 시간·메모리 점유 증가를 비교한다.

## 감점 포인트

- **모든 폴트가 스왑이라고 말한다.** 디스크 접근 없이 해결되는 폴트도 있다.
- **가상 메모리 크기를 실제 점유로 해석한다.** 예약된 주소 공간과 상주 페이지는 다르다.
- **메모리를 더 주면 항상 해결된다고 말한다.** 접근 오류와 비효율적인 작업 집합은 별도 진단이 필요하다.

## 더 파고들 거리

- 대형 페이지는 주소 변환 비용과 메모리 관리에서 어떤 교환을 만들까요?
- 복사 시 쓰기가 많은 프로세스에서 마이너 폴트와 메모리 증가를 어떻게 연결할까요?
