01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

아닙니다. TCP는 순서가 보장되는 바이트 스트림이지 메시지 전송 프로토콜은 아닙니다. send()의 호출 경계, TCP 세그먼트 경계, recv()의 반환 경계는 서로 다릅니다. MSS, 커널 버퍼링, 세그먼트 병합이나 오프로딩이 영향을 줄 수 있지만, 특정 옵션으로 경계를 복원하는 문제가 아니라 애플리케이션 프레이밍이 필요한 문제입니다.

길이 접두부, 즉 length-prefixed 프로토콜이라면 파서를 헤더 대기와 본문 대기의 상태 머신으로 구성하겠습니다. 수신 버퍼에 바이트를 누적하고 헤더가 완성되면 본문 길이를 검증한 뒤, 메시지가 완성됐을 때만 전달합니다. 한 번 읽은 데이터에 여러 메시지가 있으면 반복 처리하고 마지막 불완전한 프레임은 보관합니다. 파서는 어떤 바이트 경계에서 입력이 나뉘어도 같은 결과를 내야 합니다.

길이에는 바이트 순서, 헤더 포함 여부, 최대 프레임 크기를 명시해야 합니다. 정수 오버플로를 피하는 크기 계산과 연결별 누적 버퍼 상한도 필요합니다. 정상 크기의 헤더를 보내고 본문을 끝없이 늦추는 연결까지 고려하면 단순한 최대 크기 제한만으로는 부족해 프레임 완성 데드라인도 있어야 합니다.

송신도 부분 쓰기를 처리하는 상태 머신이 필요합니다. 논블로킹 소켓에서 일부만 쓰거나 EAGAIN을 받으면 남은 오프셋을 유지하고 쓰기 가능 시 재개합니다. 여러 스레드가 같은 소켓에 논리 메시지를 나눠 쓰면 조각이 섞일 수 있으므로 연결별 송신 큐로 직렬화하는 편이 안전합니다. 느린 수신자로 큐가 무한히 커지지 않도록 상한과 백프레셔도 둬야 합니다.

마지막으로 send() 성공, TCP ACK, 업무 처리 완료를 구분해야 합니다. TCP ACK는 상대 TCP가 바이트를 수신했다는 의미이지 DB 커밋의 증거가 아닙니다. 업무 완료에는 별도 응답과 재시도 정책이 필요합니다. 검증은 랜덤 분할·병합 입력, 프레임 중간 EOF, 짧은 쓰기와 느린 수신자를 재현하고, 파서 오류·버퍼 크기·송신 큐 지연을 관찰하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 세 가지 경계를 분리한다. API 호출, TCP 세그먼트, 애플리케이션 메시지가 일대일 대응하지 않는다는 점을 프레이밍으로 연결한다.
  • 파서를 증분 상태 머신으로 설계한다. 헤더·본문의 부분 도착, 여러 프레임 처리, 남은 바이트와 EOF를 일관되게 다룬다.
  • 부분 쓰기와 자원 상한을 함께 설명한다. 연결별 송신 직렬화, 오프셋 유지, 백프레셔와 데드라인을 고려한다.
  • 수신 보장과 업무 보장을 구분한다. TCP ACK를 애플리케이션 처리·커밋 완료로 해석하지 않는다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • “TCP_NODELAY나 PSH로 메시지 경계를 유지한다”고 말한다. 전송 시점 관련 동작은 애플리케이션 프레이밍 계약을 대체하지 못한다.
  • “MSG_WAITALL이면 요청 길이를 항상 한 번에 받는다”고 말한다. EOF·오류 등으로 짧게 반환될 수 있으며 논블로킹 상태 머신을 없애는 보장도 아니다.
  • “소켓이 스레드 안전하니 여러 메시지를 동시에 보내도 된다”고 말한다. API 안전성과 여러 호출로 구성된 논리 메시지의 원자성은 다르다.
  • “버퍼만 크게 잡으면 느린 연결 문제를 해결한다”고 말한다. 상한 없는 버퍼링은 장애를 지연시키며 메모리와 응답 시간을 악화시킨다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 링 버퍼나 scatter/gather I/O로 복사를 줄일 때 파싱된 메시지와 수신 버퍼의 수명을 어떻게 분리할까요?
  • TLS 레코드가 추가돼도 애플리케이션 메시지 프레이밍이 필요한 이유는 무엇일까요?
  • 파서에 property-based testing을 적용한다면 입력 분할 방식과 출력 메시지 사이에 어떤 불변식을 검사할까요?
  • 느린 수신자의 송신 큐가 상한에 도달하면 메시지 폐기, 생산자 대기, 연결 종료를 어떤 계약에 따라 선택할까요?

득점·감점 포인트는 학습용 자기 점검 기준이며, 특정 회사의 실제 채점표가 아닙니다.
