# 작은 조회와 큰 집계가 같은 실행 슬롯을 씁니다. 요청 수 대신 어떤 비용으로 가중 동시성 허가를 배분하나요?

## 구두 답변

CPU 시간·입력 바이트·연결 보유·메모리처럼 실제 포화 자원에 맞는 가중치를 선택합니다. 작은 조회 1과 큰 집계 20처럼 허가를 차감할 수 있지만 예상 비용이 틀린 경우 보정과 개별 상한이 필요합니다.

총 허가보다 큰 작업은 영원히 대기할 수 있어 거절·분할·별도 풀 정책을 둡니다. 작은 작업만 계속 통과해 큰 작업이 굶지 않도록 예약·공정성도 설계합니다. 가중 허가 획득과 취소·실제 완료 뒤 반환을 한 상태로 관리해 누수와 초과 실행을 막습니다.
