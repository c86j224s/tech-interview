# 프로세스 메모리를 코드·데이터 같은 논리 영역으로 관리하는 방식과 고정 크기 블록으로 나누는 방식을 비교하려 합니다. 세그멘테이션과 페이징은 주소 변환·보호·단편화에서 어떻게 다른가요?

## 구두 답변

페이징은 주소 공간을 고정 크기 페이지로 나누고 물리 프레임에 연결하는 방식입니다. 세그멘테이션은 코드·스택 같은 논리적 구간을 가변 크기의 단위로 나누는 모델입니다. 고정 크기 배치와 논리적 경계 관리라는 차이를 먼저 보겠습니다.

페이징은 프로그램의 연속 가상 주소를 떨어진 물리 프레임에 놓을 수 있어 큰 연속 물리 영역을 찾는 부담을 줄입니다. 대신 페이지 끝의 남는 공간과 페이지 테이블 비용이 생깁니다. 가변 크기 세그먼트는 논리적 보호를 표현하기 쉽지만 물리적으로 연속 배치하는 단순 모델에서는 구간 사이 빈 공간이 흩어질 수 있습니다.

현대 시스템은 하드웨어와 OS에 따라 여러 기법을 조합하거나 평탄한 주소 모델과 페이징을 사용합니다. 저는 교과서 구분을 현재 특정 CPU의 동작과 그대로 동일시하지 않겠습니다. 주소가 어떤 단위로 변환되고 보호되는지, 페이지 크기와 테이블·TLB 비용을 함께 확인하겠습니다. 구현 선택의 핵심은 논리 주소와 물리 배치의 제약을 어떻게 나누는지입니다.

## 득점 포인트

- 고정 크기와 논리적 가변 구간을 구분한다.
- 연속 가상 주소와 물리 배치를 나눈다.
- 테이블·단편화·보호 비용을 설명한다.

## 감점 포인트

- 페이징이면 모든 메모리 낭비가 없다고 말한다.
- 세그먼트는 항상 페이지와 같은 크기라고 말한다.
- 모든 현대 OS가 교과서 세그멘테이션을 그대로 쓴다고 말한다.

## 더 파고들 거리

- 세그먼트 안을 다시 페이징하면 어떤 문제가 줄어들까요?
- 페이지 크기를 키우면 내부 단편화와 TLB 비용은 어떻게 변할까요?
- 가상 주소의 보호 권한은 어떤 단계에서 검사할까요?
