01

구두 답변

정의를 외우기보다, 원리와 조건을 연결해 설명해 보세요.

슬라이스를 대입하면 원소 전체가 아니라 배열을 가리키는 정보와 길이·용량이 복사되기 때문입니다. 두 슬라이스가 같은 기반 배열을 가리키면 한쪽의 원소 변경이 다른 쪽에도 보입니다. 값으로 전달했다는 사실만으로 데이터가 독립됐다고 볼 수 없습니다.

예를 들어 수신 버퍼의 일부를 슬라이스로 잘라 비동기 작업에 넘긴 뒤 원래 버퍼를 재사용하면, 작업자가 나중에 보는 내용은 이미 바뀌어 있을 수 있습니다. 저는 호출 동안만 빌리는 데이터인지, 호출 이후에도 보관할 데이터인지 API에 구분하겠습니다. 보관해야 한다면 필요한 범위를 복사해 소유권을 넘기는 편이 명확합니다. 동시에 접근하는 경우에는 복사 또는 동기화 없이 읽기·쓰기를 섞어서는 안 됩니다.

append도 기존 용량이 남아 있으면 같은 배열을 사용하고, 부족하면 새 배열로 옮길 수 있습니다. 그래서 특정 입력 크기에서만 문제가 재현될 수 있습니다. 용량을 제한한 슬라이싱은 이후 append의 재사용 범위를 막을 수 있지만 기존 원소 변경을 독립시키지는 않습니다. 작은 부분만 오래 보관해도 큰 기반 배열 전체가 남을 수 있으므로, 짧은 데이터의 장기 보관은 복사 비용과 메모리 유지 비용을 비교하겠습니다. 테스트에서는 용량이 남는 경우와 재할당되는 경우를 모두 확인하겠습니다.

02

득점 포인트

이해가 드러나는 지점을 확인해 보세요.

  • 헤더 복사와 원소 복사를 구분한다. 기반 배열의 공유를 설명한다.
  • API의 빌림과 소유를 정한다. 비동기 보관과 버퍼 재사용 경로를 점검한다.
  • 용량별 동작을 검증한다. append 재사용과 재할당을 나눠 테스트한다.
03

감점 포인트

놓치기 쉬운 조건과 오해를 짚어 보세요.

  • 값 전달이므로 원소가 독립이라고 말한다. 배열은 공유될 수 있다.
  • append는 항상 새 배열을 만든다고 말한다. 용량에 따라 재사용한다.
  • 길이가 짧으면 메모리 점유도 작다고 말한다. 큰 기반 배열을 유지할 수 있다.
04

더 파고들 거리

하나 더 질문하며 이해의 범위를 넓혀 보세요.

  • 세 인덱스 슬라이싱은 어떤 공유를 막고 어떤 공유는 남기나요?
  • 바이트 버퍼 풀에 반환하기 전에 누가 참조를 보유했는지 어떻게 확인할까요?
  • 슬라이스에서 원소를 제거할 때 참조를 지우지 않으면 어떤 객체가 남을까요?
