# 메모리에 다 들어가지 않는 큰 파일을 정렬하려 합니다. 병합 정렬은 어떻게 활용할 수 있나요?

## 구두 답변

메모리에 들어가는 크기로 나눠 각각 정렬한 파일을 만들고, 그 정렬된 구간들을 병합하는 방식으로 처리할 수 있습니다. 병합은 각 구간의 앞쪽 원소만 비교해 순서대로 출력하므로 전체 데이터를 동시에 메모리에 둘 필요가 없습니다. 이를 외부 정렬에서 활용합니다.

예를 들어 여러 정렬 파일에서 현재 가장 작은 원소를 힙으로 선택하고 해당 파일의 다음 원소를 읽습니다. 파일마다 버퍼를 두면 작은 읽기를 반복하는 비용을 줄일 수 있습니다. 동시에 열 수 있는 파일 수와 버퍼 메모리가 제한되므로 한 번에 모두 합치지 못하면 여러 병합 단계를 거칩니다.

저는 비교 횟수뿐 아니라 디스크 읽기·쓰기 양과 임시 파일 공간을 계산하겠습니다. 중간 실패 시 어떤 구간까지 완성됐는지 기록하고 완성 전 결과를 최종 파일로 노출하지 않는 것도 중요합니다. 안정 정렬이 필요하면 같은 키에서 어느 구간을 먼저 선택할지와 원래 순서를 보존해야 합니다. 테스트는 메모리 상한, 동점, 빈 파일, 디스크 부족과 중단 후 재개를 포함합니다.

## 득점 포인트

- 정렬 구간 생성과 병합 단계를 설명한다.
- 버퍼·파일 수·임시 공간 비용을 본다.
- 완성 결과 공개와 재시작을 관리한다.

## 감점 포인트

- 병합 정렬이면 디스크 공간이 추가로 필요 없다고 말한다.
- 모든 파일을 무제한으로 동시에 연다.
- 동점 처리 없이 안정성을 보장한다고 말한다.

## 더 파고들 거리

- 다중 병합의 fan-in을 늘리면 병합 횟수와 버퍼는 어떻게 변할까요?
- 이미 정렬된 구간을 감지하면 어떤 비용을 줄일까요?
- 정렬 키와 원본 레코드를 분리해 저장하면 언제 유리할까요?
