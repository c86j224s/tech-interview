# Redis sorted set 랭킹에서 동점 정렬, 점수 정밀도, 중복 갱신을 어떻게 안정적으로 처리하나요?

## 구두 답변

Redis sorted set은 멤버별 점수를 기준으로 정렬하고, 점수가 같으면 멤버의 바이트 순서가 사용됩니다. 이것은 가입 시각이 빠른 사용자 우선이나 먼저 달성한 사용자 우선 같은 업무 규칙을 자동으로 보장하지 않습니다. 오름차순·내림차순 조회에서 동점 순서가 어떻게 보이는지도 API 계약에 포함해야 합니다.

업무 정렬 기준을 하나의 부동소수점 점수에 시각이나 보조 순위를 이어 붙여 표현하면 큰 값에서 정밀도가 깨질 수 있습니다. 최대 점수·시각 범위·구분해야 하는 최소 간격을 계산하고, 인접한 두 값이 실제 Redis 점수로 구분되는지 확인하겠습니다. 필요하면 점수와 보조 정렬 키를 별도로 관리하거나, 범위가 검증된 정수 인코딩을 사용합니다.

`ZINCRBY`는 동일 이벤트가 다시 오면 다시 더하므로 중복 재전달에 멱등적이지 않습니다. 이벤트 ID를 처리 원장에 기록하고 점수 변경과 원장을 원자적 경계에서 함께 처리하거나, 버전이 더 최신일 때만 절대 점수를 반영하는 방식을 선택하겠습니다. 보상은 변하는 현재 sorted set을 직접 읽지 말고 확정 집계 버전에서 계산해야 합니다.

테스트는 대규모 동점, 최대·최소 점수, 정밀도 경계, 중복·늦은 이벤트, 역순 조회를 포함합니다. 화면 순서와 지급 대상이 같은 비교 규칙을 사용하는지 재계산으로 확인하겠습니다.

## 득점 포인트

- 기본 동점 순서와 업무상 동점 규칙을 구분한다.
- 부동소수점 정밀도와 인코딩 범위를 검증한다.
- 증분 갱신의 중복 방지와 확정 버전을 설명한다.

## 감점 포인트

- 같은 점수에서 삽입 순서가 자동 보장된다고 말한다.
- 어떤 큰 정수도 점수에 정확히 저장된다고 말한다.
- `ZINCRBY` 재시도는 항상 안전하다고 말한다.

- 전역·지역 랭킹을 함께 갱신할 때 원자성 범위는 어디까지인가요?
