# IOCP에 concurrency 값을 지정하고 워커 스레드를 따로 만들었습니다. 이 값은 생성한 스레드 수와 무엇이 다른가요?

## 구두 답변

concurrency는 완료 포트와 연결된 스레드 중 동시에 실행 가능하게 허용할 수에 관한 값이지 생성할 워커 개수를 정하는 값은 아닙니다. 워커는 애플리케이션이 따로 만들고 완료 큐를 기다리게 합니다. 기본값과 실제 실행 상태는 Windows의 규칙에 따라 확인해야 합니다.

워커는 완료 큐를 기다리고 결과를 처리하도록 애플리케이션이 만든 스레드입니다. concurrency는 그 스레드를 생성하는 명령이 아니라 완료 포트에 연결된 실행 흐름의 동시 실행을 조절하는 값입니다. 따라서 값만 바꿔도 워커 객체나 스레드가 새로 생기는 것은 아닙니다.

CPU 작업이 많은 완료 처리라면 실행 스레드를 과하게 늘릴 때 전환과 경합만 커질 수 있습니다. 반대로 워커가 블로킹되면 다른 대기 워커가 실행 기회를 얻을 수 있습니다. 따라서 워커 수를 concurrency와 반드시 같게 둘 필요는 없지만, 블로킹 작업을 무제한으로 섞어도 괜찮다는 뜻은 아닙니다. 외부 호출이 모든 워커를 붙잡으면 완료 처리가 밀릴 수 있습니다.

저는 완료 처리의 실행 시간과 큐 대기, 블로킹 위치를 측정하겠습니다. 짧은 I/O 완료 처리는 포트 워커에서 끝내고 긴 계산이나 동기 외부 호출은 제한된 별도 실행 경로로 보낼 수 있습니다. 설정을 바꿀 때는 처리량뿐 아니라 p99와 컨텍스트 스위치를 비교하겠습니다. concurrency는 스케줄링 비용을 조절하는 장치이며 요청 순서나 연결별 상호 배제를 보장하는 장치는 아닙니다.

## 득점 포인트

- **워커 생성과 실행 제한을 구분한다.** 설정의 대상을 정확히 설명한다.
- **블로킹과 CPU 부하를 나눈다.** 완료 처리 경계를 설계한다.
- **순서 보장과 혼동하지 않는다.** 연결 상태 동기화는 별도다.

## 감점 포인트

- **concurrency만큼 워커가 자동 생성된다고 말한다.** 스레드는 직접 생성한다.
- **값이 1이면 모든 연결의 요청 처리가 원자적이라고 말한다.** 다른 실행 경로와 재진입이 있다.
- **워커는 많을수록 좋다고 말한다.** 전환과 공유 경합이 늘 수 있다.
