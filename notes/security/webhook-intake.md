# Webhook 서명 검증과 내구 접수·중복 처리

## 같은 진짜 이벤트가 여러 번 도착할 수 있습니다

결제사가 승인 이벤트 E를 보냈고 우리 서버가 DB에 반영했지만 HTTP 응답이 유실됐다고 합시다. 결제사는 E를 다시 보낼 수 있습니다. 두 전달 모두 유효한 서명을 가질 수 있으므로 서명 검증만으로 중복 효과가 없어지지 않습니다.

서명은 지정된 키로 발급된 메시지의 무결성과 출처 근거를 확인합니다. 재생 허용 창, 논리 이벤트 중복, 결제 상태 순서, 원장 변경 권한은 그 뒤의 별도 검사입니다.

## 서명 입력은 파싱한 JSON이 아니라 계약의 바이트입니다

제공자가 서명한 원문 body와 지정 헤더를 사용합니다. JSON을 파싱한 뒤 다시 직렬화하면 키 순서·공백·숫자 표현이 달라져 서명 입력이 바뀔 수 있습니다. 웹 프레임워크의 body middleware가 원문을 보존하는지 확인하고, 읽기 전부터 바이트·시간 상한을 둡니다.

제공자에 따라 서명 입력은 timestamp와 body의 결합 등으로 다릅니다. 직접 추측한 조합이 아니라 공식 verifier를 사용하고 허용 알고리즘·키·버전을 설정합니다. 비교는 검증된 안전한 API를 사용합니다. timestamp가 서명에 묶였는지 확인하지 않고 헤더 시각만 검사하면 공격자가 시각을 바꿀 수 있습니다.

| 검사 | 막는 문제 | 남는 문제 |
| --- | --- | --- |
| 서명·키 검증 | 변조·미신뢰 발급 | 같은 진짜 이벤트 중복 |
| 서명된 시각·허용 오차 | 오래된 전달의 재생 창 | 허용 창 안 재전달 |
| 이벤트 ID 유일성 | 동일 논리 이벤트의 중복 효과 | 서로 다른 이벤트의 역순 |
| 상태·버전·원장 규칙 | 잘못된 상태 전이 | 외부 시스템과의 최종 대사 |

시각 검사는 제공자의 재시도 계약을 고려해야 합니다. 원래 이벤트 발생 시각과 매 전달의 서명 시각이 다를 수 있습니다. 정상 지연·시계 오차를 이유로 무제한 재생을 허용하지도, 짧은 고정 창으로 모든 정상 재전달을 거절하지도 않습니다.

## 빠른 2xx는 내구 접수 뒤에 반환합니다


그림은 설명을 위한 순서이며 worker가 ACK 네트워크 전달보다 먼저 실행될 수도 있습니다. 핵심은 ACK 전에 내구 접수가 완료되고 worker 실행은 재개 가능하다는 점입니다. 메모리 큐에 넣고 바로 2xx를 반환하면 프로세스 중단 때 이벤트를 잃습니다.

inbox의 중복 키는 제공자·계정 등 event ID의 실제 유일 범위를 포함합니다. 같은 ID에 다른 payload가 오면 조용히 성공 처리하지 않고 해시·저장 원문과 비교해 충돌을 조사합니다. 서명 검증을 생략한 중복 경로가 민감 정보를 응답으로 드러내지 않게 합니다.

## 처리 ID와 원장 변경을 같은 거래로 묶습니다

worker가 이벤트 ID만 먼저 처리 완료로 저장하고 원장 쓰기 전에 죽으면 재시도가 효과를 건너뜁니다. 원장을 먼저 쓰고 ID를 나중 기록하면 중복 반영됩니다. 지원되는 한 DB 거래 안에서 처리 마커·현재 상태 검사·원장 변경을 함께 커밋합니다. 다른 서비스로 보낼 이벤트는 outbox로 연결합니다.

취소 이벤트가 승인보다 먼저 도착했다고 단순 도착 순서대로 최종 상태를 덮지 않습니다. 제공자가 보장하는 버전·전이 규칙을 확인하고 필요하면 결제사의 권위 상태를 조회해 대사합니다. 이벤트 시각만으로 모든 분산 순서를 정할 수 있다고 가정하지 않습니다. payload의 사용자 ID나 URL도 인증된 메시지라는 이유로 무조건 인가·외부 조회 근거로 쓰지 않습니다.

## 키 교체와 처리 실패는 다른 운영 신호입니다

구·신 서명키 중첩 기간은 제공자 계약과 토큰·전달 수명에 맞춥니다. 모르는 키를 받았다고 임의 URL에서 비밀을 읽거나 서명 검증을 끄지 않습니다. 서명 거절률, inbox 지연, worker 재시도, 중복률, 대사 불일치를 따로 관찰합니다.

테스트 제공자에서 정상 서명·원문 공백 변경·오래된 전달·같은 E 반복·취소 선행·inbox 커밋 뒤 중단을 재현합니다. 수신 HTTP 성공률만 아니라 최종 원장 효과가 한 번이며 접수한 이벤트가 실패 상태에서도 추적 가능한지 확인합니다. 이 노트는 학습용 접수 설계이며 실제 결제 webhook을 처리한 기록은 아닙니다.
