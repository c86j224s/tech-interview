# 에이전트형 검색과 주장별 근거 검증

## 다음 검색은 아직 모르는 사실을 확인해야 합니다

“배포가 장애 원인인가”에는 배포 시각·오류 증가·변경하지 않은 집단의 상태가 필요합니다. 첫 검색으로 장애 시각을 알면 해당 배포를 찾고, 후보가 생기면 다른 원인을 대조합니다. 단일 검색 RAG에 추가되는 것은 반복 횟수보다 관찰에 따른 질문 분해·자료원 선택·공백 확인입니다.

하나의 규정 원문으로 답할 수 있으면 반복 루프가 불필요할 수 있습니다. 단일 검색을 기준선으로 두고 추가 조회가 어떤 누락·불확실성을 줄였는지 확인합니다. 원하는 결론이 나올 때까지 검색어만 바꾸는 것은 확인 편향을 강화할 수 있습니다.

## 원문 수와 독립 근거 수는 다릅니다

같은 보도자료를 재인용한 문서 열 개는 독립 증거 열 개가 아닙니다. 원본·관찰 시각·적용 버전·파생 관계를 유지하고 상충 자료를 버리지 않습니다. 검색 제목·스니펫은 위치를 찾는 단서이지 규범 세부 조건을 읽었다는 증거가 아닙니다.

## 링크가 열려도 결론이 틀릴 수 있습니다

원문이 “실험 기능이며 일부 client 지원”이라고 하는데 답변이 “모든 client가 기본 지원”이라면 공식 링크도 잘못된 결론을 구하지 못합니다. 주요 주장을 쪼개어 정확한 원문 구간과 필수/선택·적용 version·전제를 대조합니다.

| 주장 | 확인할 근거 |
| --- | --- |
| 기능을 반드시 지원한다 | 규범의 MUST와 대상·버전 |
| 성공률 90%다 | 과제·시도 수·분모·실패 포함 여부 |
| A가 B보다 빠르다 | 같은 자원·도구·예산·워크로드 |
| 배포가 장애를 일으켰다 | 시간 관계 외의 대조·인과 근거 |

계산한 값은 입력·단위·공식을 남기고 직접 인용과 구분합니다. 두 source가 다른 예산을 썼다면 숫자를 나란히 놓고 우열을 확정하지 않습니다. 인용 필드를 필수로 해도 없는 근거가 생기지는 않으므로 접근 불가·미확인을 허용합니다.

## 검증기도 서로 다른 문제를 맡습니다

코드는 URL·문서 ID·구간 존재와 계산을 확인할 수 있습니다. 주장의 논리적 뒷받침은 rubric·모델·사람 검토로 보완하되 모델 채점도 틀릴 수 있습니다. 인용 개수보다 핵심 주장 중 충분한 근거가 있는 비율·잘못된 인용·조건 누락을 봅니다. 동일 latest URL이 바뀔 수 있어 고정 revision과 확인 날짜를 기록합니다.

## 검색 확대가 권한 확대는 아닙니다

다른 저장소로 이동해도 같은 사용자 ACL·외부 전송 정책·예산을 유지합니다. 새 사실 없이 같은 출처를 반복하면 중단하고 미확인 부분을 표시합니다. 문서가 권장한 조치도 사용자 실행 승인은 아니므로 실제 변경은 별도 인가·승인을 통과합니다.

삭제된 문서·모순 버전·재인용·도구 잘림·권한 철회·단위 혼합을 시험합니다. 이 노트는 조사 방법이며 특정 검색 전략의 성공률 개선을 실제 평가한 결과는 아닙니다.
