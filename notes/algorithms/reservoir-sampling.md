# 길이를 모르는 스트림의 균등 표본

## 앞 K개를 고르면 뒤의 입력은 기회가 없습니다

끝이 언제인지 모르는 로그에서 100개만 표본으로 보관하고 싶다고 합시다. 앞의 100개만 저장하면 오래된 입력에 치우칩니다. 전체를 저장한 뒤 셔플하면 공정하게 고를 수 있지만 메모리 목표를 잃습니다.

**Reservoir sampling**은 K개 슬롯만 유지하면서 새로운 항목이 들어올 때 일부 표본을 교체합니다. 처리한 입력 N개 중 각 발생 항목이 K/N 확률로 남도록 설계합니다. 기본 알고리즘은 최근 항목을 더 중요하게 보거나 테넌트별 표본 수를 균등하게 만들지 않습니다.

## 세 항목에서 한 개를 남겨 봅니다

K=1이고 입력이 A,B,C 순서라고 하겠습니다. A를 먼저 저장하고, B는 1/2 확률로 A를 교체합니다. C는 1/3 확률로 현재 표본을 교체합니다.

| 최종 표본 | 남는 사건 | 확률 |
| --- | --- | --- |
| A | B에서 유지하고 C에서도 유지 | 1/2 × 2/3 = 1/3 |
| B | B로 교체하고 C에서 유지 | 1/2 × 2/3 = 1/3 |
| C | 마지막에 교체 | 1/3 |

처음 항목은 오래 살아남아야 하므로 이후의 교체 위험을 더 많이 겪습니다. 새 항목은 작은 확률로 들어오지만 남은 위험이 적습니다. 두 효과가 맞아떨어져 최종 포함 확률이 같아집니다.

## K개 슬롯에 적용합니다

```text
sample(stream, K):
    require integer K and K >= 0
    if K == 0: return []
    reservoir = []
    seen = 0
    for item in stream:
        seen += 1
        if seen <= K:
            reservoir.append(item)
        else:
            j = uniformBelow(seen)       # 0 .. seen-1
            if j < K:
                reservoir[j] = item
    return reservoir
```

처음 K개는 모두 넣습니다. i번째 새 항목은 i개 숫자 중 K개를 뽑았을 때 들어가므로 확률 K/i입니다. 들어갈 경우 K개 슬롯 가운데 하나를 균등하게 교체합니다. 입력이 K개보다 적으면 모두 반환합니다. K=0에서 스트림을 소비해야 하는 부수 계약이 있다면 즉시 반환 대신 순회하되 표본을 저장하지 않는 별도 동작으로 정의합니다.

N개 입력의 시간은 O(N), 표본 공간은 O(K)입니다. 로그 수가 매우 크면 `seen`의 정수 범위와 난수 API가 지원하는 상한을 확인해야 합니다. 원천 난수의 범위를 넘는 i를 단순 나머지로 처리하면 균등성 전제가 깨집니다.

## 이미 있던 항목도 K/i 확률로 남습니다

i-1개 처리 뒤 어떤 기존 항목의 포함 확률이 K/(i-1)이라고 가정합니다. 새 항목이 그 항목의 슬롯을 골라 제거할 확률은 `1/i`입니다. 따라서 기존 항목이 계속 남을 확률은 다음과 같습니다.

```text
K/(i-1) × (1 - 1/i) = K/i
```

새 항목도 K/i 확률로 들어오므로 모든 항목의 주변 포함 확률이 같아집니다. 더 강하게는 Algorithm R의 교체 규칙으로 크기 K의 모든 부분집합도 균등합니다. 하지만 reservoir 배열 안의 순서가 균등 순열이라는 뜻은 아닙니다. 순서까지 무작위여야 한다면 마지막 표본을 별도로 셔플합니다.

## 무엇을 한 항목으로 셀지 정합니다

값이 A,A,B로 들어오면 기본 알고리즘은 두 A의 **발생**을 별개로 셉니다. 고유 값 A와 B를 반반 뽑는 알고리즘이 아닙니다. 고유 사용자별 표본이라면 먼저 중복 제거 상태를 유지해야 하고 그 메모리가 K를 넘을 수 있습니다.

중단 후 재현하려면 표본뿐 아니라 처리 위치, seen, 난수 상태와 입력 버전을 함께 보존해야 합니다. 같은 seed라도 입력 순서가 다르면 결과는 다릅니다. 여러 샤드의 K개 표본을 단순 합쳐 다시 K개 뽑으면 샤드 크기가 다른 경우 원래 항목의 포함 확률이 달라질 수 있습니다. 분산 병합에는 샤드별 처리량을 고려하는 별도 알고리즘이 필요합니다.

## 작은 입력의 확률을 정확히 셉니다

N=4, K=2에서 3번째 선택 j는 0~2, 4번째는 0~3이므로 12개 동일 확률 경로가 있습니다. 최종 부분집합 여섯 개가 각각 두 경로씩 나오는지 전수 계산할 수 있습니다. K=1의 세 항목 예와 함께 고정 난수를 주입해 j=K-1은 교체하고 j=K는 건너뛰는 경계도 확인합니다.

운영 표본이 오류를 더 많이 보존하도록 가중되었다면 그 정책을 균등 reservoir라고 부르지 않습니다. 관찰 지표를 표본으로 추정할 때도 추출 확률을 반영해야 하며, 단순 표본 개수를 전체 비율로 오해하지 않아야 합니다.
