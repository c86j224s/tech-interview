# 정렬 안정성과 introsort의 서로 다른 보장

## 값이 같아도 레코드의 순서는 의미가 있습니다

입력이 `(점수=80,이름=A)`, `(90,B)`, `(80,C)`이고 점수로 정렬한다고 합시다. 같은 80 안에서 A가 C보다 먼저 남는 보장이 **안정성**입니다. 키가 정렬됐다는 사실만으로 이 순서를 보장하지는 않습니다.

제자리 정렬은 추가 저장 공간에 관한 속성이고 안정성은 동점 레코드 순서에 관한 속성입니다. 하나가 다른 하나를 뜻하지 않습니다. 일반적인 삽입 정렬은 제자리이면서 안정적으로 구현할 수 있고, 흔한 제자리 퀵소트는 불안정합니다. 보조 배열을 쓰는 병합 정렬도 동점 선택을 잘못하면 불안정해질 수 있습니다.

## 비교자가 같다고 보는 기준으로 동점을 정의합니다

두 레코드의 모든 필드가 같아야 동점인 것은 아닙니다. 비교자가 점수만 비교하면 이름이 달라도 같은 키입니다. 먼저 이름으로 안정 정렬하고 다음 점수로 안정 정렬하면 점수가 같은 그룹 안에서 이름 순서가 보존됩니다. 반면 두 번째 정렬이 불안정하면 첫 순서를 잃을 수 있습니다.

| 속성 | 질문 | 별도로 확인할 것 |
| --- | --- | --- |
| 정렬됨 | 비교 기준대로 비감소하는가 | 비교자의 일관성 |
| 안정성 | 동점의 입력 순서가 남는가 | 원본 순번 |
| 제자리 | 추가 배열 없이 처리하는가 | 재귀 스택 포함 여부 |
| 최악 시간 | 어떤 입력에도 상한이 있는가 | 입력·비교 비용 전제 |

비교 키가 바뀌거나 NaN 처리·대소문자 규칙이 일관되지 않으면 알고리즘의 전제가 깨집니다. 안정성은 잘못된 비교자를 고쳐 주지 않습니다.

## 원본 순번을 보조 키로 만드는 대안

불안정 정렬만 있어도 `(원래 키, 입력 순번)`을 비교하면 동점 순서를 명시적인 전순서로 만들 수 있습니다. 그러나 순번 저장·비교 비용이 추가되고 기존 비교 의미가 확장됩니다. 모든 레코드의 입력 순번이 유일하고 범위를 넘지 않도록 해야 합니다.

## introsort는 퀵소트의 나쁜 깊이를 감시합니다

퀵소트가 매번 0:n-1로 분할되면 깊이 O(n), 시간 O(n²)이 됩니다. **Introsort**는 일정 깊이 이상 내려가면 남은 구간을 heapsort로 처리하는 전략입니다. 예를 들어 처음 n에서 `2 floor(log2 n)` 같은 깊이 예산을 정할 수 있지만 정확한 상수와 작은 구간 처리 방식은 구현마다 다릅니다.

```text
sortRange(range, depthBudget):
    if range is small:
        insertionSort(range)
        return
    if depthBudget == 0:
        heapSort(range)
        return
    left,right = partitionExcludingFixedPivot(range)
    sortRange(left, depthBudget-1)
    sortRange(right, depthBudget-1)
```

퀵소트 단계는 같은 깊이의 서로 겹치지 않는 구간 전체에서 O(n) 일을 하며 허용 깊이가 O(log n)이므로 O(n log n)입니다. 그 뒤 남은 서로 겹치지 않는 구간의 heapsort 비용 합도 O(n log n)으로 제한됩니다. 깊이 예산은 자식에서 원래 n으로 새로 계산해 리셋하지 않고 감소시키며 이어야 합니다.

## 시간 상한과 스택 상한은 따로 봅니다

깊이 제한이 있는 위 재귀는 O(log n) 깊이 안에서 heapsort로 전환합니다. 별도로 작은 쪽만 재귀 호출하고 큰 쪽은 반복문으로 처리하면 일반 퀵소트에서도 스택 깊이를 O(log n)으로 제한할 수 있습니다. 하지만 그 최적화만으로 분할의 O(n²) 시간은 없어지지 않습니다.

Heapsort로 바뀌었다고 안정성이 생기지도 않습니다. 흔한 introsort는 불안정 정렬이며 API가 안정성을 보장하는지 확인해야 합니다. 작은 구간 삽입 정렬은 전체 알고리즘의 안정성을 자동으로 만들지 않습니다. 비교 한 번이 긴 문자열·외부 호출에 비례하면 비교 횟수의 시간 분석과 실제 실행 시간도 구분합니다.

## 서로 다른 속성을 각각 검사합니다

키에 원본 순번을 붙인 중복 입력을 정렬해 값의 순서와 동점 순번을 따로 확인합니다. 정렬·역정렬·모두 같은 값·중복 집중 입력에서 비교 횟수와 최대 재귀 깊이를 측정합니다. 입력 다중집합 보존과 메모리 피크도 확인합니다.

성능 테스트에서 빠른 평균만 보고 최악 상한을 단정하지 않고, 안정성 테스트를 통과했다고 제자리라고 말하지 않습니다. 정렬 라이브러리를 선택할 때는 이 속성들이 각각 어떤 계약인지 명시해야 합니다.
