# 계수 정렬과 기수 정렬의 키 표현

## 비교를 줄이는 대신 키의 구조를 사용합니다

원소가 백만 개이고 키가 0~100 사이 정수라면 각 값이 몇 번 나왔는지 세고 순서대로 출력할 수 있습니다. 두 키를 비교해 순서를 알아내는 대신 값 범위를 직접 주소로 사용하므로 비교 정렬의 일반적인 O(n log n) 하한을 그대로 적용하지 않습니다.

하지만 키가 수십억 범위에 흩어진 백 개 원소라면 카운터 배열이 낭비됩니다. **계수 정렬**의 비용은 원소 수 n뿐 아니라 값 범위 R에도 달려 있습니다. 기수 정렬은 전체 값 범위 대신 키를 여러 자리로 나누어 이 분배를 반복합니다.

## 안정적인 계수 분배를 먼저 만듭니다

키가 `[2a,1b,2c,0d]`이고 문자는 원래 레코드의 정체성이라고 하겠습니다. 같은 키 2의 a·c 순서를 유지해야 합니다. 빈도를 누적해 각 키의 끝 위치를 얻고 입력을 뒤에서 앞으로 채울 수 있습니다.

| 단계 | 카운터 또는 결과 | 뜻 |
| --- | --- | --- |
| 빈도 | [1,1,2] | 키 0·1·2의 개수 |
| 누적 끝 | [1,2,4] | 각 키 구간의 배타적 끝 |
| 뒤에서 d | out[0]=0d | 끝 위치를 먼저 1 감소 |
| c, b, a | [0d,1b,2a,2c] | 동점의 원래 순서 보존 |

```text
stableCount(records, digit, R):
    count[0..R-1] = 0
    for record in records: count[digit(record)] += 1
    for k = 1 .. R-1: count[k] += count[k-1]
    out = new array(length(records))
    for record in reverse(records):
        k = digit(record)
        count[k] -= 1
        out[count[k]] = record
    return out
```

digit는 `[0,R)`의 정수여야 합니다. 시간 O(n+R), 일반적인 안정 분배의 공간 O(n+R)입니다. 단순 값의 빈도만 출력하는 것과 레코드의 동점 순서를 보존하는 것은 다른 요구입니다.

## 낮은 자리부터 쌓으려면 앞선 순서를 보존합니다

## 음수는 unsigned 순서와 다릅니다

고정 폭 w비트 2의 보수 표현을 unsigned로 해석하면 음수가 큰 값 영역에 놓입니다. 부호 비트를 뒤집으면 음수 영역이 앞으로 이동하면서 signed 숫자 순서가 보존됩니다.

| signed 8비트 값 | 비트 패턴 | 부호 비트 XOR 후 unsigned |
| --- | --- | ---: |
| -128 | 10000000 | 0 |
| -1 | 11111111 | 127 |
| 0 | 00000000 | 128 |
| 127 | 01111111 | 255 |

실제 코드에서는 부호 있는 overflow를 일으키는 산술 보정보다 언어가 보장하는 unsigned 변환·비트 연산을 사용합니다. LSD는 최하위 **의미상의 자리**부터 처리하므로 메모리의 첫 바이트부터 읽는 것이 항상 맞지는 않습니다. 엔디언과 자리 추출을 분리하고 마스크·시프트로 정의하는 편이 명확합니다. 부동소수점·가변 폭 정수에는 이 변환을 그대로 적용하지 않습니다.

## 문자열은 끝났다는 상태가 필요합니다

사전순에서 `a`는 `aa`보다 먼저입니다. 끝을 실제 문자와 충돌하지 않는 가장 작은 기호로 취급할 수 있습니다. 바이트 문자열이라면 끝을 0, 실제 바이트 b를 b+1로 매핑해 총 257개 기호를 사용하면 실제 NUL 바이트도 구별됩니다.

LSD는 최대 길이까지 오른쪽 끝의 부족한 자리를 종료 기호로 채운 것으로 보고 가장 뒤 자리부터 안정 분배합니다. 매우 긴 문자열 하나 때문에 모든 짧은 문자열도 많은 단계를 거칠 수 있습니다. MSD는 첫 자리부터 같은 접두 그룹을 나누고 각 그룹의 다음 자리로 내려가며 종료 기호 그룹은 더 처리하지 않습니다. 깊은 공통 접두사는 재귀 깊이와 반복 스캔을 키웁니다.

UTF-8 바이트 사전순, 코드 포인트 순서, 사용자 언어의 collation은 같은 요구가 아닙니다. 정규화·대소문자·언어별 정렬 키를 먼저 정하고 그 키에 알고리즘을 적용해야 합니다.

## 비교 정렬과 같은 결과인지 확인합니다

범위가 작은 정수·음수 최솟값·최댓값·0·동점 레코드·빈 문자열·접두 관계·NUL 바이트를 포함해 기준 비교 정렬과 대조합니다. 안정성이 필요하면 키뿐 아니라 원본 순번도 확인합니다.

키 범위와 자릿수가 커질 때 카운터·출력 버퍼·총 읽기/쓰기량을 측정합니다. 이미 정렬된 run을 활용하는 비교 정렬이 실제 데이터에서 더 유리할 수도 있습니다. “정수니까 선형”이라는 말 대신 n·R·d와 키 표현, 실제 이동량을 함께 설명해야 합니다.
