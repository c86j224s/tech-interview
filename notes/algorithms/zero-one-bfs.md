# 0-1 BFS의 덱 순서와 거리 갱신

## 이동 횟수와 비용이 달라집니다

S→A 비용이 1이고 S→B와 B→A 비용이 모두 0이라고 합시다. 일반 BFS는 간선 하나로 A를 먼저 발견하지만 최저 비용은 B를 거치는 0입니다. 처음 발견한 거리를 고정하는 규칙을 그대로 쓰면 안 됩니다.

모든 간선 비용이 0 또는 1이라면 일반 최소 힙보다 단순한 덱으로 후보 순서를 유지할 수 있습니다. 이를 **0-1 BFS**라고 부릅니다. 단위 비용 BFS와 달리 더 낮은 거리를 발견하면 갱신해야 합니다.

## 비용이 늘지 않는 후보를 먼저 처리합니다

거리 d인 최소 후보를 확장하면 새 거리는 d 또는 d+1입니다. 비용 0 후보는 현재 층에 속하므로 덱 앞, 비용 1 후보는 다음 층이므로 뒤에 넣습니다.

## 오래된 후보와 확정 상태를 구분합니다

```text
zeroOneBfs(graph, source):
    validate_all_vertices_and_weights_in({0,1})
    dist[*] = INF
    parent[*] = NONE
    settled = empty set
    dist[source] = 0
    q = deque([(0,source)])
    while q not empty:
        d,u = q.pop_front()
        if d != dist[u] or u in settled: continue
        settled.add(u)
        for v,w in outgoing(u):
            candidate = d+w
            if candidate < dist[v]:
                dist[v] = candidate
                parent[v] = u
                if w == 0: q.push_front((candidate,v))
                else: q.push_back((candidate,v))
    return dist,parent
```

입력 그래프는 정적이고 모든 비용이 0·1이며 정수 덧셈이 안전하다고 가정합니다. 덱 항목의 거리 snapshot을 함께 저장하면 갱신 전 항목을 구분하기 쉽습니다. 도달 불가 정점은 INF이고, source가 없는 경우는 입력 오류입니다.

현재 유효한 최소 거리 d를 처리할 때 덱에는 d와 d+1 층의 후보가 거리순으로 남습니다. 0을 앞에, 1을 뒤에 두면 이 순서를 유지합니다. 따라서 최소 후보를 꺼냈을 때 확정하는 Dijkstra의 비음수 논리를 적용할 수 있습니다. 처음 넣을 때가 아니라 유효한 최소 후보로 꺼낼 때 settled로 표시합니다.

## 시간과 공간의 전제를 숨기지 않습니다

각 정점은 유효 확장 한 번, 각 간선은 그 확장에서 한 번 검사합니다. 성공적인 완화와 덱 삽입은 O(E) 이내이고 push·pop이 O(1)이므로 시간은 O(V+E)입니다. 이 snapshot·지연 삭제 구현의 덱에는 중복 항목이 남을 수 있어 전체 보조 공간 상한은 O(V+E)로 볼 수 있습니다. 단순 방문 배열 하나만 두는 BFS의 공간 설명을 그대로 가져오지 않습니다.

비용이 2나 음수가 들어오면 이 두 층의 덱 불변식이 깨집니다. 목표를 조기 반환하는 변형에서도 아직 탐색하지 않은 잘못된 간선을 놓치지 않으려면 입력 전제 또는 전체 사전 검증이 필요합니다.

## 0 비용 사이클과 동점을 시험합니다

0 비용 사이클에서도 `candidate < dist[v]`인 경우만 넣으면 같은 거리로 무한히 재등록하지 않습니다. `<=`로 바꾸면 동점 사이클에서 후보가 계속 생길 수 있습니다. 경로 부모도 엄격한 개선 때만 갱신하고 복원 시 실제 간선 비용 합을 확인합니다.

작은 0·1 그래프에서 모든 시작점의 거리를 기준 Dijkstra와 비교합니다. 직접 비용 1과 우회 비용 0, 고립 정점, 자기 간선, 평행 간선과 0 사이클을 포함합니다. 덱을 쓴다는 사실보다 최소 거리의 순서가 왜 유지되는지 설명할 수 있어야 합니다.
