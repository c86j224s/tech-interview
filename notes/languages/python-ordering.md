# Python 안정 정렬·키 비용·결정적 출력

## 안정 정렬은 원래 동점 순서를 존중합니다

점수가 같은 A와 B가 입력에 A,B 순서로 있으면 안정 정렬 뒤에도 A,B입니다. 입력이 B,A이면 B,A가 남습니다. 따라서 동점자의 입력 순서 보장과 입력에 무관한 결정적 순서는 다릅니다. 여러 worker의 비결정적 합침 결과를 정렬할 때는 점수 외 최종 ID 같은 보조 키가 필요할 수 있습니다.

Python의 list.sort와 sorted는 안정 정렬을 제공합니다. list.sort는 원본을 바꾸고 None을 반환하며 sorted는 새 리스트를 만듭니다. 원본 순서를 보존해야 할 때 sort를 쓴 뒤 안정적이므로 안전하다고 말할 수는 없습니다.

## 여러 정렬을 적용하면 마지막 키가 가장 우선합니다

```python
rows = [('A', 10, 2), ('B', 10, 1), ('C', 20, 3)]
rows.sort(key=lambda r: r[2])                 # 가입 순서
rows.sort(key=lambda r: r[1], reverse=True)   # 점수 우선
print([r[0] for r in rows])                  # ['C', 'B', 'A']
```

두 번째 정렬이 동점 안의 첫 정렬 순서를 유지합니다. 복합 키 `(-score, joined, id)`로 우선순위를 한 번에 표현할 수도 있지만 값 타입·음수 변환·방향을 명확히 해야 합니다. 모든 키가 내림차순이 아니라면 단순 reverse=True가 각 구성요소의 의도를 만족하는지 확인합니다.

| 요구 | 키·입력 정책 | 잘못된 대체 |
| --- | --- | --- |
| 문서의 동점 입력 순서 보존 | stable sort | 임의 ID를 추가해 순서 변경 |
| 전역 결정적 랭킹 | 최종 유일 tie-breaker | stable만 의존 |
| 원본 목록 유지 | sorted 또는 명시 복사 | list.sort 반환값 사용 |
| 혼합 타입·NaN | 정규화·거절·별도 순서 | 모든 값이 자연 비교 가능하다고 가정 |

## Run 활용은 구현의 시간 최적화입니다

CPython의 정렬은 이미 정렬된 연속 구간인 run을 활용하는 적응형 병합 정렬 계열입니다. 부분 정렬·정렬 완료 입력은 비교와 이동을 줄일 수 있지만 모든 입력에서 선형 시간이 되는 것은 아닙니다. Timsort라는 이름만으로 버전별 병합 정책·run 처리·버퍼 크기를 영구 계약처럼 고정하지 않습니다.

## Key 함수는 원소마다 계산한 값을 재사용합니다

key 기반 정렬은 원소마다 key를 한 번 평가해 비교에 재사용하므로 매 비교마다 외부 조회·복잡한 계산을 하는 comparator와 다릅니다. n=1000일 때 key 호출 수를 계측하면 정렬 비교 수와 별개로 1000이어야 하는 정상 경로를 확인할 수 있습니다. key 예외로 중단되는 경우는 별도입니다.

여러 번 정렬하면서 같은 비싼 key를 재사용하려면 별도 사전 계산·캐시의 신선도·메모리 정책이 필요합니다. key가 현재 시각·외부 DB·가변 상태를 읽으면 원소별 평가 시점이 달라져 재현성이 흔들릴 수 있습니다. 키 계산·비교·목록 생성·병합 비용을 따로 측정하고 같은 결과를 비교합니다.

## Set 순서와 Runtime Hash를 외부 계약으로 쓰지 않습니다

set의 순회는 안정적인 정렬 순서 보장이 아닙니다. 문자열 등의 hash randomization과 내부 배치가 실행 간 순서에 영향을 줄 수 있습니다. dict의 삽입 순서 보장은 입력을 set에서 얻어 삽입하는 순서 자체까지 결정적으로 만들지 않습니다.

서명 입력·캐시 샤딩·영구 ID에 프로세스의 hash 결과를 그대로 쓰지 않습니다. 필요하면 명시적인 바이트 인코딩·정규화·안정 해시 알고리즘·버전을 고정합니다. 재현을 위해 테스트 seed를 고정할 수는 있어도 외부 출력 순서의 버그를 감추려고 보안 무작위화를 영구 제거하는 것은 다른 선택입니다.

## 입력 분포와 Seed를 바꿔 의미를 확인합니다

동점 입력 순서 두 가지, sorted 원본 보존, key 호출 수, 부분 정렬·역순·무작위 입력을 시험합니다. set 기반 출력은 여러 PYTHONHASHSEED의 새 프로세스로 실행하고 순서가 계약이면 최종 정렬이 같은지 확인합니다. 원소 집합만 요구하는 테스트는 집합으로 비교합니다.

키의 성능 비교는 Python 구현·버전·원소 수·run 비율·키 비용·할당을 고정합니다. 이 노트는 의미와 측정 설계이며 특정 최신 CPython 정렬 구현의 성능을 실제 측정한 결과는 아닙니다.
