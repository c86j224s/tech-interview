# 순수 계산·명시적 난수 상태·Memoization Key

## 시각을 읽는 경계와 만료를 계산하는 함수를 나눕니다

`expiresIn(days)`가 내부에서 현재 시각·전역 정책을 읽으면 같은 인자도 결과가 바뀝니다. 효과 경계가 시각과 policy를 읽고 `calculateExpiry(now, days, policy)`에 값으로 전달하면 계산은 재현하기 쉬워집니다. 입력 객체를 몰래 정렬하거나 로그를 쓰는 것도 호출 밖의 관찰을 바꾸는 효과입니다.

**순수 함수**는 같은 값 입력에 같은 결과를 내고 외부 상태를 관찰·변경하는 숨은 효과가 없습니다. 호출을 결과값으로 바꿔도 관찰이 같다는 참조 투명성과 연결됩니다. 로그 함수는 결과로 치환하면 로그 횟수가 달라지므로 같은 성질이 없습니다. 순수하다고 업무 규칙이 맞는 것은 아니며 잘못된 세율도 일관되게 계산할 수 있습니다.

계산 전 읽은 가격이 저장 전에 바뀔 수 있어 결과에 기준 version을 연결하고 적용 때 조건부 갱신합니다. 계산을 두 번 해도 안전하다는 사실을 결제를 두 번 보내도 안전하다는 주장으로 확대하지 않습니다.

## 주소가 같아도 입력 값은 달라질 수 있습니다

객체 `{price:100, tax:0.1}`의 주소로 결과 110을 cache한 뒤 price=200으로 바꾸면 같은 key로 110이 반환될 수 있습니다. 불변 입력 또는 실제 계산에 영향을 주는 값·정책 version을 key로 사용합니다. 같은 값의 새 객체도 재사용할지는 값 동일성 계약으로 정합니다.

| Key 선택 | 이점 | 필요한 전제·비용 |
| --- | --- | --- |
| 객체 identity | 저렴한 lookup | 객체가 변하지 않거나 명시적 무효화 |
| 값 tuple·policy version | 의미가 명확함 | 모든 영향 입력 포함 |
| 깊은 hash | 큰 구조를 작은 key로 | 계산 비용·충돌·정규화·동일성 검사 |

map 순서·NaN·-0·Unicode 정규화·직렬화 생략이 계산 의미를 바꾼다면 단순 JSON 문자열을 보편 key로 쓰지 않습니다. hash 충돌을 값 동일성과 혼동하지 않고 cache size·eviction·보유 참조도 관리합니다. 전역 환율을 계속 몰래 읽으면 key 수정만으로 순수성 문제를 해결하지 못합니다.

## 난수를 상태 입출력으로 연결합니다

설명용 작은 생성기를 `next=(5*state+1) mod 16`, 결과값을 next라고 둡니다. seed 1에서 6→15→12가 나옵니다. 함수는 상태 1을 주면 언제나 `(값6, 다음상태6)`을 반환하고 다음 계산은 그 상태를 명시적으로 받습니다. 실제 통계 품질·보안에 적합한 생성기라는 뜻은 아닙니다.

전역 RNG를 공유하면 다른 작업이 한 번 소비한 것만으로 순서가 달라집니다. seed뿐 아니라 알고리즘·version·호출 순서·병렬 분배를 고정해야 replay가 같습니다. 병렬 작업은 안정된 작업 ID별 stream 분리 등 정책을 정하고 임의 스케줄 순서로 공유 RNG를 소비하지 않습니다. 보안 token에는 재현 가능한 테스트 seed가 아니라 적합한 암호학적 난수 경로가 필요합니다.

## 계산의 재현과 효과의 실패를 따로 시험합니다

동일 값 입력·입력 불변·동등한 다른 객체·정책 version 변경·eviction·RNG 상태 재개를 기준 계산과 비교합니다. 효과 단계에서는 저장 성공 후 이벤트 실패·중복 호출·현재 version 충돌을 별도로 검사합니다. 이 노트는 계산 경계 설명이며 이 예시 RNG를 제품에 사용하도록 권하는 것이 아닙니다.
