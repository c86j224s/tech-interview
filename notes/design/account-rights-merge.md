# 계정 병합의 권리 원장·늦은 결제·취소 경계

## 계정 ID 치환보다 무엇을 보존할지가 먼저입니다

A와 B의 소유권을 모두 증명한 뒤 대표 계정과 병합할 항목을 정합니다. 이메일 문자열이 같다는 사실만으로 소유 증명을 대신하지 않습니다. 구매·포인트·쿠폰·제재·로그인 수단은 같은 합산 규칙을 쓸 수 없습니다.

| 데이터 | 병합 규칙의 예 |
| --- | --- |
| 포인트 | 원장·만료·사용 이력을 보존한 이전 |
| 상품 권리 | 안정 주문 ID 기준 중복 제거·합집합 |
| 환불·분쟁 | 현재 주문 상태·제한 유지 |
| 일회성 쿠폰 | 사용 이력 보존·추가 횟수 생성 금지 |
| 제재 | 정상 계정 병합으로 제한 제거 금지 |
| 로그인 수단 | provider별 소유 증명·충돌 처리 |

단순 잔액 합산 뒤 원장을 잃으면 환불·만료·중복 판정을 할 수 없습니다. 되돌릴 수 없는 변경 전에 구체 결과와 제한을 사용자에게 확인합니다.

## 교차 병합과 원본 쓰기를 같은 상태 계약으로 통제합니다

A→B와 B→C가 겹치면 중간 대표·순환·이중 이전이 생길 수 있습니다. 고정 ID 순서 lock 또는 양 계정 expected version을 검사하는 원자 예약으로 병합을 등록합니다. 진행 중 계정에 새 병합을 무작정 시작하지 않고 대표 조회는 최종 대표와 병합 generation을 반환하며 순환을 거절합니다.

내구 병합 ID 아래 계정·구매·보상 단계별 상태·이전한 원장 항목 ID·실패·대사 필요를 저장합니다. 완료 단계를 재개할 때 원본 잔액을 다시 더하지 않고 고정된 항목 처리 여부를 검사합니다. 여러 service의 효과를 하나의 DB rollback으로 가정하지 않습니다.

## 전환 직전의 결제는 누락과 이중 지급을 모두 막아야 합니다

결제 E가 A로 왔을 때 현재 대표 B·generation 7을 확인해 B에 한 번 적용하거나, 전환 중이면 내구 보류하고 적용 위치를 남깁니다. mapping 조회 뒤 권위가 바뀔 수 있어 실제 저장 지점에서 generation을 검사하고 실패하면 재조회합니다. A와 B 양쪽에 지급한 뒤 잔액 합산하면 중복입니다.

환불·취소도 동일한 안정 주문 ID에 연결합니다. 중복 event ID와 동일 주문의 서로 다른 상태 사건을 구분하며 옛 worker의 늦은 쓰기는 거절합니다. 완료 후 원본 session/token은 정책에 맞춰 폐기·재인증하고 옛 ID의 조회·늦은 event routing을 유지할 기간을 정합니다.

## 병합 취소는 이전 단계를 되감는 버튼이 아닙니다

아직 이전하지 않았으면 예약·실행권을 해제할 수 있습니다. 이미 B로 포인트 100을 옮긴 뒤 B가 60을 썼다면 A의 옛 100 snapshot을 복원하면 재화를 만들 수 있습니다. 항목별 역이전·조정 원장·현재 잔액/권리 검사로 보정하고 불가능하면 수동 대사 상태로 남깁니다.

취소와 정상 완료가 경합하면 expected state/version·정정 ID로 한 전이를 확정합니다. 기존 성공 이력을 지우지 않고 취소 가능·보상 가능·수동 확인의 경계를 명시합니다. 제재·쿠폰 사용 기록도 보정에서 사라지지 않아야 합니다.

## 중간 실패에서도 권리와 제한을 대조합니다

동시 병합·늦은 결제·응답 유실·같은 단계 반복·사용 후 취소·옛 token·보류 event를 시험합니다. 성공 표시보다 권리 합계·주문 원장·제재·사용 이력·미처리 수를 확인합니다. 이 노트는 병합 설계이며 실제 사용자 계정을 병합한 실행 결과는 아닙니다.
